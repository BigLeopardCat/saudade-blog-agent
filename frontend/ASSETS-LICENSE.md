## 想优化或二次开发：原始 `.psd` 在哪

本仓给的是**成品**——`agent_2.moc3`（模型数据）与 `texture_00.png`（贴图，也就是画本身）。
**分层的源文件不在仓里**，作为发布附件分发：

<https://github.com/BigLeopardCat/saudade-blog-agent/releases/download/v20261007/agent_2.psd>

19.0 MiB / 1728 × 2304 RGBA，同发布页的 Assets 一节也能下。校验（下回来应当是这个值）：

```bash
sha256sum agent_2.psd
# 3264012542f3037057ad103ea94449e91f4a6f7974758752bfe88328f36b0348
```

有它和没它，两种活儿的代价不一样：

- **拿现成产物就能做**：换色、调尺寸、裁一裁（当头像/壁纸），以及在**代码侧**改渲染与动作
  ——那半边是 MIT，随便改。
- **必须有原始 `.psd` 才能做**：把贴图**重画干净**（改线稿、翻新上色，而不是叠滤镜）、
  给角色**加部件**（换装、把新表情画进贴图）、**重新绑定** Live2D 参数（动骨骼与结构，
  而不只是动动作）。成品里那片图层信息已经不存在了——只拿一张拍平的 PNG 做这些，等于从头
  重画一遍，改动也没法合回原模型。

**为什么不直接放进仓里**：19 MiB 的二进制一进 git 就永久留在**每一个** clone 的历史里（删文件
没用，只能改写历史），而真正需要它的只是少数要重画或重新绑定的人。挂在发布附件上，要改的人点
一下就有，其余人 clone 与构建都不受影响。原始文件由作者自己另留一份。

改完怎么回到线上：成品由 Cubism 导出后覆盖 `public/live2d_model/` 下的对应文件——注意那两棵树
是**父仓 `frontend/widget.lock.json` pin 住的**，改完要回父仓把 sha 与 tree 一起 bump，否则改动
永远不上线、也不会有任何东西变红。

## 为什么美术是 NC、代码是 MIT

代码要能让别人自由部署、自由改成自己的，所以代码是 MIT（可商用、无附加条件）。
形象不一样：它是一份**作品**，作者希望的是"大家都能用、都能改、改完还得放回公共池子"，
而不希望"谁都能拿去印在商品上卖"。NC 挡住后者，SA 挡住"改一版私有化"。

代价要说白：**带 NC 的许可不是 OSI 意义上的开源许可**。本目录的美术资源因此属于
**源码可用（source-available）**，而不是"开源"——这是有意的取舍，不是疏漏。
代码那一半仍然是货真价实的 MIT。

## 一条**不写进协议**的社区约定

**禁止作恶**——不得用于欺诈、骚扰、仇恨、深度伪造他人等用途。

它**不是**上面那份协议的条款。CC 不允许在协议上叠加额外限制（叠了会让整份授权失效），
所以它只能是一条社区约定：靠共识执行，不靠许可条款执行。

## 与代码许可的关系

- 本目录**代码** → MIT（[LICENSE](LICENSE)）：可商用。
- 本目录**美术** → CC BY-NC-SA 4.0（本文件）：不可商用，改作必须同样协议。
- 发布附件里的 `agent_2.psd`（角色的原始 `.psd`）与上一条**同源同协议**；它不是代码。
- 两者是**各自独立的两份作品**（代码不是美术的衍生，美术也不是代码的衍生），只是恰好放在
  同一个目录里分发。**任何一方都不吞并另一方的许可**，许可边界按"文件是代码还是美术"划。
- 消费端（博客仓 `Saudade-Blog`，GPL-2.0）在构建时把这两棵树取过去、随站点产物一起
  分发。那是"同一介质上的聚合"（mere aggregation）：GPL-2.0 不因此覆盖到美术资源，
  但**分发者仍须原样带上本文件与署名**。
