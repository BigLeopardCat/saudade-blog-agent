# 对话工作区

面板沿用博客的粉紫蓝渐变与和纸配色。默认宽420px、高度最多420px，初始悬浮在
看板娘上方；较矮视口自动收紧高度，拖动或缩放后按用户位置显示，不再保留气泡尖角。
顶部只显示原有会话标题签；36px顶栏、32px工具栏与输入区保持紧凑。
历史列表是面板内部的可调整分栏，开合不移动或加宽窗口，消息和输入位于另一列。
长文、代码和表格在消息区域内阅读，不让整页跟随横向溢出。
暗色主题与减少动效设置有独立样式。

## 交互

- 空白对话提供认识博客、查找文章、一起读文章三个入口。点击只填写输入框，用户编辑并发送后才请求服务；已有草稿时保留草稿并提示。
- Enter 发送，Shift + Enter 换行；中文输入法选字、组合键、长按回车均不触发发送。
  会话重命名也避开输入法选字回车。
- 空输入且没有图片时禁用发送；本窗口回复时按钮切为带文字的「停止」。
  另一窗口正在回复、正在撤销确认时，发送按钮禁用并展示原因。
- 图片入口位于输入区，可逐张移除；超过数量限制、读取或压缩失败在状态栏提示。
- 完成的回复使用独立复制图标，成功切换为勾号，失败给出短提示；复制不包含执行过程及操作按钮。
- 输入区没有常驻标语或键盘说明。键盘规则通过控件提示提供；屏幕阅读器保留状态播报，
  错误和需要等待的跨窗口操作通过临时提示显示，不占用底部布局。
- 回复结束仅在发起者仍留在输入流程时恢复焦点；转移到页面其他输入框或关闭面板后不抢焦点。
- 「有新消息」继续复用原有滚动跟随逻辑。用户向上阅读时不强制拉回底部。
- 确认卡继续使用原有签名、撤销、幂等和结果未知协议；卡片标题、状态色来自明确结果字段。
  结果未知不显示成功，也不自动重试业务操作。

关闭、新消息、输入、历史搜索等控件有可访问名称。短状态使用独立 live region，
不把整段流式回复设为自动播报区域。浮动面板不是模态弹窗，不锁住宿主页面焦点。

## 模块与兼容边界

`chat-render.js` 保留现有 DOM 标识。`chat-ui.js` 管理呈现和输入反馈，
通过少量 `ctx.ui` 钩子接收程序草稿变更与轮次焦点意图；不直接发业务请求。
`chat-stream.js` 仍负责确认、SSE、停止与错误重试，`chat-session.js` 仍负责历史会话。
新增 CSS 在基础 `widget.css` 后加载，局部变量、主题与层级均限定在对话工作区。
没有新增运行时依赖或构建步骤。

## 验证

默认离线回归（Node 内置测试，无浏览器依赖）：

```sh
node --test frontend/tests/*.test.mjs
```

可选浏览器验收需开发环境提供 Playwright 和匹配 Chromium；未安装时明确失败，不静默跳过。
默认从正常 Node 模块解析路径加载 `playwright`，也可以指定现有安装位置：

```sh
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright/index.mjs \
CHROMIUM_EXECUTABLE=/path/to/chromium \
node frontend/tests/chat-ui.browser.mjs
```

脚本自动启动本地静态/API/SSE 夹具并拦截外网请求，驱动实际 render/engine/stream/session/UI 模块，
不加载 Cubism 或真实模型、不连接生产服务。覆盖桌面、375px 手机、明暗主题、长文、抽屉，
以及输入法、真实发送/停止、复制、焦点、跨窗忙碌、确认未知与撤销反馈。
截图默认写入 `/tmp/chat-ui-preview`，可用 `CHAT_UI_PREVIEW_DIR` 指定输出目录。
这些模拟接口测试不能替代宿主鉴权、真实 SSE 网络及移动设备软键盘验收。

## 宿主接入

宿主通过 `frontend/widget.lock.json` 的固定提交及两棵子树校验值消费组件。
入口把该提交号作为 `?v=` 传给子资源，无需再维护日期版本。
部署时同步博客锁文件，通过真实页面核对主题、Live2D层级、气泡位置与触屏拖拽。
离线浏览器夹具覆盖分栏的边界不变、正文不被覆盖、初始气泡位置及复制图标；
模拟接口仍不能替代真实鉴权、网络或设备软键盘验收。

## 页面操作与接续

支持回报的客户端发送`browser_feedback`。导航工具用固定站内页面表提供可直接选择的地址，
不要求先读取站点地图；动态文章和分类仍使用真实来源链接。
执行到导航时通过LangGraph `interrupt()`保存原任务，向客户端发出带任务、命令编号及期限的
导航事件，不先生成完成叙述。SPA等待路由器完成；整页加载从sessionStorage恢复本次待回报任务。
浏览器最多等待6秒，随后以completed/failed/timeout和当前路径接续同一checkpoint，才生成回复。
回报绑定当前身份、会话、任务和命令；它只是客户端观测，不授予任何业务变更权限。
相关实现采用[LangGraph标准中断和恢复](https://docs.langchain.com/oss/python/langgraph/interrupts)。
旧客户端未声明能力时保留指令发送语义，不把它冒充完成回报。

任务进展保留实际工具名，移除每次模型开始和工具返回的重复行，不将过程行数当模型调用数。
运行中的展开过程区预留固定高度，新记录在内部跟随；用户上翻记录时停止跟随。
输入区使用单个圆角编辑面板，文本在上、图片入口和发送／停止按钮在下；声明居中放在
面板上方，分割线紧贴声明底部。日间用户气泡使用白字与较深的主题渐变，夜间保留原配色。
图片入口有独立按钮容器，贴近编辑面板左下角。草稿随行数增高，到 CSS 高度上限后才滚动；
删除文本或放宽窗口后可重新收缩，不沿用旧横向输入栏的伸缩比例。
手动继续任务时保留已有过程，追加接续标记；模型调用次数与token仍以trace为准。
消息气泡按窗口可用宽度排版；输入框单层焦点边框，仅溢出时显示滚动条。
公告确认卡以原文展示正文并交给宿主的安全Markdown管线，不向卡面输出JSON转义。
