- **新增工具级菜单 `agent/tool_menu.py` 与它的判据套件**（⚠️ **agent 对外行为零变更**：这个
  模块今天**没有任何生产消费方**）。加它是为了一件还没有答案的事——把模型的动作空间从「50 条
  手写技能模板」换成「按角色过滤的真工具表」，整条 harness 撑不撑得住。它只做一件事：把
  `tools/base.py` 的 70 个工具按 `authz` 的 scope 表过滤成这个身份的菜单，输出**与技能级那份
  （`planner_llm.build_tool_schema`）逐格同形**的 OpenAI `tools` 数组 ⇒ 两臂能喂同一个
  `bind_tools`，「菜单形状」这才成为一个能单独拨动的自变量。
  三条纪律写在模块头注：① 角色过滤只有 `required_scope(tool) ∈ scopes_for(role)` 一处判据
  （不写第二份名单 ⇒「菜单里能选的」恒 ⊆「执行期放行的」，不扩权是结构性的，不是靠提示词请求）；
  ② 描述只**读** `graph._TOOL_MENU_LINES`，不抄第二份；③ `intents` / `reply_kind` / 三个伪函数
  **照搬**——它们是 harness 资产、不是模板资产，不搬就等于把「菜单形状」与「少了一条自我申报
  通道」混成一个变量。
  实测可见数（不含三个伪函数）：user **11 技能 → 31 工具**、admin **49 → 70**、zako **1 → 0**
  （zako 在 `_ROLE_SCOPES` 里是空集 ⇒ 工具侧零工具；技能侧还给它一个 `chat`，而工具侧
  「一个都不调」就是 chat）。**菜单变大是这件事的核心张力，不是附带发现**。
  判据 `tests/test_tool_menu.py` 44 项：逐角色的可见集合等于按 authz 表**独立算一遍**的集合、
  形状与技能级那份逐格对齐（键集 / `additionalProperties` / 无必填不写 `required`）、跨切面槽位
  在场、描述同源、确定性。含一条**正控**（把某工具的 scope 改成没人有的 ⇒ 它必须从菜单里消失，
  证明断言真的在读表，而不是「两边都空」也能绿）与两条反控（去掉角色过滤 / 去掉 `intents` 槽，
  各自让对应断言变红）。**这里的绿不代表模型会用这张菜单**——那只有真链路 A/B 答得了。
