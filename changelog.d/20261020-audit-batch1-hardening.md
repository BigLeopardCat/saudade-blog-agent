- **三处"关着也看不出来"的安全开关收紧**（⚠️ 正常用户的对话行为一个字节都没变；变的是
  **出问题时的处置**）。三件：
  ① **删标签改成一律弹卡**（20261019 安全审计 SAU-014）：`delete_tag` 此前在「两档」族——
     主人原话里有命令骨架（「把标签 X 删掉」）就免问、直接执行。改判的理由是**不可逆 + 成片**：
     删一级标签会 CASCADE 掉它下面**全部**二级标签、并从**所有文章**上摘掉引用，站内没有
     "恢复标签"这个动作（重建同名标签是一条新记录，文章不会自己挂回去）。同族的
     `delete_category` **刻意不进**（后端是 `ON DELETE SET NULL`：文章只是变成"没有分类"）。
     连带两处判据跟着动：出处核对的强制域 = 写集 − 一律弹窗族 ⇒ `delete_tag` **移出**该域
     （卡面印全值，人眼是核验方）；react 臂 ⑥b 原先断言"命令形态 ⇒ 直执行"，现在断言
     "命令形态仍然弹卡"，并用一枚覆盖它的令牌作反控（否则"闸恒拦"也能让它全绿）。
  ② **空密钥不再静默签发代签令牌**（SAU-012）：`_sign_local_jwt` / `_sign_user_jwt` 都以
     `settings.jwt_secret` 现取（此前是**导入时快照**的模块常量——套件打的 `settings` 桩因此
     静默不生效），空值 ⇒ 抛 `RuntimeError("JWT_SECRET 未配置…")`，把失效时刻从"Rust 那边一次
     401"提前到"当场可读的原因"。判据两头都有：空 ⇒ 两条签名路径都拒绝；有 ⇒ 照常签得出且
     签名能用同一把密钥验过。
  ③ **`write.device` 不再吃 shadow 灰度**（SAU-007）：进 `_HARD_SCOPES` ⇒ 拒绝恒生效，与
     `AGENT_AUTHZ_ENFORCE` 取哪一档无关。它是第三族（前两条是"纯新增能力、没有观测期"，
     这条是**后果落在物理世界**：`device_oled_display` 把一段字刷到设备屏上）。三个真角色
     都授予它 ⇒ 对正常用户一字不改，它拦的只有"身份不明"。`read.own` / `write.own` 仍不进，
     理由写在集合旁（前者的唯一拒绝对象 `zako` 本来就整轮零工具，硬拦买不到新防线）。
