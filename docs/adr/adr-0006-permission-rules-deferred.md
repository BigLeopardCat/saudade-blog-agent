# ADR-0006：权限规则集（(action, resource, effect) + 「总是允许」）——方向认可，现在不做

- **状态**：已搁置（20261006）——**方向认可，条件未到**，重开条件见下
- **背景文档**：[../agent-architecture.md](../agent-architecture.md)（授权与确认闸的现状）、
  `agent/authz.py`（`_ALWAYS_CONFIRM_TOOLS` / `consent_granted` / `scope` 声明表）
- **影响范围**：无。本次没改一行代码——这份 ADR 存在的目的就是**别再重开一遍讨论**
- **判据**：无（没改代码）。重开时第一件要建的是判据（见下"重开时先建什么"）
- **触发条件**（**任意一条**成立才重开）：
  1. 主人**明确抱怨**"每次都要点一下"——注意是抱怨，不是我们自己觉得点得多：
     判据是可观测的读数（确认卡的**取消/放弃**占比，或同一意图被重复弹卡的次数），
     而不是"弹卡总数"（这个数大是设计意图，不是问题）；
  2. 出现**跨会话**的"这件事别再问我了"——今天所有同意都是一次性的，主人反复下达
     同一类写命令时**每一次**都要点，这一条成立才说明"记住上次点头"是真需求；
  3. `_ALWAYS_CONFIRM_TOOLS` 增长到**需要分类**（今天的 17 件全是"写站内数据"这一种性质，
     所以"每次都弹"是一条能逐条拍板的规则；一旦混进低风险项，一刀切才成为问题）

## 背景

### 现状：同意闸是两档，不是一套规则

- 一般写操作走 `consent_granted`：判"主人这句话算不算明确命令"（命令骨架 + 目标有据），
  算就**直接执行不弹卡**，不算才弹一次确认卡。判据是**词形 + 地基**，不是规则集。
- 另有 17 件恒弹卡工具（`_ALWAYS_CONFIRM_TOOLS`）：`consent_granted` 对它们**恒 False**，
  弹卡是它们**唯一**的执行路径。这 17 件是主人**逐条拍板**过的语义（"这一类我不要它自动办"）。

也就是说：今天的"权限"= 一张恒 False 的名单 + 一句可判定的命令判据，**没有 effect、
没有资源维度、没有持久化**。这套东西的优点是**行为可从代码逐行读出来**（哪句话弹卡、
哪句话直接办，是纯函数判的，可回归）；缺点是没有表达力——比如做不出"这类操作总是允许"。

### 参考形态（不是本仓现状）

`(action, resource, effect)` 三元组规则集，求值语义 = **默认 ask、deny 优先、`findLast` 命中**；
主人的"总是允许"要**持久化到 Rust 侧**（会话之外仍然有效）。

## 决策

**现在不做。** 三条理由，按分量排：

1. **它不治任何一条已知的红。** 同一批对"弹窗族"慢性红的归因结论是：~60% 是
   **planner 没触发**（选 `chat` 做澄清、或编造"站内没有这个能力"）、~25% 是前提/夹具
   （靶不存在、`uid=0` 哨兵）、~15% 是判据过窄。**没有一条**的红因是"同意机制缺少表达力"
   ——换规则集一个百分点都换不回来。
2. **它横跨语言，而且要新表与迁移。** `authz.py` 头注要求 scope/role 名与 `src/authz.rs`
   **同源**（今天的做法是同名字面 + 跨语言守卫测试）；"总是允许"要落库 ⇒ 新表 + 生产迁移，
   而**生产迁移需要显式授权**（本仓纪律）。这不是一次重构的规模，是一次跨仓变更。
3. **它一上来就要回答一个产品问题，而不是技术问题。** 规则集里"总是允许"生效的第一件事，
   就是有人问"那 17 件恒弹卡的要不要开豁免"。**这 17 件逐条是主人拍过的**，所以这不是重构
   顺手能给答案的——它需要主人重新拍一遍 17 次。

## 重开时先建什么（写在这里，免得重开时从头想）

- **判据先行**：规则集的第一条判据不是"求值函数对不对"，而是**"改坏它会红"的行为面**——
  例如"某条 deny 规则在场时，`consent_granted` 必须恒 False 且弹卡仍是唯一入口"。
  同族教训：本仓最贵的失效模式是"看着在跑、其实没跑"。
- **词形判据不许被规则集吃掉**：今天 `_confirm_popup` 的否决位（提问/假设不弹卡）与
  `consent_granted` 的命令判据是**两支错向相反的判据**（一个服务"别把提问读成意图"，
  一个服务"明确命令别多问一次"）。规则集若要取代其中之一，先回答"另一支还留着吗"——
  两支合并会让它们的错向互相绑架。
- **规则集不是弹卡的替代品**：`_ALWAYS_CONFIRM_TOOLS` 今天保证的是"这 17 条写能力**必有**
  一个入口"（弹卡）。任何规则化改动都要先证明这条不变量还在（`tests/test_write_dead_end_guard.py`
  的完备性锁就是它的网）。
