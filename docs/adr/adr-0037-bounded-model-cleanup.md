# ADR-0037：模型连接清理有期限且失败后停止复用

- **状态**：已采纳（2026-11-03）。
- **承接**：[ADR-0024](adr-0024-framework-kernel-and-domain-extensions.md)。
- **影响范围**：ModelIO 生命周期、就绪检查与资源诊断。
- **判据**：`tests/providers/test_model_cleanup.py`，以及既有模型停止、截止时间和连接池复用测试。

## 背景

同步框架调用通过 AnyIO portal 使用异步 HTTP 连接池。取消 Future 不代表生产者已经退出；
没有期限的 shield 和线程事件等待可能让停止或关停一直等待。httpx 的 `is_closed` 在底层
流清理完成之前就可能变为真，不能单独作为释放证据。

## 决策

继续复用 AnyIO、httpx 和应用 ExitStack。清理使用 AnyIO 标准取消作用域及有限等待，
生产者实际退出事件与取消 Future 分开记录；不另建执行器、任务调度框架或杀线程机制。
默认清理期限为两秒，线程观察退出另留短暂调度余量，不增加部署配置旋钮。

任何清理失败都会停用当前连接池，后续模型调用被拒绝，`/ready` 返回不可用原因；
`/health` 返回连接池是否可用及仍未退出的清理任务数，正常执行中的流不算清理积压。
trace 记录生产者退出、底层响应
关闭和清理完成，不能把取消已发出写成资源已释放。

底层库若自己屏蔽取消，外层期限不能强制终止它。此时资源仍属于原实例，待清理数量
保持可见；关停报错，不重新分配连接池掩盖问题。进程最终退出由服务管理器负责。
普通成功调用和正常取消仍复用健康连接池，不因单次取消创建新池。

## 范围与后续

本次不把同步框架入口改造成自定义异步循环。若迁移为原生异步，须同时验证 checkpoint、
确认恢复、工具顺序、停止和资源释放，且使用框架公开接口。工作上下文与摘要策略保持原值。
