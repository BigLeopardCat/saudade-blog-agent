# ADR-0037：模型连接清理有期限且失败后停止复用

- **状态**：已采纳。
- **核对日期**：2026-11-09。
- **历史来源**：[删除前记录](https://github.com/BigLeopardCat/saudade-blog-agent/blob/538b84c56820979d8dbb49dcbf7ff0938a396c93/docs/adr/adr-0037-bounded-model-cleanup.md)。

## 背景与决策

取消 Future 不代表生产者已退出，HTTP 客户端显示 is_closed 也不证明底层清理完成。
无限 shield 和线程等待可能阻塞停止与关停，因此继续复用 AnyIO、httpx 和应用资源栈，
清理使用标准取消作用域及有限等待，单独观察生产者实际退出。

清理失败停用当前连接池，后续模型调用拒绝，就绪检查报告不可用原因；
健康检查暴露清理积压，正常活动流不计为积压。
trace 区分已发出取消、响应关闭、生产者退出和清理完成，不能提前宣称释放成功。

## 取舍与限制

底层库若自行屏蔽取消，外部期限不能强制终止它。资源仍归原实例，
未退出清理保持可见，关停报告失败；最终进程退出由服务管理器负责。
不杀线程，也不重新分配池来掩盖泄漏；普通成功和正常取消继续复用健康池。

此决策补充 [ADR-0027](adr-0027-cancellable-model-io.md)，
不将同步框架入口换成自定义异步循环。
未来迁移原生异步时须使用公开接口并同时验证 checkpoint、确认、
工具顺序、停止和资源释放，不能只看网络调用取消成功。

实现及回归见 `models/`、`tests/providers/test_model_cleanup.py`。
清理超时与就绪细节随实现维护，不作为可绕过资源失败的部署开关。
