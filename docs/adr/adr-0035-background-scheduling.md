# ADR-0035：管理员持久调度

状态：已采纳；首版实现见 [管理员后台计划](../scheduling.md)。

## 决策

采用 DBOS 3.4 的 PostgreSQL 持久队列、动态 cron、异步持久等待与执行历史。
独立 Worker 运行调度；Agent HTTP 进程使用公开 DBOSClient，不启动调度循环。
沿用 LangChain / LangGraph 执行 Agent，不增加另一套 Agent 规划或节点 DSL。
DBOS 仅负责后台调度与步骤恢复，业务工具仍执行现有授权和幂等策略。
使用独立 PostgreSQL schema 和公开 JSON 序列化，不保存登录令牌或确认凭据。

APScheduler 的时间触发能力不足以独立承担任务投递后的持久恢复；为它补队列、
补偿和恢复会扩大维护面。DBOS 提供这些原语且复用现有 PostgreSQL，
无需部署 Redis、消息代理或 Temporal 服务。版本与公开 API 经独立验证后锁定。

## 首版范围

- 仅已验签管理员管理自己的计划，执行前重新核实账号当前身份与冻结状态。
- 一次性绝对时间、相对延时、带 IANA 时区的周期 cron；界面展示明确的本地时间。
- 个人提醒、独立后台的只读 Agent 任务；结果可查询并通知本人。
- 一次任务可在起始时间之后等待明确的文章公开条件，带截止时间和有界检查间隔。
- 暂停、继续、取消、分页读取计划及执行记录，记录失败与错过执行时间。
- 新后台任务有独立 checkpoint 线程，聊天会话可以继续使用。

首版不自动批准任意业务写入，不把等待中的确认卡持有到未来重放。
固定业务写入的长期委托授权、现有交互任务跨线程迁移、客户端页面动作另行实施。
创建卡必须明确说明上述执行范围，不能让用户把只读计划误认为未来会自动发布或修改。

## 正确性边界

调度创建和管理复用签名确认与操作执行账；重放相同操作不能新增计划。
使用调度库的稳定工作流编号和执行记录，不另建任务租约、队列和恢复状态机。
外部请求必须在可恢复步骤内；网络结果未知不作为成功，也不无条件重做业务写入。
暂停和取消为协作式控制，不回滚已经完成的步骤。
计划的等待不占聊天连接、会话锁或模型预算。模型只在真正执行只读任务时被调用。

## 验收

默认 CI 不连接生产数据库和模型。单元测试覆盖身份隔离、时间/条件校验、确认绑定、
重复创建、权限变化、分页与控制语义；显式 PostgreSQL 集成验证动态周期、取消及
杀进程后的持久恢复。真实模型验证仅使用隔离业务夹具，不自动批准生产业务写入。
