# ADR-0039：条件任务的预授权与后台执行

- **日期**：2026-11-10。
- **状态**：采纳设计；通用委托授权尚未实现。
- **范围**：管理员创建的延时、定点和条件后台任务。
- **优先级**：沿用 [ADR-0038](adr-0038-general-agent-and-release-priorities.md) 的正式版范围，
  本决策不启动跨会话任务协调或通用工作流平台建设。

## 背景

用户可能要求“明天九点检查文章 A，已公开就整理摘要发给我，否则跳过”。
执行所需信息在未来才能取得，批准时无法冻结判断结果或完整输出正文。
只允许预先确定全部参数会把正常的条件决策变成人工接续任务；
只保存一句“到时照办”又不能界定后台写入的权限。

当前 DBOS 调度已支持提醒、只读 Agent、定时公告和部分冻结的管理员变更；
条件触发仅覆盖指定文章公开等有限场景。普通暂停接续使用 LangGraph checkpoint。
这些能力不等于已经支持通用的、有写入权限的条件 Agent。

## 决策

区分两种授权，继续复用现有身份、业务确认和执行账：

| 任务 | 用户批准的内容 | 到时执行 |
| --- | --- | --- |
| 确定操作 | 已知对象、明确内容和具体操作 | 直接调用业务能力，复核版本及权限 |
| 委托任务 | 目标、条件、允许的资源与动作、预算和有效期 | Agent 读取未来事实并在授权范围内判断、执行 |

委托任务授权整个条件决策过程。未来事实决定执行分支，不构成权限扩张。
用户明确批准“根据文章内容生成摘要后私发给我”时，摘要不必预先固定；
把结果改成公开公告、发给其他账号或修改其他资源仍需新的授权。

### 授权记录

确认时持久化独立、可撤销、带版本的授权记录，至少包含：

- 创建者、任务归属、授权版本与批准时间。
- 原始目标、判断条件、可信来源范围及允许生成的输出类型。
- 允许调用的业务动作，以及对象、接收人和内容使用范围。
- 触发时间、时区、截止时间、重复执行和条件不满足时的行为。
- 最大处理数量、模型与工具预算、付费操作的单次及累计上限。

已知对象优先绑定具体 ID；未来才出现的对象，使用业务后端能够核验的筛选范围和数量上限。
自由文本的“自行判断”不能充当资源权限或付费上限。参数沿用已有工具 schema；
不引入执行脚本、任意 SQL、计划 DSL 或用户可定义的策略语言。

签名确认卡证明用户批准了该版本授权，后台执行读取持久授权记录。
不把过期确认令牌当作长期凭据，也不把聊天正文、摘要、模型计划或网页内容升级为授权。
修改目标、动作范围或额度需要重新批准并形成新版本；暂停、取消与撤销按任务版本生效。

### 执行与职责

1. DBOS 负责持久等待、队列、触发及执行恢复；等待期间不占聊天连接或模型轮次。
2. 到点复核授权状态和创建者当前权限。需要推理的任务启动独立 LangGraph 执行，
   携带目标、授权约束与必要证据引用，不复制整个原聊天历史。
3. 简单可计算条件由确定性代码检查；语义条件由 Agent 读取证据后判断。
   条件判断和实际工具调用保留结构化结果与证据，模型的结论本身不授予权限。
4. 每次产生副作用前，确定性代码校验实际动作、资源、接收人、授权版本、期限及剩余预算。
   业务后端继续执行当前权限、目标版本和事务检查；预授权不绕过这些边界。
5. 执行结果与交付沿用现有回执、执行账和结果通知。用户能看到成功、跳过、等待输入、
   部分完成或结果未知，不能把排队、发出请求或模型判断当成业务完成。

撤销检查应尽量靠近业务提交；能够同库校验的版本与变更在同一事务中处理。
已发出的跨服务请求可能继续完成，取消不承诺回滚；无法核实的效果保持未知并进行对账。
后台授权不依赖网页在线。必须由浏览器完成的动作，应明确客户端条件，不能承诺关页后执行。

### 条件与人工接续

- 单次检查条件不满足：正常跳过并记录原因。
- 等待条件成立：明确截止时间和有界检查频率，通过持久定时或业务事件唤醒。
- 周期任务：沿用既有不重叠和漏跑策略；每个触发批次有独立执行标识及预算。
- 证据不足：在预算内补充读取；仍无法判断时进入等待输入或终结为无法判断。
- 需要越出授权范围：暂停受影响的动作，展示新增授权内容；已完成操作保留真实回执。

条件不满足本身不弹确认卡。高风险条件的判断方式必须在创建时明确，不能用
LLM 的置信概率替代业务授权或实际状态核验。

生图继续遵守两阶段审批：用户可提前批准提示词、参考图、模型和费用范围，
到时生成；是否保留实际结果仍由人查看图片后确认。生图许可不包含自动设为封面或发布文章。

### 组合任务与恢复

一个委托目标可组合多个现有业务能力，由框架 Agent 选择与安排调用。
确定的业务流程继续使用已有业务事务或 DBOS workflow；不要求所有任务先变成固定节点图。

授权版本、触发批次与操作身份用于界定幂等范围。恢复不能重复已确认的业务效果；
外部结果未知时先查询核实，不盲目重放。跨业务的多步任务允许部分完成，
记录各步结果与后续处理，不承诺跨服务全有或全无。

LangGraph 是 Agent 状态及暂停接续的真源，DBOS 是持久触发和 workflow 的真源。
授权记录只保存应用权限与关联，不复制第三套执行状态机。日志与聊天不承担状态恢复。

## 验收与实施边界

实施前同时核对 Agent 和博客的授权、写入与撤销接口。发布验收至少覆盖：

- 未来事实满足、不满足、变化及无法核实；允许的动态内容不会反复要求批准。
- 未批准、错误用户、角色降低、授权撤销、过期和旧版本均不能产生新增写入。
- 实际对象、接收人、数量和付费调用超范围时阻止执行，不依赖模型自律。
- 网页关闭、服务重启、触发重复、通知重试及确认接续不重复业务效果。
- 多步部分失败与外部结果未知能够恢复、查询和如实汇报。
- 延时生图只启动获批请求，生成后仍等待结果保留审批；未经另行批准不设置封面。

先验证一个未来事实驱动的真实任务和一个可控的组合任务，再扩展能力登记。
不把列举更多定时操作、增加工具数量或通过单个成功样例作为通用能力完成的证据。

## 后果

任务不必预知未来数据，仍能保留明确的资源与费用边界；代价是需要持久授权、
逐次副作用核验与撤销语义，不能只为现有工具增加一个时间参数。
这些是应用授权职责，复用框架的执行和调度能力，不另建 Agent 框架。
