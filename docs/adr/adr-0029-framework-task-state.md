# ADR-0029：任务状态以框架 checkpoint 为准

- **状态**：已采纳。
- **影响范围**：框架任务 schema、Session 工作视图、确认接续与恢复投影。
- **判据**：`test_task_state_authority.py`、确认/压缩/暂停恢复相关测试。

## 决策

工具激活、结果字符消耗、摘要覆盖、输入应用记录、待确认和终结结果存于 `ExecutionState`。Session 只保留当前节点的工作视图，不再用独立属性保存同一批字段，也不再维护逐字段的另一套序列化逻辑。

节点边界从框架 state 刷新工作视图，框架返回值负责持久化。提交更新时复制可变数据，避免后续工具修改已经返回的更新。终结结果通过 state 转成产品 `TurnResult`，不是第二份可独立恢复的结果。

同批工具依次执行；标准 `Command` 的明确更新同时反映到当前批次视图。非末尾工具只提交自己的更新，末尾工具提交应用批次状态，不重复写其他中间件的全部通道。`effects` 使用框架字典合并 reducer；新任务和替换任务用标准 `Overwrite` 清空旧效果，避免跨任务残留。

`resume` 是外部接续控制输入，验证并消费后显式清空，不由普通状态投影再次写回。确认回执中的业务效果在匹配当前待确认操作后写入 state。恢复时，消息 artifact 可补充尚未归并的完成事实；同名字段以已提交 state 为准，旧消息投影不能覆盖新值。

模型句柄、工具实例、连接、取消信号、流式缓冲和传输回执缓冲属于当前请求，不进入 checkpoint。已观测的工具事实和回执用于会话展示和历史投影；业务执行仍以独立幂等账为准。

此决策没有引入新的执行循环或持久化后端。LangChain/LangGraph 继续管理模型与工具节点、state 合并、checkpoint 和 interrupt。独立读取并发需要另行消除产品证据和回执收集中的共享可变状态，不在本次直接打开。
