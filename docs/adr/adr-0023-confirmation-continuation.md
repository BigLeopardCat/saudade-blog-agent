# ADR-0023：签名确认暂停原生工具交换，取得回执后续行

- **状态**：已采纳（20261026）
- **影响范围**：原生工具循环、确认执行、会话 checkpoint 和结果叙述
- **判据**：`tests/test_confirmation_continuation.py`、`tests/test_pending_favorite.py`

长期暂停恢复方向见 [ADR-0024](adr-0024-framework-kernel-and-domain-extensions.md)。
以下确认、回放和故障语义作为迁移保留项；自定义游标格式为当前实现，不要求长期保留。

## 背景

准备工具原先直接结束整个工具循环。模型一次返回多个准备调用时，运行时拒绝整批；
只准备一项时，确认后也没有原始请求的暂停位置，容易丢失剩余事项。

## 决策

使用现有 saver 保存原生消息交换的暂停位置。保留模型返回的工具调用、已完成兄弟调用的
响应、待处理调用、领域加载顺序、正文证据和结果预算；不创建计划 DSL 或新的工作流引擎。

同一时间只展示一张签名卡。未处理的调用保存在私有 `continuation` 字段，不能作为写入授权。
当前项完成后继续执行剩余准备或读取，再由模型决定下一步；每个新的业务变更仍须独立确认。
存在排队调用时，卡片说明继续与取消的范围。取消停止本次后续处理，不自动批准其他事项。
无需改动的准备结果作为工具响应继续交给模型，不能丢掉同批剩余事项。

游标绑定已验签的账号、角色、会话和当前卡片的操作标识。角色变化不恢复旧权限下的上下文；
目录和实际工具调用重新检查当前权限。确认令牌不进入游标、模型消息或日志。
图片保存可回看的引用，复用现有媒体读取机制。正常消息历史仍只保留有来源的事实与对话，
不把整个暂停提示词塞进历史摘要。

业务写入继续使用独立执行账。取得有效回执后，先持久化执行事实并消费当前游标，再调后续
工具或模型。旧确认重放只返回其回执，不能推进新卡或重复后续页面、设备调用。
写入结果未知时保留原卡和游标，停止后续处理；不猜测成功，不盲目重写。

确认后的原生循环负责结果回复，避免再调用一次独立叙述模型。没有游标的既有卡片继续使用
原有回执叙述路径。每个确认请求内的工具、模型和叙述共享当前预算及截止时间；
新的人工确认是新的 HTTP 请求。恢复领域时保持工具顺序，减少前缀重排；服务商是否命中缓存
仍须以实际 usage 为准。

## 恢复边界

- 执行账已完成、消费游标的 checkpoint 写入失败：重放确认读取原回执，再消费仍在等待的游标。
- 消费游标后进程退出或用户停止：执行事实已经保存，旧确认不会再次分派后续调用；
  用户可在新消息中继续未完成请求。这里不承诺每个纯读取步骤的自动恢复。
- 后续模型超时或服务商报错：保留本次取得的回执，说明后续中断；存储异常和用户取消继续向外传播。
- 后续卡片准备完成但尚未保存时退出：没有批准新的业务写入，之后需要重新准备该卡。
- 取消、替换、到期后的下一轮以及删除会话，分别清除匹配的游标；旧卡不得清除新卡的游标。

多项变更不是跨服务原子事务，已成功的一项不会因另一项失败而自动回滚。
实际写入、回放和故障边界使用隔离业务夹具验证；线上回归只读取和准备确认，不批准业务变更。
