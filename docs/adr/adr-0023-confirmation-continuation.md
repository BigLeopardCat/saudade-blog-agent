# ADR-0023：签名确认与框架持久审批恢复

- **状态**：已采纳（20261026，框架承接实现）
- **影响范围**：标准 Agent、确认执行、会话 checkpoint 和结果叙述
- **判据**：`tests/test_confirmation_continuation.py`、`tests/test_pending_favorite.py`、`tests/test_framework_kernel.py`

执行内核及领域边界见 [ADR-0024](adr-0024-framework-kernel-and-domain-extensions.md)。

## 决策

LangChain `create_agent` 承接模型与工具循环，作为持久子图接入 LangGraph 会话审批图。
子图保存标准消息、加载领域、来源证据和有界结果计数；准备工具返回签名卡后，
会话图通过 `interrupt` 暂停。恢复使用公开 `Command(resume=...)`，不序列化自建计划或工具游标。

同一时间展示一张签名卡。同批后续调用只留下未执行的工具消息，不能提前查询或准备下一项。
确认取得真实回执后，middleware 用回执替换当前工具响应，继续原批次尚未执行的调用；
已完成调用复用原响应。保留原生工具 ID、参数和服务商重放元数据，每项新的变更独立确认。
取消停止后续处理；无需改动的准备结果作为正常工具响应继续执行。

审批绑定账号、角色、会话及操作标识。模型消息不包含确认令牌；签名卡及私有审批状态
保存在服务端 checkpoint。角色变化不恢复旧权限下的上下文，工具目录及执行重新检查权限。
图片只在当前请求内供模型读取，持久状态保存可重新读取的引用，不保存内联图片载荷。

普通插话使用无持久写入的标准 Agent，完成后只提交对话，保留原审批及持久子图。
替换需求先撤销旧签名，再把本轮标准 Agent 状态提交为新的持久子图和审批。
取消和到期后的新请求清除审批；删除会话同时删除所有框架 namespace，并保留删除屏障。

## 写入与恢复

业务写入仍由独立执行账、签名、目标版本及后端授权保障。框架恢复信号不能授权业务写入，
checkpoint 不承诺跨服务 exactly-once。

取得真实执行回执后，审批节点先持久化事实并清除当前审批，再调后续工具或模型。
写入结果未知时保留原卡，停止后续处理，不重试业务写入。
旧卡重放只返回执行账的结果，不能推进新卡，也不能重复后续页面或设备调用。

- 业务已成功、审批节点尚未持久提交事实：重放读取执行账，再恢复仍在等待的审批。
- 框架已持久保存审批节点的完成写入，即使后续 checkpoint 失败：当前审批已消费。
  旧卡只返回回执；用户可发新消息继续未完成事项。框架 pending writes 也属于持久状态。
- 事实提交后用户停止或进程退出：事实保留，不自动重做后续调用。
- 后续模型超时：保留回执并说明后续中断；存储异常和用户取消继续向外传播。
- 后续卡片已准备：签名未被批准前不会发生该项业务写入。

确认后的标准 Agent 负责自然回复，不再额外调用独立叙述模型。
本次 HTTP 请求的工具、模型和叙述共享预算及截止时间；新的人工作出确认属于新请求。
框架调度本身不增加模型调用，缓存是否命中以服务商 usage 为准。

## 升级兼容

旧会话对话和有来源的事实继续可读。升级前签发的卡片仍由原签名与执行账保障执行和回放，
但不恢复旧格式保存的待执行调用；需要用户重新提出剩余事项。
`continuation` 仅作为滚动升级清空字段保留，不读取、解释或执行其内容；旧游标类和编解码已删除。

多项变更不属于跨服务原子事务，已成功的一项不会随另一项失败自动回滚。
实际写入及故障测试使用隔离业务夹具；线上回归只读取和准备确认。
