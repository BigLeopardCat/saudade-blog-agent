# ADR-0025：普通任务通过框架 checkpoint 显式续跑

- **状态**：已采纳，2026-10-26。
- **承接**：[ADR-0024](adr-0024-framework-kernel-and-domain-extensions.md)。
- **判据**：`tests/test_task_recovery.py`、审批续行与服务取消回归，以及浏览器停止/继续验收。

## 决策

停止取消当前 HTTP 流及协作式执行，保留框架已经保存的进度。继续任务以显式
`resume_task` 和会话编号发起，不通过识别“继续”等用户文本路由，也不重新发送原问题。
`task_id` 是一次任务的标识，`thread_id` 是整段会话的框架坐标，两者职责不同。

恢复先核对任务、账号、角色与会话绑定，再通过 `get_state(subgraphs=True)` 读取标准子图状态，
由框架继续未完成节点。已经提交的 ToolMessage 按原调用 ID 复用；加载领域、来源证据和
业务结果元数据随框架状态恢复，不保存自定义执行计划或工具游标。

任务标识、原请求与绑定保存在会话图的 `run` 字段。当前图片保存可重新读取的引用，
不将内联图片编码写入持久状态。子图保存本任务标识及终态结果，用于核对恢复来源。
任务直到规范对话提交成功才结束；子图已完成而最后提交失败时，复用已保存结果，不重调模型。
原问题是否已经提交单独记录，续跑不重复追加问题或已有工具观察。

## 控制与权限

- 继续请求不携带新问题、图片或确认凭据，宿主不将其保存为新的用户发言。
- 每次继续均重新验证当前身份；角色变化、任务被替换或会话删除后拒绝旧控制。
- 等待审批时，继续只重新展示原签名卡。它不是批准，不执行写入。
- 写入成功后，真实回执由审批节点先持久提交；后续回复中断仍可继续，原写入不重做。
- 普通新指令保留已停止的问题并建立新任务；显式编辑或重新生成才丢弃对应旧游标。
- 已结束任务不因重复继续而重新运行；旧确认仍由独立执行账处理重放。

确认卡使用稳定操作标识，重展示保留同一身份。确认与继续都是控制请求，
不将“确认执行”等合成文本写入用户历史或模型上下文。

## 资源与保证边界

每次人工作出的继续使用新的请求预算和截止时间；它不会自动续费或后台无限重试。
模型调用仍经过完整预算入口。取消不保证服务商立即停止计算或计费。
恢复从框架保存的节点状态继续，并非接回已经取消的模型请求的下一个 token。

尚在执行或结果未写入 checkpoint 的读取可能重试。写入的安全仍依赖签名、版本及执行账，
未知结果不能从缺少 ToolMessage 推断为“没有发生”。页面指令和设备回执遵守各自交付语义。
旧任务没有本次引入的绑定标识时不推测恢复位置；旧签名卡继续受原确认与重放契约保护。
