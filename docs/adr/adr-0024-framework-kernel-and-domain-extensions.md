# ADR-0024：成熟执行内核、精简业务 harness 与领域能力包

- **状态**：已采纳（20261026，长期方向已确认；执行内核替换尚未实施）
- **承接**：[ADR-0021](adr-0021-native-runtime-core.md)、[ADR-0023](adr-0023-confirmation-continuation.md)
- **影响范围**：执行内核选型、工具和 middleware 扩展点、领域与产品依赖边界；本次仅记录决策。
- **判据**：现有确认、权限、记忆、取消、预算和传输行为测试作为迁移基线；标准内核对照与跨领域验收待实施。

## 背景

项目首先服务博客对话：模型能利用工具核实事实、持续完成多步请求，并依据真实结果自然回复。
博客体验以接近 coding agent 的持续执行为目标：主动核实、处理多步与失败、确认后接续，
过程可见且可取消；自然表达保留产品人设并受事实约束。
长期需要把能力迁移到其他业务领域，通过能力包扩展并维持稳定的执行语义。

当前主线复用 LangChain 消息、模型和工具组件，以及 LangGraph checkpoint；
工具循环、暂停游标与确认后续行仍由项目自行维护。工具目录、执行循环和提示词也仍直接依赖
博客领域与人设。旧规划引擎退出已经完成，通用执行职责收敛和插件化尚未完成。

现有验收未证明自建执行内核相对于成熟框架有明确的成本、延迟或可靠性收益。
项目将维护投入优先用于业务工具、上下文质量、可见交互与任务完成效果。

## 决策

长期架构采用成熟框架执行内核、精简业务 harness 和领域能力包。
延用 LangChain/LangGraph 生态，优先验证 `create_agent`、公开 middleware、interrupt
及 checkpoint 对现有契约的承接能力；实际 API 和兼容性以锁定版本的验证为准。

执行图表达通用的模型与工具循环、暂停和恢复点，业务步骤由模型决定。
为模型升级改善意图理解和执行选择保留空间，业务权限与副作用约束保持确定性。

| 层次 | 职责 |
| --- | --- |
| 框架执行内核 | 模型与工具循环、标准消息处理、流式、暂停恢复及 checkpoint |
| 应用 harness | 可信调用上下文、预算和成本、权限接入、事实来源及事件适配；优先使用公开扩展点 |
| 领域能力包 | 标准工具、业务接口、目标与版本校验、审批需求和真实回执 |
| 产品配置与界面 | 人设和称呼、表达风格、卡片、进度及客户端交互 |

框架审批负责等待决定及恢复执行。服务端身份校验、签名与有效期、确认内容绑定、版本校验、
执行账和未知结果处理继续由应用及业务服务保障。模型回复、普通消息或框架恢复信号均不能
独立构成业务写入凭据；checkpoint 本身不提供跨服务 exactly-once。

领域扩展复用标准工具和 middleware。能力包声明工具、权限及审批需求和必要上下文，
由可信应用装配和后端授权；新增领域的验收条件是无需修改通用执行内核。
人设、站点地址、文章证据规则和浏览器业务动作归入对应产品或领域适配。
初期使用显式装配与配置启停；独立发布出现实际需求后再引入包发现机制。

当前 `NativeRuntime`、`ToolSession` 和 `ToolContinuation` 是在役过渡实现。
框架承接通过验收后删除重复职责，保留业务工具、安全边界、幂等与回归材料。
自定义扩展需要说明框架的具体缺口及验证依据；扩展范围以该缺口为限。

## 迁移顺序

1. 冻结当前实现及请求级契约，列出框架承接项、领域依赖与待确认卡/会话迁移要求。
2. 在短期分支验证标准内核，复用现有业务工具和隔离执行夹具，比较同一组固定任务。
3. 验证通过后替换通用循环及暂停恢复；明确旧会话、在途操作和失败恢复策略，删除重复实现。
4. 收敛领域与产品装配，使用不依赖博客的示例能力包验证跨领域复用，再冻结版本开展完整验收。

验证分支有明确退出条件：成功后合并替换，失败则记录具体缺口并关闭实验入口。
生产保持单一运行入口，代码和文档分别标明在役实现与目标状态。

## 替换验收

| 方面 | 验收要求 |
| --- | --- |
| 任务行为 | 固定多轮、跨领域任务正确核实目标、完成查询与后续事项，真实歧义才追问 |
| 审批和副作用 | 多项操作逐项决定；取消、旧卡重放、权限变化和未知结果符合现有契约，无未授权或重复业务写入 |
| 运行与恢复 | 断连、取消、截止时间、存储失败和删除后迟到任务保持正确资源与状态边界 |
| 上下文与表达 | 保留相关目标、来源和执行事实；摘要不得升级为授权；自然回复和进度与实际结果一致 |
| 成本与缓存 | 固定模型、请求、预算与采样方式，记录完整输入、schema、模型/工具次数、真实 usage 及缓存字段覆盖 |
| 扩展与维护 | 无博客依赖的能力包可通过装配接入；自维护通用职责实际减少，现有必要验证仍可执行 |

对照前固定判据和可接受的成本、延迟变化范围。样本不足时报告原始值与覆盖范围，
不能据少量运行声称稳定成功率或延迟分位数。框架封装是否增加成本以实际模型请求为证据。
真实业务执行使用隔离夹具；线上回归仅读取和准备确认。完整线上基线继续等待实现稳定。

智能程度与自然表达按用户任务结果验收，框架接入或离线测试数量不能代替产品效果。
现有错误写入、事实虚构和意图失败仍需保留为回归材料。
