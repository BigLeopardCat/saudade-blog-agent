# ADR-0026：工具激活状态独立于历史窗口

- **状态**：已采纳，2026-10-28。
- **影响范围**：会话状态、任务恢复、工具目录与请求预算。
- **判据**：`tests/runtime/test_tool_state_lifecycle.py`、`tests/runtime/test_context_contracts.py`。

## 背景

原实现扫描历史 ToolMessage 恢复整个领域。历史预算改变时，工具定义也随之变化；
它还不能还原原始激活顺序。任务 checkpoint 已有 `loaded`，继续扫描历史形成第二来源。
缓存审计证明 schema 变化会影响前缀复用，但命中率不能替代任务成本与授权边界。

## 决策

继续使用标准框架状态保存激活领域，不增加运行时、计划 DSL 或模型路由器。

- 子图的 `loaded` 是同一任务恢复的唯一来源；按当前授权目录重建，保留激活顺序。
- 已完成任务把绑定账号、角色和会话的 `tool_state` 写到会话图。新任务可直接继承，
  无需重复加载仍可用的领域。它是能力目录状态，不是数据缓存、授权或执行凭据。
- 新任务若无法同时容纳继承目录、必要对话、当前输入和输出预留，按原激活顺序逐个回收，
  足够容纳即停止，保留其他定义的相对顺序和全部发现入口。
- 本轮从上轮继承、尚未被选中的领域是可回收候选；模型本批明确选择的所有领域立即保护，
  先保护再执行，不能卸载同批尚未执行的工具。加载新领域遇到预算压力时，只能回收这些
  未选中的继承领域。当前任务实际加载或选择的领域不再回收；无法容纳仍走已有预算收尾。
- 子图保存 `loaded` 与 `evictable` 两个不同含义的集合：实际目录和可回收候选。
  同一任务恢复直接使用这两个字段，不重跑继承、不扫描历史，也不新增预算。
- 回收及保留记录 `tool_working_set`，包含估算schema成本、来源和领域名单；部分回收为
  `tool_menu_trim`，全部继承定义都移除才是 `tool_menu_reset`。估算量不冒充提供商真实用量。
- 不从摘要、宿主历史或工具观察推导激活。旧会话缺字段时使用基础目录，缺字段不妨碍
  原有签名确认与任务 checkpoint 的恢复。无需数据库迁移或批量回填。
- 权限、目录或产品能力变化仍可改变定义；保持缓存不能覆盖权限检查。

## 取舍与复验

固定每轮重置会增加跨轮发现调用；永久携带全部领域会增加无关 schema。
采用有完整预算边界的显式继承，不增加另一套计数上限、淘汰时钟或意图关键词。

离线回归验证状态契约；真实模型连续任务验证短答承接与来源复用。
缓存按冷启动、后续新轮和同任务恢复分组，报告总输入、未缓存输入、调用数及耗时。
服务商缓存是尽力而为，不设置固定命中率作为公共 CI 门槛。
