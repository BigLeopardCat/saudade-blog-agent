# ADR-0012：写操作先记执行意图，未知结果禁止盲目重放

- **状态**：已采纳；旧图接线及键格式已由当前签名操作执行路径替代。
- **核对日期**：2026-11-09。
- **历史来源**：[删除前记录](https://github.com/BigLeopardCat/saudade-blog-agent/blob/5e3d89e18f77ea0edf5c89811deb1346f02e80aa/docs/adr/adr-0012-write-idempotency-ledger.md)。

## 背景与保留的决策

checkpoint 在节点边界保存状态。远端写入已经发生、节点尚未提交时进程退出，
恢复可能再次运行节点；图中的消息和回执无法单独证明写入是否发生。
因此业务写入使用独立持久执行账，先占执行意图，再调用业务服务。

已知完成的操作重放已有结构化结果。只有意图而没有可信结果时报告未知，先查询或人工核实，
不能因超时、取消、重启或 checkpoint 保存失败自动重发。执行账不可用时拒绝新的写入。
账本及去重记录的保留期必须覆盖仍可使用的确认和恢复记录。

## 当前承接与边界

`agent/runtime/writes.py` 将账号、会话、签名操作标识、工具名和冻结参数组成操作键；
生产使用 PostgreSQL 执行账。确认路径仍校验身份、签名、有效期、目标版本及业务权限。
同一操作的回放不能误吞另一次明确批准的新操作。

原记录中的旧图工具收口、按 checkpoint namespace 推导键及 SQLite 降级不是当前生产配置。
这项决策限制重复调用，并不承诺跨服务 exactly-once；未知结果也不等于操作未执行。
模型叙述失败不能触发业务重做，客户端命令还须遵守各自回报协议。

回归见 `tests/runtime/test_write_ledger_contracts.py` 和确认接续测试。
