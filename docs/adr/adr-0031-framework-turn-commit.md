# ADR-0031：持久任务由框架节点提交轮次

- **状态**：已采纳。
- **影响范围**：父执行图、轮次提交、HTTP 适配和会话维护。
- **承接**：[ADR-0020](adr-0020-conversation-store.md)、[ADR-0029](adr-0029-framework-task-state.md)。
- **判据**：完成流式、审批/浏览器接续、提交失败恢复、摘要替换、角色变化及旧回执回归。

## 决策

持久执行父图使用 `agent → commit → approval/END`。
Agent 子图完成后输出本次轮次的提交数据，框架提交节点一起保存有来源的消息、工具事实、
摘要替换和任务状态。待确认任务保留 `run` 并记录原始输入已提交，普通完成清除 `run`。
浏览器 interrupt 停在子图中，不会运行提交节点。

`turn` 是父图中相邻节点之间的临时提交数据，提交后清空；它不参与模型上下文，不是计划、
执行游标或另一份业务执行账。提交节点失败后，标准 checkpoint 保留待提交数据，恢复仅重试
该节点，不重复模型调用或已完成工具。checkpoint 后端若在部分持久写入后报错，状态可能已
提交，调用方不能把异常解释为事务回滚；任务状态与执行账用于判断是否还能恢复或重做。

正文与卡片使用同一个完整回复投影函数。模型完整消息经过现有可见文本过滤后形成当前请求的
正文片段；流式传输发送增量，提交节点保存相同正文。内部控制文本和推理不进入回复投影。
完整回复持久化不依赖客户端是否已经消费最后一个 SSE 帧。

普通请求、显式恢复和标准审批接续不再在图执行后调用维护保存来结束任务。
确认后的模型失败保留执行事实和未完成的图位置；旧授权重放只返回事实，不能清除当前任务。
身份变化后的合法操作回执不能恢复旧身份上下文，使用匹配操作的受控撤销边界终止旧审批。

会话存储仍承担读取、删除屏障、历史维护和不带标准恢复位置的既有卡片。
审批期间的独立插话和撤销后的状态转移仍有适配逻辑，需按
[任务可靠性计划](../task-reliability-plan.md) P0.6 单独收敛。
维护保存必须拒绝结束活动执行；只有原审批绑定一致的历史追加可以保留等待状态。

## 取舍与边界

保留执行账、签名及业务版本核验；图内提交不提供跨服务 exactly-once。
模型循环、工具调度、重试位置、持久化与 interrupt 继续由 LangChain/LangGraph 提供。
没有引入新的执行循环、用户意图路由或业务计划 schema。

这项改动收敛任务状态提交，不证明模型已完成用户全部事项。漏项、工具发现、预算、
批量审批与客户端展示仍按实施计划分别验收。
