# ADR-0007：`unavailable` 的那次原地重试不在提示词层治

- **状态**：已搁置（20261007）
- **背景文档**：[../问题记录.md](../问题记录.md) §1.55（现场、机制、残余与这次的负结果）
- **影响范围**：无（提示词层的两版纠偏**没有落地**，`agent/graph.py` 停在 HEAD）。
  下一层的候选（菜单层禁用）会碰 `agent/skills.py::build_planner_context` 与
  `agent/graph.py::_tools_desc`。
- **判据**：已落地的那一半（`account_roster.planner_contract` 的回落句）由
  `tests/test_account_roster.py` ④/⑥ 两侧锁着；本 ADR 说"不再往提示词层加句子"没有
  判据——它是一条**不再新增**的决定，靠这份文档与 §1.55 的读数执行。
- **触发条件**：① 出现一次**线上现场**（不是评测）证明"写能力因此没有入口"仍在发生；
  ② 或模型换代（`llm_model` 变更）后重测；③ 或有人拿到用户对这一层机制改动的点头。
  三者任一发生，就该先读 §1.55 的 1b，再决定是否走菜单层。

## 背景

uid=0 哨兵下（以及线上任何"身份/服务这一轮给不出数据"的轮次），`list_accounts` 返回
`kind=unavailable` ⇒ `_check_spec` 判 BLOCK——**"服务挂了"不是一条站内事实**，它不能进
跨轮执行记忆。可交回 planner 的东西只有「工具名 + 原因码」，与"你参数写错了"**长得一模一样**
⇒ planner 把这一轮当改参重试：**原地再点一次同一个调用**；键是「工具::原因码」⇒ 同键二次
受阻 ⇒ `blocked_repeat` ⇒ reflector ⇒ `decide=wrap_up` ⇒ 终局计划。主人要办的那件事
（一条**完全能办**的写操作——弹卡这条路本来不需要名录）整条没有入口。

20261007 上午已经用**契约层**治过一半（把"名录读不到 ≠ 不能办…不要再点一次本技能"写进
`account_roster.planner_contract`）：禁言一族改选率 0/4 → 4/6，但**解禁 3/6、禁言 2/6
仍然原地重试**——那句话长在"下一步该去"的技能旁边，而模型卡在"上一步"。

## 决策

**不**在提示词层继续加句子。理由是一次两版、两批共 10 跑/臂的 A/B（§1.55 的 1b）：

- 接线完全正常——臂 A 的目标轮次 100% 记到了 `planner.unavailable_correct`，文本确实进了
  `{correction}` 槽（零额外 LLM、零额外轮次）；
- 但它**没有把"原地重试"变成"改选写技能"，只变成了"当场放弃"**：三个账号写用例共 18 例·跑里，
  臂 A = 改选 12 / 原地重试 1 / **只回一段 chat 5**，臂 B（HEAD）= 改选 14 / 原地重试 3 /
  只回一段 chat 1。两种失败都办不成事 ⇒ 通过率基本不动（臂 A 30+50 绿 vs 臂 B 34+52 绿），
  而每一轮受阻多付四百余字。

**为什么不是"再改一版措辞"**：v1 → v2 已经修掉两处真实疑点（"同一轮内不许重试"留了一条
自认合法的缝；只报工具名、不提 planner 实际选的那个技能），改完仍然如此。同一条禁令住在
契约里、住在纠偏槽里，模型都照样原地重试 —— 这是提示词层的上限，不是措辞问题。

**下一步的候选（未采纳，需先点头）**：让重试**结构上不可能**——在那一轮的菜单里摘掉那个
工具（`build_planner_context` 收一个"本轮禁用"集合），于是它没有可再点的东西、只能改选或
如实作答。它比纠偏文本的爆炸半径大（所有 `unavailable` 轮次的菜单都变，含 `device_query`
与 `own_*` 未登录一族），必须单独 A/B，且要用户点头。

**另一个已经否决的方向**：把 `unavailable` 从 `blocked_repeat` 的键里拿掉（当作可重试）。
那不解决任何事——它只是让空转从"两轮后收尾"变成"撞到 `MAX_PLAN_ROUNDS` 才收尾"。
