# ADR-0038：通用 Agent 长期架构与正式版优先级

- **日期**：2026-11-09。
- **状态**：已采纳范围取舍；通用任务协调架构延期，暂不实施。
- **近期目标**：交付任务质量、性能和成本可验证的博客 Agent 正式版。
- **长期目标**：支持执行中调整、任务切换与受控并行，具备跨业务迁移能力的通用 Agent 架构。

## 背景

博客当前主要需求是问答、检索阅读、页面操作和经过确认的业务变更。
普通聊天脱离网页连接继续执行、同时处理多个交互任务，尚无足够业务需求。
为此引入后台聊天票据、额外状态与前端重订阅链路，会增加发布和故障处理成本。
跨会话后台执行也不能单独满足根据新对话修改旧目标、挂起恢复和自动协调任务的长期目标。

项目仍以高质量推理、工具选择、纠错与上下文管理为发展方向，并保留跨业务装配边界。
智能水平应由真实任务表现衡量；并发数量、框架层数和工具数量不作为替代指标。
近期工程展示和面试材料应来自可复现的实现、取舍与优化证据。

## 决策与当前范围

1. 暂停通用任务协调架构实施，不为正式版新增主从 Agent、自动任务路由或跨任务状态迁移。
2. 撤下未合并的跨会话后台聊天候选：
   [Agent PR #356](https://github.com/BigLeopardCat/saudade-blog-agent/pull/356) 与
   [宿主 PR #244](https://github.com/BigLeopardCat/Saudade-Blog/pull/244)。
   关闭 PR，保留历史供以后参考；不合入功能开关后的闲置实现，不执行配套迁移或部署。
3. 保留主线已存在的在途补充、显式暂停接续、确认机制、DBOS 定时计划及服务并发控制。
   此次撤下的是新增后台聊天方案，不回退独立的业务修复、性能优化或已有调度能力。
4. 近期以[发布验收](../release-acceptance.md)为准优化并冻结正式版证据。
   不因长期架构目标扩大本轮发布范围，也不为通过验收降低质量或授权边界。

当前聊天与后台计划的实际语义以[架构说明](../agent-architecture.md)为准。
下述设计均为未来方案，不代表已上线能力。

## 长期架构方向

采用持续响应的对话 Agent 协调独立任务。简单请求直接完成；需要长时间执行或
隔离上下文的目标才创建独立任务。主 Agent 根据新消息、近期对话和精简任务目录，
决定追加要求、修改目标、启动任务、挂起、恢复、取消或查询进度。
显式任务操作直接调用控制接口；语义不明且可能影响错误任务时向用户澄清。

### 状态与执行

| 概念 | 职责 |
| --- | --- |
| Conversation | 用户交流历史、任务关联和结果展示 |
| Task | 持续目标、约束、证据引用、版本及独立 checkpoint |
| Run | 一次实际执行；由现有持久执行设施管理 |
| Input / Event | 带目标与版本的输入，以及进度、结果和待确认通知 |

复用 LangChain 模型循环、LangGraph checkpoint/interrupt 和 DBOS 持久调度。
任务目录只保存关联与必要索引，不复制完整图状态或维护第三套执行状态机。
会话锁不再覆盖独立任务的全部执行时间；同一任务仍只允许一个执行器推进。
身份归属、会话删除、检查点清理、审批和预算必须随任务隔离一起设计。

### 执行中交互

- 区分即时调整与完成后追加，输入绑定任务、预期执行轮次及版本，拒绝错误目标和过期更新。
- 在模型与工具调用的安全边界消费新要求；过期的未执行工具提案失效，已发生的业务效果保留。
- 接收输入、应用输入、请求暂停、实际暂停分别展示，不能提前宣布状态变化。
- 暂停保存可恢复状态；取消停止后续推进；两者都不撤销已完成的业务操作。
- 独立读取可受控并行；冲突写入继续依赖业务版本校验、确认及执行账。
- 结果通过事件返回主对话，避免 LLM 轮询；需要用户批准的操作不得由协调 Agent 代批。

任务各自保留执行上下文，主对话仅携带有界摘要与证据引用，需要时再检索原始材料。
系统与工具前缀尽量稳定，动态任务状态放在后续消息；不把全部子任务日志复制回主上下文。
简单请求不强制增加分类模型调用或任务委派。协调开销必须计入每个成功任务的完整成本。

### 参考与复用选择

- [Codex App Server](https://learn.chatgpt.com/docs/app-server)：参考 thread/turn 边界、
  `turn/steer` 与 `expectedTurnId`，防止输入到达错误的活动轮次。
- [Claude Code 子任务](https://code.claude.com/docs/en/sub-agents)：参考独立上下文、
  后台消息和恢复语义；公开产品行为不等同于可复用的内部运行时源码。
- [pi agent-core](https://github.com/earendil-works/pi/tree/main/packages/agent)：参考
  steering 与 follow-up 队列的区分及边界处注入，避免将接收消息等同于抢占推理。
- [Deep Agents 异步子任务](https://docs.langchain.com/oss/python/deepagents/async-subagents)：
  重新启动此方向时优先验证现成 middleware。其 Agent Protocol 服务端要求、beta API、
  更新任务对活动 run 和待审批请求的处理，须与现有授权、恢复和部署方式核对后再采用。
- [LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)：复用持久暂停，
  恢复可能重新执行节点，副作用仍须幂等；不将 checkpoint 理解为任意指令位置冻结进程。

不整体移植 coding agent 的 shell、文件系统和单用户工作区假设；只补必要的产品适配。
不新建通用工作流 DSL、消息总线、规划器或多层主管体系。现有框架无法满足的部分，
先用最小兼容性验证说明缺口，再决定是否扩展。

## 近期优化与正式版证据

按实际瓶颈推进，每个候选保留固定基线、改动假设、配对结果与退化检查：

1. **性能**：分开测首反馈、模型首 token、首段正文、工具等待和完整任务耗时。
   优先减少重复查询、无效模型往返和阻塞等待，不用提前发送进度事件掩盖完成延迟。
2. **成本**：按任务类别统计全部模型调用、总输入、未缓存输入、缓存输入和输出，
   包括摘要、重试、失败与取消的消耗。优先优化工具 schema、重复读取和上下文增长。
   跨峰谷价格时段比较用量及缓存指标；费用只在可比价格口径下比较。
3. **RAG**：验证相关证据命中、来源正确、读取范围及检索延迟，减少无关上下文和重复补读；
   使用固定查询与语料版本的对照证据，不为展示引入无业务收益的检索组件。
4. **可靠性**：以实际执行事实验收权限、确认、幂等、取消恢复和浏览器回执，
   复核语义评审疑点，不把检查器的错误归因给 Agent。
5. **发布与展示**：冻结双仓版本、评测条件和报告，记录已知限制、回滚方式与结果覆盖率。
   展示有来源的检索、确认后写入、执行中改要求、异常恢复，以及优化前后质量和消耗。

具体阈值和样本要求只维护在[发布验收](../release-acceptance.md)，本 ADR 不另设门禁。
缓存命中率属于诊断指标，不能替代任务成功率、实际延迟和每个成功任务的消耗。
面试材料说明哪些是已有实现、哪些是已验证收益、哪些是长期设计，不宣称达到某款
coding agent 的通用智能水平，也不将单业务示例描述为已经证明跨领域迁移。

## 重新启动条件与后果

出现真实长任务交互需求，或明确进入第二业务域并需要上述任务协调时，重新评估本 ADR。
评估时要求明确场景、资源预算和验收标准；不因现成框架新增特性就自动扩大范围。

实施顺序为独立任务与恢复、语义调整与任务切换、受控并行。
验收至少覆盖“执行 A → 修改 A → 挂起 A 执行 B → 恢复 A → 结果正确归属”，
以及断线重启、迟到输入、权限变化、待确认操作和上下文压缩后任务不丢失。
跨业务迁移由第二个真实产品的接入与行为测试证明，优先保持执行内核无需领域特判。

延期会保留当前网页执行期间的切换限制，也不会获得自动任务协调能力；收益是减少近期
运行与发布复杂度，将投入集中到可落地质量。已关闭分支仅供参考，未来实现必须基于
届时主线重新评估，不能直接将旧候选视为可发布版本。
