# ADR-0018：以固定 tokenizer 约束完整 embedding 输入

状态：提出；随本次 RAG 输入预算改动评审。

## 问题

字符上限不能保证模型 token 上限。Qwen 首轮验证中 1,800 字符中文样本有 1,189
tokens，超过临时服务的 1,024-token 上限；查询侧另有静默截取 512 字符的行为。
模型、指令与 tokenizer 变化也会影响向量空间，不能只按模型名/端点/维度复用。

## 决策

新增可选、固定校验和的本地 tokenizer profile，使用 Hugging Face Tokenizers。
API 仍可不启用，不为计数加载完整 embedding 模型。不自行实现 tokenizer 或推理服务。

保留原 BM25 切片。向量侧在完整标题/路径/文档指令预算内细分原文窗口，维持同一
小节中的字符偏移；两路继续共用文档聚合与证据读取。热路径复用有界的文档窗口缓存。
查询计入指令与特殊 token，超限回退，不改变问题后再发送。

profile 的语义字段及 tokenizer/窗口版本进入空间签名；内容键覆盖实际请求文本。
无 profile 的原缓存保持兼容；启用/更换 profile 首次重建该空间，后续继续增量。
无效 profile 只影响可选向量路，不能使 BM25 不可用。

## 代价与验证

模型需要提供可信、与服务一致的 tokenizer 文件。JSON 文件由部署者显式准备并核对
校验和，不在请求中下载。文件按不可变配置缓存，更改后重启 Agent。pooling/归一化
声明需要与服务实际参数一致，签名不能自动证明服务配置未漂移。

细分后会增加向量数及建库成本。暂不引入多模型索引路由、自动 API 回退或 reranker。
API/本地对照需记录各自预算和切片差异，不把模型质量与切片策略的收益混为一谈。
协议和源范围用离线回归验证；真实 Qwen 服务验证完整覆盖及零请求重复更新。
质量与目标机资源验收仍需后续实验，见 [输入预算说明](../embedding-inputs.md)。
