# ADR-0032：审批反馈复用原任务并撤销旧预览

- **状态**：已采纳。
- **影响范围**：框架审批、任务恢复、执行账、会话维护与客户端任务标识。
- **承接**：[ADR-0023](adr-0023-confirmation-continuation.md)、[ADR-0031](adr-0031-framework-turn-commit.md)。

## 决策

等待确认期间，新文本作为对当前任务的反馈，通过 `Command(resume=...)` 恢复原审批节点。
节点先按账号、角色、会话及操作标识核验绑定，幂等撤销旧签名，再保存反馈与原操作未执行的事实。
同一 Agent 继续解释、结束或重新准备；文本从不批准业务写入。改变要求后原批次的延迟调用不再执行。
新预览必须取得新的明确确认。显式取消按钮仍使用确定性撤销入口。

任务 ID、框架子图、激活工具和累计预算保持不变。客户端仅接受当前请求流发出的服务端任务坐标；
旧流或其他身份不能重绑当前任务。审批等待时输入队列处于暂停状态，继续后按原任务恢复并收尾。

当前工具消息将旧预览及延迟调用标记为未执行，保留原生工具消息配对。
已提交历史保留预览及随后撤销的事实，不改写历史，也不把“本操作未执行”升级为业务当前状态。
撤销事实不是业务成功回执。

删除隔离执行、状态提升、独立轮次保存和备用叙述模型。普通完成、反馈恢复和确认接续统一经过
`agent → commit → approval/END`；会话存储仅提供加载、删除屏障及必要的受控维护。
没有当前框架审批绑定的签名只能查询已存在的执行账，不能首次执行或接续其他任务。

## 故障与边界

- 撤销前失败：不能宣称操作已取消，也不能继续模型或后续工具。
- 执行账已撤销、审批节点提交前失败：框架重试节点；幂等撤销不得再次写入，反馈恰好出现一次。
- 快照的待执行节点列表为空不代表任务结束；恢复同时检查公开任务记录中的错误及 interrupt。
- 操作已有执行意图但结果未知：不能撤销并谎称未执行，必须核实已有结果。
- 模型或浏览器等待中断：原任务仍可恢复；旧卡不得执行、推进或清除当前任务。
- 图内提交仍不提供跨服务 exactly-once。连接断开时客户端可能未收到撤销展示事件，授权安全由执行账保障。

该设计采用框架持久化的审批反馈语义，没有新增意图分类器、计划 DSL 或任务调度器。
