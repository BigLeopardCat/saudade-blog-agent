# ADR-0032：审批反馈复用原任务并撤销旧预览

- **状态**：已采纳。
- **核对日期**：2026-11-09。
- **历史来源**：[删除前记录](https://github.com/BigLeopardCat/saudade-blog-agent/blob/5e3d89e18f77ea0edf5c89811deb1346f02e80aa/docs/adr/adr-0032-approval-feedback.md)。

## 决策与依据

等待确认期间的新文本作为原任务反馈，经 Command 恢复原审批节点。
节点核对账号、角色、会话和操作绑定，先幂等撤销旧签名，再保存反馈与未执行事实；
同一 Agent 继续解释或重新准备。普通文本不能批准业务写入。

任务 ID、子图、激活工具和累计预算继续沿用，旧批次不再执行已被反馈取代的延迟调用。
新预览需要新的明确批准，显式取消按钮保留确定性撤销入口。
客户端只接受当前服务端流的任务坐标，旧流不能重绑新任务。

## 故障与边界

历史保留旧提议及随后撤销的事实，撤销不能证明业务目标不存在。
撤销前失败不能宣称已取消；执行账撤销后 checkpoint 失败时由框架恢复，
重复撤销不新增业务写入或重复追加反馈。

已有执行意图且结果未知时，不能撤销后谎称从未执行，应先核实结果。
没有当前审批绑定的旧签名只能读取已有执行账，不能首次执行或清除当前任务。
连接断开可能使用户未收到撤销展示，但授权安全由服务端执行账保障。

此决策不引入隔离 Agent、备用叙述模型或新的意图路由器。
