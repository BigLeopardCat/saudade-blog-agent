# 任务可靠性与实现收敛计划

类型：方向型。本文是当前整改的详细执行清单；已上线设计以
[架构说明](agent-architecture.md)为准。阶段状态在本文维护，
[路线图](../ROADMAP.md)只链接本文，不再维护另一份完成度。

## 1. 目标、范围与当前证据

目标是让博客 Agent 主动核实目标、持续完成多步请求，在审批、暂停、浏览器等待和重启后
正确接续，并依据真实结果自然表达。接入框架、覆盖工具、弹出卡片和测试数量都不是任务成功。
模型能力上限与系统造成的能力损失分开评估，不以架构改造承诺模型能力等同于 coding agent。

继续采用 LangChain `create_agent` 与 LangGraph checkpoint / interrupt。
复用公开 middleware、消息、工具和恢复接口；产品保留身份、业务审批绑定、幂等、预算和客户端协议。
不增加意图关键词路由、可执行计划 DSL、第二套调度器或新的通用 Agent 平台。

当前已复现的问题：

| --- | --- | --- | --- |

| R2 | 总结未读、标记已读、跳转，只产生已读确认 | 准备操作可以先于内容读取，且确认产物截断了交付 | P1 设计与真实模型验证 |

## 2. 状态所有权与不可破坏的约束

| 信息 | 权威来源 | 允许的投影 |
| --- | --- | --- |
| 执行位置、待恢复任务和 interrupt | LangGraph checkpoint | API、卡片与进度展示 |
| 当前消息、工具交换、已激活能力 | 框架任务 state | 单次模型请求视图 |
| 写入已执行、未执行或结果未知 | 持久操作执行账 | 工具回执与用户展示 |
| 文章、消息、账号当前状态 | 博客业务服务 | 带范围与时间的读取结果 |
| 稳定用户偏好 | 用户归属的长期记忆 | 按需模型上下文 |

必须满足：

1. 同一执行状态只有一个提交职责；外层展示和历史保存不能结束一个等待中的任务。
2. 审批一项操作只推进这一项；任务是否完成取决于剩余请求。
3. 重复、过期、跨用户、跨任务的审批或客户端回执不能推进执行。
4. 已成功写入不因恢复重复执行；结果未知必须核实，不自动重做。
5. 取消某项操作不是对象当前状态的证据；摘要、页面文本和普通消息不是授权依据。
6. 同一个任务的输入、费用、工具结果跨 HTTP 请求连续，不能因暂停或审批清零。
7. 删除会话后，排队任务和迟到回执不能复活会话。
8. 工具调用和结果保持完整配对；不能靠裁掉头部丢弃当前目标和未决对象。

checkpoint 保存应用进度，不能保存模型内部生成进度。
模型生成中被取消后可能重新请求该次生成；已提交的工具事实和业务回执必须复用。

若单一图内提交不能满足某个产品交互，记录公开 API 的具体限制及最小适配范围，不扩建调度层。

| 入口 | 状态写入职责 | 本批处理与剩余范围 |
| --- | --- | --- |
| 普通持久任务 | 父图 `agent → commit` | 正文、观察、摘要和完成状态一起提交 |
| 审批接续 | `approval → agent → commit` | 执行账先记业务结果；框架提交事实并继续任务 |
| 浏览器等待与恢复 | 子图 interrupt 与原父图 | 等待不提交完成；回执恢复后仍走同一提交节点 |
| 完成节点失败 | 父图 checkpoint | 保留提交数据，恢复只重试完成节点 |
| 审批期间反馈 | 原审批节点撤销签名并保存反馈 | 同一任务、工具状态与预算；输入恰好一次 |
| 替换/撤销后继续 | `approval → agent → commit` | 不提升状态；新操作重新准备预览 |
| 按钮取消、身份变化后结束旧审批 | 匹配操作的受控维护入口 | 必须核验操作标识；不能接续旧身份上下文 |
| 旧授权重放 | 执行账返回事实 | 不能重写另一活动任务的状态 |
| 删除与丢弃重试轮次 | 显式生命周期维护与删除屏障 | 不作为普通轮次完成提交入口 |

提交职责见 [ADR-0031](adr/adr-0031-framework-turn-commit.md)，审批反馈与退役项见 [ADR-0032](adr/adr-0032-approval-feedback.md)。

退出条件：上述边界的状态与业务效果完整验收；旧卡和重复回执不推进；有用户输入恰好一次、
已完成写入恰好一次的断言。执行中止与进程重建分别覆盖，不把重建对象等同于真实进程崩溃测试。
PostgreSQL 恢复按 CI 的显式隔离依赖执行，不使用生产数据库做破坏性演练。

退役项：完成/等待由多个入口分别判定的分支，以及已无调用者的迁移辅助逻辑。
会话删除屏障、权限检查和执行账保留，直到有等价实现及回归证据。

## 4. P1：任务完整性、工具与审批

状态：进行中。P0 已完成；本批收敛标准按需清单、审批前回复和独立交付判据。

代码范围：`agent/runtime/session.py`、`agent/runtime/middleware.py`、
`agent/runtime/catalog.py`、`agent/runtime/tool_execution.py`、`agent/domains/`、
`agent/products/blog/`；目标解析确需宿主能力时联动博客接口。

- [x] P1.1 通过标准 TodoListMiddleware 提供按需清单，记录当前任务事项、状态及证据编号。
  简单任务不增加规划调用；复合任务通过标准工具/state 扩展记录轻量清单，不保存长推理。
  清单属于模型工作记忆，不作为业务执行授权或任务成功的独立证明。
- [x] P1.2 验证总结未读→标记已读→导航。内容读取、总结正文、审批、实际修改和到达页面
  分别验收；解决确认输出覆盖正文或提前截断的问题。先比较标准 HITL 及现有审批适配，
  不通过新增一句场景专用提示词关闭该问题。
- [ ] P1.3 按任务频率和 schema 成本调整基础工具与按需工具。工具目录提供授权能力发现；
  历史中出现但本任务未激活的工具不能直接执行。测量发现次数、未知工具率与额外模型调用。
- [ ] P1.4 收敛机械接口编排：稳定的一次业务能力在工具内部完成参数转换和有界读取，
  不让模型逐个拼 DTO 或无限翻页。返回必要事实、总数、游标和受权限控制的内容引用。
- [ ] P1.5 核查登录名与昵称候选搜索。唯一目标采用稳定 ID；多候选展示区分信息；
  查询为空明确匹配范围。准备操作绑定选定 ID，执行前复核目标及版本。
- [ ] P1.6 同类批量操作使用一个明确的对象集合与变更预览；依赖操作和风险不同的操作
  分开审批。修改内容后旧授权失效。部分成功返回逐项结果，不宣称跨服务原子性。
- [ ] P1.7 确认完成后回到原 Agent；回执包含实际结果，模型继续其余事项并自然表达。
  取消只报告本操作未执行，需要描述当前业务状态时重新读取。
- [ ] P1.8 错误区分参数错误、无匹配、无权限、临时失败和结果未知。读取有限重试；
  写入重试由幂等与状态核实支持，不靠模型盲猜。

退出条件：上述复合任务在真实模型与隔离业务接口中重复通过；报告漏项、错误目标、
多余澄清和纠错调用。卡片出现、模型自报成功和用户清单勾选均不计完整成功。

退役项：公开工具中无必要的后端传输细节、重复的准备/确认协议说明和单次事故专用流程提示。

## 8. 验收矩阵与指标

| 场景 | 必须验收的终态 |
| --- | --- |
| 找文章→读取→解释→指定格式 | 找到正确内容，解释有来源，格式遵循 |
| 未读总结→标记已读→后台导航 | 总结正文真实；审批后正确消息已读；页面回执匹配 |
| 昵称找人→通知→修改正文→审批 | 目标唯一且正确，批准版本与实际发送一致 |
| 同类批量与部分失败 | 一次明确审批、逐项回执、失败项未被报成功 |
| 首项写入完成→取消第二项 | 首项保留，第二项未执行，剩余事项准确 |
| 确认→导航→回执→确认 | 每个等待边界可重建，无重复写入，无丢失任务 |
| 短应答与摘要 | 上一问、候选及选择准确，摘要不变成权限或执行事实 |
| 写入远端成功、本地回执未知 | 核实状态或明确未知，不盲目重复执行 |
| 身份变化、删除、旧卡和迟到事件 | 不能越权、复活任务或推进新操作 |

首版目标待与现有 `eval/release_profile.json` 对齐后冻结，不因本轮结果自动放宽：

| 指标 | 初步目标与统计方式 |
| --- | --- |
| 常见任务完整成功 | ≥95%，报告独立场景数与 Wilson 95% 区间 |
| 多步骤跨确认任务 | 初期 ≥90%，单独分层，不被闲聊通过率稀释 |
| 未授权与重复写入 | 必测集合零失败，出现即阻断；不宣称证明所有输入绝对安全 |
| 恢复 | 必测边界全部通过；线上按实际任务单列失败率 |
| 首次行动正确率 | 只统计需要行动的请求，区分工具选择与不必要追问 |
| 语义质量 | 单列漏项、错误目标、虚构、不必要澄清和用户纠正次数 |
| 时延 | 分任务报告有效反馈、正文首 token、审批准备与端到端 P50/P95；排除人等待时间需注明 |
| 成本 | 每个成功任务费用、失败浪费、总/未缓存输入、输出和模型/工具调用数 |
| 缓存 | 冷/热、工具变化、摘要后首轮、恢复分组；同配置配对，字段覆盖率完整报告 |

简单任务以 1～2 次模型调用为优化目标；复杂任务使用自己的费用与时延分层。
固定版本约 200 个独立场景作为首轮验收规模规划，关键场景重复运行。
该规模不是所有分层都具有足够置信度的保证；小样本分层必须注明不确定性。
本计划不新增一套评分器；复用现有 task metrics、judge 校准、配对对照和发布门禁。
