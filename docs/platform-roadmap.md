# 平台维护与长期规划

更新：2026-11-03。当前实现以[架构说明](agent-architecture.md)为准；
本轮产品验收见[P4进展](p4-progress.md)，架构取舍见[ADR-0036](adr/adr-0036-explicit-product-composition.md)。

## 本轮收尾

| 项目 | 处理 |
| --- | --- |
| 领域反向依赖产品 | 领域改用现有通用权限检查；签名提案移至共享协议模块 |
| 运行时默认绑定博客 | 必须显式传入应用；博客与资源装配移到应用入口 |
| 迁移期命名 | AgentRuntime / CheckpointConversationStore，删除旧导入路径 |
| 表情可用但使用偏少 | 产品提示明确站内表情语法和适度使用；评审使用当轮实际清单 |
| 浏览器虚构完成 | 区分 sent、completed、failed、timeout，失败返回标准工具错误 |
| 容量触发后反复摘要 | 分段压缩持续到目标容量，保留当前任务与覆盖来源 |
| RAG通用算法 | BM25S、LangChain、SciPy、Tokenizers与CommonMark parser承接通用能力；来源与增量发布属于应用适配 |
| 静态扫描失效 | Ruff 共用严格 JSON 适配，扫描异常拒绝通过或更新基线；保留原质量阈值 |
| 模型清理等待 | 有限清理、实际退出计数与失败停用，见 [ADR-0037](adr/adr-0037-bounded-model-cleanup.md) |
| 发布验收 | 先小批量后固定全量；分别报告确定性结果、语义复核和未评估项 |

实现完成、部署完成和产品验收通过分别记录。开发回归不等同于独立验收。

## 后续事项与启动条件

| 优先级 | 事项 | 启动条件与完成标准 |
| --- | --- | --- |
| P1 | 独立验收集 | 由未参与调优的策展者提供；来源分组隔离、封存与去重检查通过。现有开发集不得换名充数 |
| P1 | 真实故障恢复演练 | 在隔离业务夹具中验证模型中断、数据库失联、进程退出、执行结果未知；既有行为和PG测试继续保留 |
| P1 | 运营可靠性 | 持续收集可用性、任务成功率、用户纠正及未完成原因；达到观察周期后再评价SLO |
| P1 | 依赖安全维护 | 按实际执行路径处理嵌套KaTeX、rustls等可达依赖；保留公告的适用条件，修复与复测后再关闭告警，不批量dismiss |
| P2 | 相对期限由后端归一化 | 后端准备接口提供固定绝对时刻与规范化意图后迁移；确认时不重新计时，覆盖时区、准备后等待、版本冲突与回放。边界见[职责说明](backend-capability-boundaries.md) |
| P2 | 业务查询投影下沉 | 通知覆盖窗口外查询时优先补后端筛选、分页和按编号查询；公开文章返回标签投影，待办提供按编号状态。以少取数据、减少往返及范围正确为验收，不以删除Python循环为目标，见[职责说明](backend-capability-boundaries.md) |
| P2 | 注册表延迟导入 | 有启动剖析表明业务模块导入成为瓶颈，或需要可选依赖独立安装时启动。保持权限目录和执行端一致 |
| P2 | 独立能力包分发 | 第二个真实产品需要独立发布能力包时评估标准Python entry points；当前显式装配继续适用 |
| P2 | 原生异步接入与顺序工具 | 全局 `max_concurrency=1` 在当前消息流配置下发生等待线程与图任务争用，隔离回归死锁；保留现有顺序屏障。改为框架原生异步入口或官方工具节点独立并发配置后，必须通过顺序、前置失败阻断、确认回放、流式和取消测试才删除屏障 |
| P2 | 检索器直接组合 | 当前 `EnsembleRetriever` 校验要求权重与检索器数量一致，不能用空检索器调用融合方法。保留有效适配；将实际词法与向量检索接入标准 retriever 后再删固定列表包装，保持来源、版本一致性、降级及 embedding 调用次数 |
| P2 | 工具结果表示收敛 | 工具领域改动时将结构化结果统一到标准 artifact 边界，减少字符串往返；须保留错误、确认、部分失败与回执事实，不引入新 IR |
| P2 | 静态词表门禁收敛 | 按行为测试逐项承接实际路由和安全风险后，删除源码形状及无关文案计数约束；不得以删除统计放松权限或执行质量门槛 |
| P2 | Runtime职责整合 | 发现实际循环依赖、重复状态机或重复职责时处理；不按文件数量合并，不再实现框架循环 |
| P3 | adminops模块归组 | 下一次涉及相应业务改动时按职责迁入领域包，同时改调用方与文档；不保留空壳兼容层 |
| 条件触发 | MCP、第二提供方、OTel | 分别出现外部工具接入、多提供方运营或集中观测消费需求时采用成熟实现 |
| 暂缓 | 图谱、多模态与Jev | 有明确产品需求、足够语料和固定对照评测后再启动；不作为本轮收尾前置 |

继续使用LangChain/LangGraph及DBOS承接执行、持久状态和后台任务。
应用维护身份、授权、确认绑定、幂等账、业务事实和界面协议；不建设通用Agent平台。

## 维护约束

- CI从锁定的公开宿主版本读取跨语言契约，不需要生产配置、密钥或本机路径。
- 缓存按冷/热、schema变化、摘要后首轮及恢复分组；使用服务商真实usage，缺失字段标未知。
- 卡片和业务写入检查不被语义judge替代；judge也需要校准、人工复核和未评估出口。
- 优雅关停复用服务框架和标准资源生命周期；业务未知结果通过执行账核实，不杀线程或盲重做。
- 历史事故与决策保留在Git和ADR；当前文档只描述有效行为及仍存在的限制。
