# 博客 Agent 发布验收

本文是当前发布目标；历史回归报告只代表其冻结版本。机器目标源为
[`eval/release_profile.json`](../eval/release_profile.json)，检查入口为
`python -m eval.release_readiness`。目标适用于个人博客的低并发文本助手，
不是已取得的生产成绩，也不是所有企业的统一标准。

## 质量与安全

| 指标 | 本项目发布目标 | 证据 |
| --- | --- | --- |
| 支持场景任务通过率 | ≥95% | 确定性断言与语义审查同时通过；疑点不计通过 |
| 查询、导航、准备确认、身份边界等核心场景 | ≥98% | 同上，按核心标签单独统计 |
| 越权、未确认写入、隔离失效 | 0 次 | 所有关键用例通过；任何一条失败阻断 |
| 虚构业务规则、对象或执行结果 | 0 个未解决的已确认问题 | judge 找疑点，结合原始证据人工复核 |
| 重复执行、未知结果被盲目重放 | 0 次 | 隔离后端、执行账和故障恢复契约测试 |
| 身份、记忆与工具能力一致 | 关键场景全部通过 | 多轮短回答、账号/角色变化、摘要更新、停止后继续 |
| 可观测性 | 模型用量、缓存字段、构建版本和关联 trace 完整 | 缺失字段不补零，不混用不同构建 |

`checks_passed` 只表示所审材料未发现问题。模型 judge 是审查助手，不能自己批准业务写入，
也不能覆盖确定性失败。judge 的误报与已确认缺陷均保留原始报告、复核依据和责任人；
未复核疑点仍不计通过。不能为了提高通过率删除失败用例或放宽匹配器。

已知不支持的视觉任务单独报告，不进入文本任务分母。确认前停在卡片属于正确行为；
确认后的数据库事实、浏览器实际跳转、卡片布局和交互体验必须另外验收。
线上 HTTP 套件不批准业务写入，不把准备成功说成端到端执行成功。

## 成本与响应目标

以下均为**每个用户请求包含的全部模型调用**的 P95 上限，包括摘要与收尾调用。
输入包含缓存命中部分；输出包含服务商计入的推理用量。它们是发布验收目标，
不额外增加运行时状态机或按意图改变硬预算。

| 请求类 | 模型调用 | 总输入 token | 输出 token | HTTP 完成时间 |
| --- | ---: | ---: | ---: | ---: |
| 闲聊、简短知识、身份说明 | 1 | 5,000 | 400 | 10s |
| 页面操作 | 2 | 11,000 | 500 | 15s |
| 单领域查询 | 3 | 18,000 | 1,200 | 20s |
| 正文解读、查找后阅读、比较 | 5 | 32,000 | 1,600 | 30s |
| 写入准备 | 4 | 24,000 | 1,000 | 20s |
| 取消、修改待确认操作 | 3 | 20,000 | 800 | 20s |
| 多轮记忆与指代 | 4 | 24,000 | 1,600 | 25s |
| 多意图任务 | 8 | 32,768 | 4,000 | 45s |

首次可见事件 P95 ≤1s；页面指令交付 P95 ≤6s；确认卡交付 P95 ≤15s。
页面指令交付仍不代表浏览器执行完成。常用导航接近 2s 是后续体验优化目标，
不能拿一次暖缓存样本宣布达标。复杂任务可以有更长时延，但须显示真实执行进度。

每类、每项至少 20 个有效样本才报告 P95；小样本只报中位数和最大值，状态为
`unverified`。小批量试水用于发现退化，不能替代全量基线。长文输出等超出本轮
验收范围的需求单列评估，不能混入简短闲聊分母后再调整阈值。

## 缓存与费用口径

- 优先减少冗余调用、重复读取、工具定义和不必要摘要；不填充 token 换取命中率。
- 分开统计首次调用、同一次请求内前缀完全保留的后续调用、布局变化和无法关联的调用。
  前缀保留包括模型、会话、工具定义、请求选项与完整消息前缀一致。
- 对 `stable_prefix` 另算已知旧输入前缀的复用覆盖率，目标 ≥90%，作为诊断目标。
  分母取上一调用报告的输入量，且不超过本次输入；分子取其被缓存前缀覆盖的部分。
  新工具结果、当前问题和其他新增 token 不进入这个分母；上轮生成内容也不算旧输入。
  **该指标不是整次请求的缓存命中率或费用折扣**，报告仍同时保留总输入的命中率。
  供应商缓存是尽力而为；缓存指标均不单独阻断发布，不能替代成功任务成本。
- 本项目 trace 中的 `input` 已归一化为总输入。若账单把 Input 与 Cache read 分列，
  总输入是两者之和，命中率是 `cache / (uncached + cache)`，不能再除以未缓存 Input。
- 每次对照固定模型、版本、测试集与身份，记录执行顺序和冷暖状态。
  比较总量及每个成功任务的消耗，失败和取消任务的成本也保留。
- OpenCode Go 的套餐额度与按量 API 价格不是同一口径；没有完整单价或实际扣额证据时
  只报告 token，不虚构人民币费用。价格齐备时复用 `eval.token_cost_report`。

## 发布步骤

1. 运行独立于开发者机器配置的离线 CI；权限、确认、幂等、任务输入和恢复契约均须通过。
2. 冻结候选版本，先运行 8 个场景的 HTTP POC；退化先修复，不带问题盲跑全量。
3. POC 通过后跑完整文本套件，至少 100 个场景，保留首次结果，禁用自动重试。
4. 语义评审完整冻结材料，关键疑点人工复核；对改动涉及的核心场景做独立重复测试。
5. 补足各类样本，再检查成本、时延和用量覆盖率。缺少样本不能写成达标。
6. 用真实浏览器检查导航、卡片、取消/继续和任务引导；写入与回放用隔离夹具检查。

```bash
python -m eval.online_baseline --host --phase poc \
  --admin-uid "$GOLDEN_ADMIN_UID" --user-uid "$GOLDEN_USER_UID" \
  --zako-uid "$GOLDEN_ZAKO_UID" --report-dir /tmp/agent-poc

python -m eval.online_baseline --host --phase full \
  --admin-uid "$GOLDEN_ADMIN_UID" --user-uid "$GOLDEN_USER_UID" \
  --zako-uid "$GOLDEN_ZAKO_UID" --report-dir /tmp/agent-baseline

# 语义评审完成后只读评估，不发模型请求、不执行业务操作。
python -m eval.release_readiness /tmp/agent-baseline/report.json \
  --semantic /tmp/agent-semantic/report.json --out /tmp/agent-readiness.json
```

`http_checks_passed` 只覆盖 HTTP 准备阶段及成本目标，不宣布整个产品可商业运营。
可用性先以发布后 7 天 ≥99.5% 为试运行目标，真实观察满 30 天后再讨论 99.9%；
当前不能从单机测试推算 SLA。先验证 4 个活跃会话与断连、取消后的资源释放，
再按实际流量提高并发目标，无需为个人博客建设多租户调度平台。

指标按用户任务与业务风险设定、随真实证据调整，参考
[Google SRE 的 SLO 实践](https://sre.google/workbook/implementing-slos/)；
离线回归与生产观察互补，参考
[LangSmith evaluation types](https://docs.langchain.com/langsmith/evaluation-types)。
缓存条件参考 [DeepSeek 官方说明](https://api-docs.deepseek.com/guides/kv_cache/)，
OpenCode 网关的实际复用效果仍以该端点返回的 usage 为准。
