## 实现结果

- P1：明确对象集合的批量标签变更使用一张确认卡，执行前整体复核版本；
  不同风险或依赖操作分别授权。失败回到原 Agent 核实，未知结果禁止自动重放。
  读取通道分类错误、有界重试，每次尝试检查取消和剩余截止时间。
- P2：标准 `create_agent`、`SummarizationMiddleware` 与 LangGraph checkpoint 管理执行和恢复。
  超大旧历史按完整消息及工具交换分段摘要，每段保存覆盖范围；恢复复用已完成摘要。
  当前任务原文、用户补充、审批事实和工具激活不由摘要替代。
- 分离模型窗口 1M、工作输入 128K、累计任务 token 1M、模型/工具次数 12/16 和活动时间 300 秒。
  压缩按容量约 80% 触发、约 40% 为目标；额度不足明确停止，不进一步裁掉任务依据来尝试调用。
  人工等待不计活动时间，进程失联保留预留；预算停止仍保存结果和关闭本地审批。
- 请求记录脱敏消息、工具、生成参数和端点指纹，定位首次变化；排除递减 HTTP 超时的伪变化。
  摘要/主对话、恢复/新任务、成功/失败/未评审任务分别计量。缺失字段、未知费用不补零。
- 对话记忆、任务状态和业务知识各有来源与权限边界。跨会话长期偏好自动提取和写入未启用，
  不从摘要或模型猜测生成用户画像。

部署删除 `AGENT_REQUEST_TOKENS`，使用 `AGENT_TASK_TOKENS` 与 `AGENT_TASK_SECONDS`，没有旧参数别名。
具体决策见 [ADR-0034](adr/adr-0034-context-task-budgets.md)；完整阶段清单见
[任务可靠性计划](task-reliability-plan.md)。

## 用量与缓存

| 样本 | 总输入 | 缓存输入 | 未缓存输入 | 命中率 |
| --- | ---: | ---: | ---: | ---: |
| 生产 13 轮 / 17 次模型调用 | 64,190 | 39,552 | 24,638 | 61.6% |
| 其中连续记忆追问，排除首次请求 | 13,198 | 12,416 | 782 | 94.1% |
| 隔离组主对话 22 次 | 82,667 | 74,752 | 7,915 | 90.4% |
| 隔离组摘要 6 次 | 88,989 | 44,160 | 44,829 | 49.6% |

生产输出 1,888，其中 reasoning 1,150 是子集，不能再相加计费。
生产抽查包含多个新会话、不同身份、首次文章内容和新增工具目录，不能用暖会话 94.1% 代表整体。
隔离组刻意用 24K/16K 小窗口触发摘要，总命中 69.3%；这不是生产的 1M 窗口配置或日常摘要频率。

同端点自动工具模式的 A/A/B/B 配对请求：相同输入 2,207、重复时缓存 2,176；
追加工具后输入 2,253、缓存 2,048，再次重复缓存 2,176。
本次工具追加保留了大部分缓存，但相同指纹、工具追加或路由亲和均不保证服务商一定命中。

原始响应同时验证：标准 `prompt_tokens` 包含缓存，OpenCode 明细 `tokens.input` 是未缓存部分。
命中率可用 `cache / prompt_tokens`，或 `cache / (OpenCode input + cache)`；两种口径不能重复相加。
Go 的 list cost、allowance 不是实际账单，费用保持未知；完整价格下的估算沿用 `token_cost_report.py`。

生产请求结束 P50 约 3.5 秒、首段正文 P50 约 3.55 秒；进度事件先出现不代表正文首 token。
不足 20 个请求，不报告 P95，也不据此宣称企业成功率达到 95%。
