# 主流 ReAct + 按需 schema：架构改造方案

- **档**：方向型（§6 每阶段都有触发条件与预注册判据）
- **状态**：**未开工**。这份文件只出方案，不动代码。
- **前身**：`docs/tool-menu-poc-20261020.md`（工具级菜单 POC）、
  `docs/prefix-cache-audit-20261020.md`（成本审计）

**一句话**：把 planner 从**受限规划器**降成**路由器**，schema 从**每次全量**改成
**索引 + 按需取**，执行层改成 **ReAct 循环**；**叙述层保持零工具**、人设只此一份。

> ⚠️ **这份方案有一条不能碰的红线**：narrator 必须仍是**零工具节点**。
> `react_arm.py:739` 写死了理由——闸门判的是"叙述的**声称**与执行事实对不对得上"，
> 而那个判据成立的前提是 narrator **结构上不可能动手**（"我调用了 X"从它嘴里出来
> 必然是声称）。**给它装工具 = 拆掉判据的地基。** 本方案全程不动这一条。

## 1. 为什么现在能拆

### 1.1 诊断：当年是信息不对等，不是模型能力不够

这一族事故全部出自 `docs/问题记录.md` 与 `gate 声称洞①–⑭`，
**逐条读下来没有一条是"模型推不出来"**，全是 harness 把信息喂错/喂漏：

| 事故 | 真身 |
|---|---|
| 契约里出现可抄的否认句 | 提示词里**给了一句可以照抄的假话** |
| 站内「没有」误伤能力否定 | 判据把"站内没有 X"与"我没有 X 能力"混成一格 |
| 删规划契约 ⇒ 检索族成片红 | 那句契约**没有别的落点**，删了就没人替它写 |
| `task_intents` 的"本领名"描述 | 同一份上下文里两句话互相打脸 |
| 零调用轮的正控问题 | 纯否定族在"什么都不产出"的臂上**恒真** |

**⇒ 受限规划当年是在替模型补信息**（工具语义、返回口径、完成判定）。
现在 `agent/planner_llm.py` 的 schema、`authz` 的角色过滤、checker、同意闸、
`reply_contract` 都已经把这些**显式写下来了** ⇒ 补信息这件事有别的落点了。

### 1.2 实测：现在的账（全部从生产 trace / 离线渲染量出）

| 量 | 值 | 出处 |
|---|---|---|
| planner 单次输入 | **52,145 tok** | 生产 trace，admin |
| ├ 其中 **tools schema** | **38,738 tok（74%）** | 两角色两方程解 + trace 真值重渲校核 |
| └ 其中提示词正文 | 13,407 tok（26%） | 同上 |
| schema 解剖 | 散文 41,499 字符（**50.2%**）/ 结构 41,113 字符 | 剥 description 前后对比 |
| planner 调用次数 | **1.61 次/轮**（多轮占 38%） | 57 个会话轮 |
| **首轮决策落在 `chat`** | **40%**（21/57） | 同上 |
| narrator 输入中位 | 12,759 tok（其中逐字历史 ~65%） | 生产 trace |
| planner 缓存命中 | 50.1%（33/92 全冷） | 见成本审计 §3 |

**最刺眼的一格**：**40% 的轮次要付 52,145 tok 才能得出"这就是句闲聊"。**

### 1.3 但信念缺一次实验

「harness 已经够好、可以上 ReAct」——**最接近的那次读数不乐观，而且它是今天的 harness 跑的**：

| 臂 | 读数 | 它改了什么 |
|---|---|---|
| `graph`（生产） | 0.9825 | — |
| `react` | **0.9766** | **加 loop**（菜单不变） |
| `tools` | **0.6725** | **平铺 73 工具 + 自由选工具** |

⇒ **loop 本身只值 −0.6pt**（`react` 臂），所以"上 ReAct"这件事本身**不是**风险源。
**风险在 `tools` 臂**，而它**一次改了两件事**（菜单形状 + 丢掉 `instantiate_plan`），
**这两件事的贡献现在分不开**——这正是 §6 分阶段要拆的。

## 2. 目标架构

### 2.1 拓扑

**四个节点名是跨语言契约，不许改**（`server.py` 的生产者按名字从 `updates` 里取
恰好这四个键，且只把 `langgraph_node == "model"` 的分片当用户可见正文）。改的是
**每个节点干什么、提示词多大**：

```
现在（react_arm.build_graph()，与生产同形）：
  START → planner ─┬─(有技能调用)──→ execute ─┬─(弹卡/零改动)──→ END
                   │                          └─(还有得做)─────→ planner
                   ├─(零工具 = 收尾)─→ model ──→ gate ─┬─(gate_replan，只此一次)→ planner
                   └─(预算/无进展)───→ model            └────────────────────→ END

目标：
  START → planner ─┬─(闲聊 / 无需动作)───────────────────────────→ model → gate → END
                   └─(选定族 + 意图)──→ execute ─┬─(还有得做)──→ execute
                                                 └─(做完)───────→ model → gate → END
```

### 2.2 每个节点改什么

| 节点 | 现在 | 目标 | 提示词大小 |
|---|---|---|---|
| `planner` | 受限规划：从 52 条技能里选一条 + 填参 | **路由器**：选**族** + 意图，或判"闲聊" | 52,145 → **~8,000 tok** |
| `execute` | 按 `instantiate_plan` 展开的**固定工具序列**逐条执行 | **ReAct 循环**：只绑**该族的**工具 schema，自由选工具 | 每次 ~8,000 tok |
| `model` | 零工具 narrator：人设 + 24 条叙述纪律 + 计划 + 帧 + 回执 | **不变**（本方案一个字不动） | 12,759 tok |
| `gate` | 判叙述声称与执行事实 | **不变** | — |

### 2.3 「chat 就是叙述层」

今天 `chat` 是一条**技能**（有 `reply_contract`、走 planner → execute 零工具 → model）。
目标里它**不再是技能**：路由器的"无需动作"出口**直接连到 `model`**，
`planner` 那一格只写一个空计划。

**省的是**：40% 的轮次不再付 52,145 tok 的 planner 提示词。
**不是省在**"少一次调用"——chat 轮从"planner + narrator"变成"router + narrator"，
**调用次数一样**，省的是**每次的体量**。

> ⚠️ **纠正一处**：`_PLANNER_PROMPT`（12,978 字符）里 `人设` / `口气` / `persona` /
> `喵` **各 0 次**——**planner 今天就没有人设**，人设（2,182）与叙述纪律（6,927）
> 只在 narrator。所以"省掉 planner 的人设提示词"这笔**不存在**；
> 能省的是 planner 的**规划规则块**（12,978 字符）与 **schema**（82,612 字符）。

## 3. 按需 schema 的机制

### 3.1 索引与取回

```
planner 看到：      50 条技能各一行索引（实测 2,633 字符 ≈ 1,253 tok）
                    + 结构（名字 / type / enum / required / 嵌套 schema，41,113 字符）
                    + 一个 describe_skill(name) 工具
需要细节时：        调 describe_skill("content_query") ⇒ 返回完整 description
                    （~420 字符 ≈ 200 tok，一次 1–2 条）
```

**结构一个字不动** ⇒ enum 白名单（带参清单靠它拦）、工具名、required 全部保留。

| | 现在 | 改后 |
|---|---|---|
| 结构 | 41,113 字符 → 19,570 tok | 19,570 tok（不动） |
| 散文 | 41,499 字符 → 19,754 tok | 索引 1,253 tok + 取回 ~400 tok |
| **schema 侧合计** | **38,738 tok** | **≈21,200 tok** |
| **planner 输入** | **52,145 tok** | **≈34,100 tok（−34.6%）** |

### 3.2 为什么这不违反既有结论

- `saudade-agent-surface-carries-contract`：「删规划契约 ⇒ 检索族成片红 ⇒ 契约搬进
  函数 schema」。**但"搬进 schema" ≠ "必须常驻"**——它要的是**决策那一刻看得见**，
  按需取正好满足。
- `eval/contract_position_ab.py`（7 用例 × 12 遍）已实测**位置无关**：
  住正文 84/84、住 schema 84/84、**整句删掉 73/84**。⇒ 契约那句话**本身承重**，
  但**放哪不重要**。索引化属于"换个位置"，不是"删掉"。
- **也不是 POC 那个"平铺 73 工具"**——那还是一份**完整**目录，只是更长。

## 4. 保住的清单（本方案一个字不动）

| 资产 | 为什么不能动 |
|---|---|
| **narrator 零工具** | gate 判据的地基（见文首红线） |
| `instantiate_plan` 的**固定工具序列** | checker 验收 / 7 个写参数校正器 / 同意闸次序 / 收尾判定**四样东西的落点**。§6 阶段 2 才碰，且只对只读族 |
| `authz.TOOL_SCOPE` 角色过滤 | 越权面靠它，不靠提示词 |
| 同意闸 / `_confirm_popup` / `_grant_covers` | 写操作唯一入口 |
| `_drop_correction` 剔空纠偏 | 静默空计划交 narrator ⇒ 重开幻觉洞 |
| 19 条 regression 硬层 | 判据不许空过 |
| 四个节点名 | 跨语言生产者契约 |

## 5. 明确不做

- **不给 narrator 装工具**（红线）。
- **不合并/精简工具**——"把 70 个工具并成几个可组合的"**本身就是另一种手写分组**，
  量它等于量"手写分组 v2 vs 手写模板 v1"。本方案量的是**组织方式**，不是重新分组。
- **不缩写描述**——schema 那 50.2% 的散文里装的是**路由契约**，缩写 = 删翻译层。
  **只许去重 / 外置，不许缩写。**
- **不在第一轮碰写族**（30/50 条技能）。
- **不动 golden 用例**（子集只用 `--only`）。
- **不部署、不重启、不装 cron**。

## 6. 分阶段（每阶段独立、可回退、判据跑前定死）

### 阶段 0：散文外置（不动架构）

**动**：`build_tool_schema` 的 description 截成一句索引 + 新增 `describe_skill`。
**不动**：技能层、`instantiate_plan`、gate、写族、narrator。

| 判据 | 阈值 |
|---|---|
| schema 侧 tok | 38,738 → ≤22,000 |
| `landing_gate.ab_compare(graph, index)` | 无回归（Wilson 下界差不超 `AB_TOL=0.005`） |
| 19 条 regression 硬层 | 全绿，**不许空过** |
| 取回率（模型调 `describe_skill` 的比例） | **这是主读数**——太低说明索引没在起作用 |

### 阶段 1：路由收窄（保留固定序列）

**动**：planner 第一轮看**粗菜单**（族），选定后只绑那一族的 schema。
**不动**：`instantiate_plan` 的固定序列**保留**。

| 判据 | 阈值 |
|---|---|
| POC **A 族**（13 条近义选错） | 转绿 |
| 19 条 regression 硬层 | 全绿 |
| planner 输入 | ≤ 阶段 0 的 60% |

### 阶段 2：执行层改 ReAct（**只对只读 + 导航 + 检索族**）

**动**：`execute` 从"跑固定序列"改成 ReAct 循环，只绑该族工具。
**不动**：写族继续走模板；narrator 零工具。

| 判据 | 阈值 |
|---|---|
| POC **B 族**（8 条定序漏步） | **不许掉**——这是本阶段唯一要证的东西 |
| 19 条 regression 硬层 | 全绿 |
| `arm_capability --arm <新臂> --probe` | `comparable=True`，否则**退出码 3、pass_rate 不许引用** |
| 不变量 | `corpus_invariants` I2 零调用 / I3+I4 fallback / I5 / I7 |

### 阶段 3：写族

同阶段 2 的判据，另加：7 个写参数校正器与同意闸次序**逐条搬家**，每搬一条留一条锁。

## 7. 风险与对照

| 风险 | 对照 / 反假绿 |
|---|---|
| **取回率低** ⇒ 退化成"描述全删" | 必须有 **`names-only` 对照臂**（只留名字、无索引、无 `describe_skill`）。**index 与它的差才是那次取回的价值**；打平 ⇒ 阶段 0 不成立 ⚠️ 探针 `_selfcheck` 有一条"菜单说明非空"断言，该臂会被判红，需先决定豁免写法 |
| 探针语料是 **user 角色**设计的（25 条，无 admin 专属句） | 跑 `--role admin` 前**先补 admin 语料**，否则量的是"schema 本来就不大"那一档 |
| **单遍是噪声** | `--rounds 3` 是下限；相邻两次同配置红集只重叠 ~5 条 |
| **缓存那笔账会变** | 现在 schema 是**恒定**的 39,319 tok（跨会话可共享）；索引化后**路由那一次**小且恒定（命中率高），**执行层**按路由变 ⇒ **跨会话不再共享**。**总量大幅下降是真的，但"命中率高"只在路由那一次成立**——要定价，别断言 |
| 多一次往返 | `rounds` 是读数、`BUDGET=6` 是熔断。**"多几轮算可接受"跑前定死** |

## 8. 估算（**标注假设，未实测**）

按 §1.2 的实测值与下列假设推算，**仅供排序，不作为承诺**：

- chat 轮（40%）：现在 52,145 + 12,759 = 64,904 → 目标 router ~8,000 + 12,759 = 20,759（**−68%**）
- 动作轮（60%）：现在 52,145 × 1.61 + 12,759 = 96,713 → 目标 8,000 + 8,000 × 1.61 + 12,759 = 33,639（**−65%**）
- **router 8,000 tok** 与 **act 8,000 tok/次**是**估算**：前者 = 索引 1,253 + 规划规则（12,978 字符需大幅收窄）+ 注入槽；后者 = 该族 8 个工具的 schema + 窗口。**这两格是这份方案里最不确定的数**。
