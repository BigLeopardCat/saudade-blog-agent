本页解释已经实现的关键设计，供代码复盘和技术评审使用。框架能力与应用实现分别说明；具体发布成绩以固定版本的验收材料为准，不把案例描述当作当前生产指标。

## 1. 全文总结：读取完整与模型看见完整是两件事

用户要求总结整篇文章时，RAG 命中相关片段不能证明处理了全文。逐页把正文放进普通对话也不保证先前页面在后续压缩后仍然可见。

项目因此将问题检索与全文总结分开。总结模式从零偏移开始，按同一文章修订连续读取，核对解析器、总长度、起止范围和续读坐标，再不加分隔符地拼接原文。存在缺页、版本变化或取消时，不把部分结果交付成完整总结。

完整原文能放入主模型下一次请求时直接交付，不因 HTTP 分页额外调用摘要模型；放不下才使用 LangChain stuff/refine 链。派生摘要独立记录源覆盖，不能登记为主模型直接读过全部原文。

内部生成成功仍可能交付失败：来源链接、覆盖元数据、同批工具结果与最终答复都占容量。实现先计算实际结果信封，预检摘要计划，并为主模型临时保留收尾调用和 Token 额度；保留不是消费，退出时释放。过长或截断的摘要拒收，不靠裁断冒充完整。

增大上下文不能替代源连续性、任务累计预算和最终答复预留。完整覆盖也不能保证摘要忠实，应继续检查前中后章节和跨章节限制。

代码：[源读取与交付](../agent/domains/articles/summary.py)、[摘要模型链](../agent/domains/articles/summary_model.py)、[观察额度](../agent/runtime/tool_context.py)。验证：[全文总结](../tests/test_article_full_summary.py)、[请求额度](../tests/runtime/test_observation_plan.py)。完整契约见 [RAG](rag-design.md) 与[会话预算](conversation-memory.md)。

## 2. 写入成功但响应丢失：本地执行账不等于远端事务

公告已在宿主提交，但 Agent 未收到回执时，盲目重试可能重复写入或通知；直接标失败也会误报业务状态。

Agent 执行账通过唯一操作键和原子派发转换协调并发批准、取消及恢复。宿主对支持的单项即时公告操作，使用稳定操作编号，在同一 PostgreSQL 事务内完成去重、业务变更及回执保存。两层解决不同问题，不能省成一个跨服务的“先入账就安全”。

响应丢失后查询原操作编号。匹配回执恢复原结果；明确 absent 且原批准仍有效时，才可向同一幂等入口提交同一请求，迟到提交仍由宿主唯一约束去重。absent 本身不证明未执行；查询失败、旧端点不支持或签名失效均不授权重放。

本地提前标成功可能丢工作，事后标成功存在崩溃窗口；宿主幂等也不能替代用户批准和当前权限校验。因此保留两层记录，并对不支持业务恢复的工具保守报告未知，不承诺所有写入 exactly-once。

代码：[执行入口](../agent/runtime/writes.py)、[公告恢复](../agent/domains/announcements/recovery.py)。验证：[执行账契约](../tests/runtime/test_write_ledger_contracts.py)、[公告原生链路](../tests/domains/test_announcements_native.py)。完整边界见[身份与写入](identity-and-permissions.md)。

## 3. 评测：主干正确不能抵消局部虚构

比较表格的一格可能编造限制，语义 judge 也可能把违反明确长度要求的答复判为通过。只看语气、最终一句话或整体印象，不能证明任务完成。

执行事实由确定性检查核对：实际工具、目标、签名、写入次数、回执和观察状态。语义评审按对应来源修订检查逐项主张，使用 OpenEvals 接线，业务 rubric 与标注校准集由项目维护。缺失、截断或无法解析的评审记为未评估，不能自动通过。

保留首轮失败材料；校准开发集与独立验收集分开。误判应改进判据或新增独立检查，不能通过重跑筛选通过结果。精确输出等可机械判断的要求，应采用适用的确定性检查，不能全部委托给模型评价。

统计也遵守证据边界：缺失 usage 不补零，套餐额度与现金分开，内部摘要调用计入任务，小批诊断不宣称生产 P95 或长期成功率。数据库、浏览器、模型和部署证据分层报告，历史报告不自动继承为新版本成绩。
