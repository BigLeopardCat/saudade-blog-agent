## 缓存与压缩

- 连续短聊 12 轮每轮一次模型调用，无摘要。排除首轮后，11 轮缓存输入命中合计 94.0%，未命中输入中位数 188 token，范围 78–254。
- 全量整体输入命中约 71.24%，包含新会话、目录变化和压缩。不能把它与暖会话混成同一个目标。
- 89 次实际前缀保持不变的调用，已知可复用前缀重用约 98.16%。新追加正文仍需预填充，不计为应命中而失败的缓存。
- 五轮长会话实际触发框架压缩，并正确回忆最早的项目名与预算。POC 中历史估算从 6,188 降至 2,179 token。压缩改变前缀后的冷缓存是预期代价。

## 语义评审与门禁

原始语义评审覆盖 153 轮：130 轮未发现问题、21 轮疑点、2 轮因材料超过输入上限未评。按原判据组合后是 111 个场景 checks_passed、20 个 needs_review、1 个确定性失败、1 个未完整评估。疑点不是经人工确认的错误率。

复核发现两类问题：

- 真实数据链路问题：额度确认卡把账号名裁为共同前缀；文章统计把完整三十天序列提前裁成七天且没有补读入口。本次修复复用完整账号名接口，并保留最多三十天序列。
- 需要继续复核的模型或评审问题：代写通知增加未授权恢复承诺、检索结论扩大到整类内容、身份名称串用等；部分评审把比喻或诊断假设当成业务规则，或误读准备阶段的通知影响数量。不能一律算成产品失败，也不能删掉疑点来提高分数。

长会话未评是评审材料组织的覆盖缺口，不是记忆测试失败。需要去除重复的静态评审上下文，同时保留用户原文和工具事实，再校准正反例；不能截断后假装完整评估。

既有发布门禁保持 failed：未完整复核的语义质量，以及短聊输出/延迟和读取调用次数的 P95 尚未达到配置目标。没有放宽阈值，没有用单次正确回复替代长期质量证据。下一轮先收敛数据与证据契约，再做有针对性的行为对照；不继续叠加重复提示词或意图关键词分支。
