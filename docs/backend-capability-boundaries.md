# 后端业务能力与 Agent 适配边界

业务事实由所属后端产生；模型选择能力、理解上下文并解释结果。Python 服务仍负责框架执行、
授权接入、确认绑定、预算、恢复和数据契约校验，不要求它成为零逻辑的HTTP转发器。

## 已核对的职责

| 能力 | 当前归属与结论 |
| --- | --- |
| 文章日统计窗口与窗口内月份小计 | Rust `note_stats::window` 基于同一份日数据生成 `dailyWindow`；Agent 只展示，缺失时保持未知，不自行推算范围或汇总 |
| 全站总量、排名、周/月/年报 | Rust/数据库计算。Agent 不把榜单前N名相加当总量，也不把滚动窗口当整月 |
| 写入政策、原状态、影响范围、版本冲突 | Rust 准备接口和业务事务负责。Agent 保留签名确认、调用绑定及回执一致性检查 |
| 相对禁言小时数 | 当前 Python 转为绝对到期时间，后端校验并绑定到确认版本。这是输入归一化；若收敛到后端时间，应在准备时返回固定到期时刻与规范化意图，确认执行不得重新计时 |
| 本页文章状态计数 | Python 使用标准Counter辅助展示，仅覆盖实际返回页，不是全库统计。可保留；若其他消费者需要同一指标，再由目录接口统一提供 |
| 通知全局与窗口计数 | 后端unread是全局数，Agent分别展示unreadTotal与unreadInWindow；最近100条窗口不是全收件箱，全部未读准备在范围不足时拒绝 |
| 通知筛选与分页 | 当前Agent在后端最近100条窗口内筛选、搜索和分页，未把窗口外记录当作不存在。后续可增加后端筛选与按编号查询以减少传输、拓展覆盖；不以语言性能推断它已是瓶颈 |
| 文章标签名补查 | 公开文章搜索在`tools/notes.py`读取两级标签字典后补充名称。关联投影适合由Rust查询接口返回，避免一次搜索额外读取两份字典；未知标签仍应明确缺失，不能由模型猜测 |
| 单项待办准备和核验 | 当前读取本人完整待办快照，上限200条；Rust负责上限、归属和版本条件写入。单项操作可改为后端按编号返回状态和版本，创建可提供准备结果及写入回执，减少整表往返，仍需校验已批准范围 |
| 后台文章、账号、审核和工作队列分页 | 现役领域工具通过`admin_pages.read_page`把筛选和分页交给Rust；不是在Python中读取全库再切片 |
| 站内信摘要和单封正文 | 后端分别提供recent和按编号读取接口，Agent只校验归属和投影字段，不拉取全信箱后做摘要 |
| 分页完整性、未读总数一致性、回执条数 | 后端提供结果，Agent 的计数用于契约校验和展示，不产生授权或业务状态，不能为了“只调用”移除 |
| 待办日期 | 现役准备工具要求完整ISO日期，日期可解析性在适配层校验，写入政策仍由后端核验。旧辅助入口存在相对词归一化，不据此认定现役模型依赖关键词规划 |
| 后台定时任务 | DBOS提供持久定时与恢复，领域任务调用后端能力；到期等待不持有聊天线程或SSE |
| 上下文、缓存预算、工具编排、RAG排序 | Agent职责。继续使用LangChain、LangGraph和成熟检索库，不为统一语言重新实现一套 |
| 本机服务状态与日志观测 | 运行服务所在层读取基础设施事实，工具不能从当前状态推断历史故障原因 |

## 后续收敛原则

- 新的业务汇总、时间窗口、资格判断或跨记录规则，先完善后端业务接口，再让Agent消费。
- 后端接口应返回明确的覆盖范围、生成时刻、缺失状态和必要的影响摘要，减少全量明细传输。
- 相对时间若改为后端归一化，必须测试准备与批准之间经过时间、版本冲突、重放和时区。
  既有确认固定的绝对时刻不能因迁移而延后，不能在执行时重新计算并破坏签名或幂等。
- 纯展示格式化和安全校验可以留在Python；不能把消除所有计数当作架构目标。
- 确认计划的前后状态与实际请求一致、回执与已批准编号一致，属于调用边界校验。
  后端仍须独立授权和执行事务，不能用Agent检查替代；也不能以“只调用”为由移除这些检查。
- 性能优化以测量为依据：优先减少重复查询、过量数据及多余模型调用。RAG的NumPy/SciPy等
  重计算也不等于逐元素运行Python代码，不仅凭语言名称判断瓶颈。

## 收敛顺序与验证

1. 业务口径错误先修复：统计窗口与月份小计由后端返回，通知区分全局与窗口未读。
2. 通知增加后端筛选、分页及按编号查询；先覆盖窗口外目标、本人归属、稳定排序和
   批量确认范围冻结，再替换Agent窗口筛选。不能把分页首批当作全部未读。
3. 公开文章接口补充明确的标签名称投影，验证搜索不再额外请求两级字典，并保留
   文章可见性、未知标签和检索结果边界。
4. 待办采用按编号读取或准备接口，验证多用户归属、陈旧版本、创建上限、确认后等待
   与重放语义；不把少取数据改成少做校验。
5. 相对期限统一服务器时间时，在准备阶段冻结绝对时刻，批准与重放消费同一个意图。

通知、标签和待办是接口效率与覆盖范围的改进项；本次源码审计没有做CPU剖析，不能把它们
描述为已经证实的CPU瓶颈。`products/blog/read_tools.py`会以领域工具替换部分旧名录工具；
判断线上行为时应沿实际注册与调用路径检查，不能把仍可导入的旧辅助函数都算作现役行为。

这种边界与[Anthropic工具设计建议](https://www.anthropic.com/engineering/writing-tools-for-agents)
中将筛选、分页和范围选择放入工具接口的做法一致。具体归属以数据所有权和事务边界决定，
不是以实现语言或是否含有循环决定。

日统计接口的权威实现见博客仓 `src/routes/note_stats/window.rs`；协议和资源回收见
[聊天流协议](chat-stream-protocol.md)，发布指标见[发布验收](release-acceptance.md)。
