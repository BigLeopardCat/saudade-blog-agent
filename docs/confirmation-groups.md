# 按事务分组的确认卡

确认粒度由领域工具的事务契约决定。同类、相同意图且可原子执行的目标使用一张多选卡；不同业务领域、不同意图或具有独立执行条件的事务使用独立卡片。模型选择工具和目标，不能自行批准或把不同事务拼成一个授权。

目前待办批量删除、文章批量状态与置顶、文章批量标签支持逐项目勾选。每个圆形勾选框是原生 checkbox，支持键盘、全选、部分选择和空选择禁用。正文差异审阅是编辑器自己的采纳交互，不混入业务发布确认。

## 执行约束

- 每个可选单元对应签名清单中的具体操作；存在依赖的操作使用不可拆分的签名单元。
- 界面只提交单元索引，服务端验签后收窄范围。即使全选，也只提交实际展示并勾选的索引；不依靠模型解析选项文本。
- 未选择的项目明确记录为保留，不排入后续执行。执行回执把这个决定交给模型，避免把未选项误判为漏做。
- 每组仅发一次业务请求。Rust 在同一事务中核验所选目标的归属和版本；任一目标冲突就整组回滚。
- 已处理卡片只能重放既有结果。换一组索引不能让旧卡追加写入；需要重新准备新的确认。
- 勾选状态只作为显示偏好保存在账号与会话隔离的缓存中，凭据仍从服务端恢复。旧卡与其他会话的状态不能恢复为新授权。

不同事务仍按当前任务的依赖顺序分别等待确认。取消整项任务会停止后续处理，卡面会明确提示这个范围。签名载荷另受总大小限制，超出范围时应拆成更小的事务组。

## 验证

回归覆盖多选与依赖单元的签名收窄、重复/越界选择拒绝、部分批准后保留未选项、旧卡换选择重放拒绝、文章混合意图拒绝、原子批量回执，以及实际聊天 UI 的勾选、空选、单次提交和跨卡恢复。Rust 公共 PostgreSQL 回归验证后续项冲突时回滚前面已删除的项，以及跨账号目标不能混入本人的事务。
