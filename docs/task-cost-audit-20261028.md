# 单任务成本与缓存审计（2026-10-28）

## 证据范围

冻结线上基线为 d9b4f94：132 场景、148 轮、322 次模型调用。本文分析该批原始数据，
不把修正自动判据当作模型重跑，也不把修改后的单次小样本当作同条件 A/B。
原始生产材料保留在受限评测目录，不提交用户正文或确认凭据。

## 放大点与本批修改

| 任务 | 原始调用 / 输入 token | 发现与修改 |
| --- | --- | --- |
| 后台文章清单 | 4 / 22,046 | 紧凑元数据默认 5 条、最多 10 条，需要额外一轮翻页；默认及上限改为 20，保留完整 JSON 和 7,500 字符护栏 |
| 后台账号清单 | 4 / 20,501 | 同样扩大小型名录分页；不返回密码、邮箱或其他敏感字段 |
| 搜索后按主题解读 | 4 / 27,465 | 检索有布局章节，但文本只展示首个根章节；现在保留最多三处标题、章节 ID、真实偏移和版本，可定位读取正文 |
| 放弃待确认操作 | 两轮 5 / 24,643 | 已验证待办的取消工具直接出现在可用菜单；仍校验身份并撤销原凭据，取消后继续完成当前请求 |
| 多轮闲聊 | 五轮输入合计 4,442 | 单轮已很轻，不能通过填充提示词提高命中率；将稳定账号上下文放在固定前缀，动态页面与摘要仍在最近对话之前 |

公开文章正文列表和含内容的活动分页保持原有小页；只扩大小型名录，避免把正文与账号清单
当成同一体积。排名仍使用现有 BM25/RRF 实现，未增加关键词意图路由。

候选代码的两条真实只读首跑中，文章清单降至 3 次调用 / 15,757 输入，账号清单降至
3 次 / 14,909 输入。新 schema 处于预热阶段，未缓存输入并非都下降；这两条不能证明
费用、延迟或全量通过率全面改善。其余进程内候选探针受代理变量和缺少持久执行账影响，
作为评测环境错误保留，必须通过真实 HTTP 持久化路径另验，不能计作功能通过。

## 服务商缓存口径最小验证

使用同一组合成消息、工具 schema 和 OpenCode 会话标识，顺序运行 auto、auto、none、none、auto：

| 模式 | 服务商归一化输入 | 缓存读取 |
| --- | --- | --- |
| auto 首次 | 2,236 | 0 |
| auto 预热 | 2,236 | 2,176 |
| none | 21 | 0 |
| none 重复 | 21 | 0 |
| auto 再次 | 2,236 | 2,176 |

工具定义和消息在本地请求指纹中一致。由 usage 可推断 none 模式的服务商计量/模板与 auto
不同，但不能据此确认网关内部实现。保留 none 的预算收尾约束；不为缓存比例开放无剩余额度
的工具。考核同时看输入总量、缓存读取、未缓存输入、输出、调用次数和端到端延迟。

## 摘要频率与宿主依赖

部署契约原来每 10 条未摘要消息触发一次。10 月 28 日活跃会话的 18 次请求中实际总结 3 次，
各增加约 3–3.6 秒，输入分别 1,809、670、1,247 tokens。已有覆盖水位，并非每次重读全部历史。
博客侧改为未覆盖正文达到 6,000 字符或达到 20 条消息时触发，计数上限与恢复窗口对齐；
字符计数只是调度代理，不替代完整请求预算。身份隔离、完整前缀、删除屏障和 CAS 保持不变。
摘要变化不会控制已持久化的工具加载状态。
