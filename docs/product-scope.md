# 当前产品范围

Saudade Blog Agent 是博客里的内容与管理助手。核心博客的阅读、写作和后台管理可独立使用。Agent 接入后，用户可在对话中提出任务，由模型理解问题，宿主按权限提供业务事实和执行结果。

| 用户与场景 | 现有做法 | Agent 的候选价值和完成条件 |
| --- | --- | --- |
| 读者知道主题，想找到解释 | 站内搜索、打开候选文章、定位相关段落 | 帮助选文、定位并给出可对照原文的答案。证据不足时说明范围。 |
| 读者手中已有一篇或几篇文章 | 打开正文、记下要点并自行比较 | 归纳已读取内容，区分每篇来源。明确要求全文时，读取覆盖与答案内容分别核对。 |
| 作者需要审阅文字修改 | 在后台编辑、保存草稿和发布 | 在工作副本中审阅建议。采纳、保存和发布各有自己的可见结果。 |
| 管理者在聊天里查询或准备变更 | 打开后台对应页面，查看结果或填表提交 | 减少找页面和重复输入。读取以宿主事实为准，写入需经过确认，并以业务回执核对完成。 |

当前证据支持将有来源的文章查阅作为优先验证场景。后台已有待审汇总和公告表单，简单取数及给定原文的单次写入，应以现有界面最短路径作为基线。复杂组合操作、后台计划、可选模型和存储按对应能力文档使用。候选优先级随实际需求复核。[后台计划](scheduling.md) · [身份与写入](identity-and-permissions.md)

现有回归样本说明功能能否按预期执行。任务真实发生的频率、相比页面的节省时间、最终使用率、用户是否反复回来，以及读者和管理者的优先顺序，仍缺少足够的现场样本。后续用有来源的实际请求记录人工步骤、最终完成情况与等待时间，再据此决定投入。

长期通用协调、跨业务迁移和任务切换的取舍见[ADR 38](adr/adr-0038-general-agent-and-release-priorities.md)。新增领域的技术接线见[领域扩展](product-extensions.md)。
