# 评测与可观测性

[验证命令](#运行入口) · [trace 与指标](#追踪与指标) · [语义判例](#语义评审判例) · [成本口径](#成本与响应目标) · [冻结回归](#冻结回归与采集证据)。发布前如何选择范围见[发布验收](release-acceptance.md)。

## 分层验证

| 层 | 目的 | 依赖 |
| --- | --- | --- |
| 离线回归 | 工具、权限、确认、记忆和预算契约 | 桩或隔离 loopback，无部署凭据 |
| 数据库集成 | 真实事务、锁、恢复和幂等 | CI 临时 PostgreSQL，显式测试 DSN |
| 浏览器集成 | 布局、卡片、图片、输入及暂停接续 | 真实组件、合成接口、禁外网 |
| 真实模型任务 | 语义理解、完成率、用量和时延 | 固定模型、配置、构建和数据集 |
| 部署验收 | 鉴权代理、端到端业务及资源释放 | 经过授权的目标环境 |

离线通过不证明模型理解正确，卡片出现不证明正文真实，准备成功不证明业务写入完成。每层分别报告通过、失败、跳过和未评估。

## 数据集与判据

回归集按完整场景组织，覆盖角色边界、短应答、多轮指代、工具发现、跨领域、写入选择/取消、目标版本变化、断连恢复、摘要后回忆及错误服务。真实故障经归因后加入开发集，独立验收集保持隔离并轮换。

校准和正式评审均支持 `--reasoning-effort none|low|medium|high`；报告记录实际推理开关、输出预留及温度。比较使用相同配置，推理评审也不替代人工复核。

确定性断言检查真实工具、目标、执行账和数据库/浏览器事实。LLM judge 检查语义、虚构规则及表达，须用人工标注集校准。每个场景单独记录确定性结果、缺评轮次和有疑点的轮次。即使确定性失败已计入允许的非关键失败比例，缺失评审或未复核疑点也会阻止 HTTP 验收通过。

模型视觉识别仅供按需诊断，发布回归运行文本用例。宿主图片展示仍需浏览器测试。

声明了标签、分类、留言或设备前置条件的用例，先经宿主接口验证夹具。夹具缺失时先补数据
或在启用该能力的环境里单独跑对应场景。预检失败记为评测错误，不计为模型回答失败。

跨仓检查固定 `.github/host-contract.json` 的公开源码提交，CI 必须检出并运行，不读取维护者的本机博客 checkout。更新契约版本须验证双方接口后提交锁文件。

## 运行入口

```sh
uv run --frozen pytest -q
python -m eval.dataset_audit --out /tmp/dataset-audit.json
python -m eval.native_contracts --help
python -m eval.online_baseline --help
python -m eval.online_judge --help
python -m eval.release_readiness --help
```

线上 HTTP 验收使用 `online_baseline`；隔离写入/回放使用 `native_contracts`，
语料夹具共用 `golden_evaluation`。语义复核只通过 `online_judge` 审评固定报告，
普通离线测试统一由 pytest 收集，不在生产 cron 中串联这些入口。

`native_contracts` 使用真实模型、合成业务 API、临时 SQLite 执行账和内存 checkpoint，
检查确认后的真实夹具状态、取消、重放及显式恢复；不连接生产业务库，不证明 PostgreSQL 耐久性。
可用 `--case` 选核心链路，`--fail-fast` 在首次失败时停止扩量；保留首次 journal、报告及 trace。
`navigation_feedback_*` 经过与生产相同的回执控制入口，核对 checkpoint 重建、错误回执拒绝、
完成/失败/超时/错误路径和重复回执。这些回执是合成观察，真实浏览器交互另由 Playwright CI 验证。

普通用户回复出现“主人”按已接受口径保留原话至 `observations`，不单凭该词判失败。
此观察不证明角色陈述正确；身份与权限、对象、精确交付数据、确认签名、写入次数及回执状态仍独立校验。
其余已接受的轻微语气/措辞观察不新增禁词断言，显式 JSON、校验码及拟写正文的精确要求不放宽。

部分写入后的核对检查 Agent 本轮成功查询的工具证据，不依赖内部 HTTP 次数或列表路径。
两个指定编号可以一次列表读取，也可以分别读取详情；两者均须有直接、无重复的状态证据。
`release_profile.json` 中的调用和延迟目标用于观测。分析个案时保留实际调用数及
临时效率目标，结合成功结果、工具证据、额外模型开销和真实用户等待判断是否需要优化。

语义 judge 使用开发依赖 OpenEvals，由 `eval/semantic_judge.py` 适配当前模型协议。
执行前用 `uv sync --locked` 安装开发依赖，生产服务无需安装 OpenEvals。
业务 rubric、证据投影、引用校验和最终验收仍由项目维护；解析失败、截断或材料缺失
记录为未评估，不自动重试或降级。报告固定 OpenEvals 版本、输出 schema 和推理参数。
评审期间关闭 LangSmith tracing，不额外上传材料；不为评审调用业务工具。

`eval/fixtures/article_claim_grounding.jsonl` 是文章逐项比较和统计范围的合成校准开发集：包含单个表格单元虚构、错误 exactly-once 保证、明确推论、跨月峰值及并列峰值。每个单元按对应来源独立判断，不能用主体正确抵消局部错误，也不能把“未提及”改成“不支持”。显式授权模型调用后可运行：

```sh
uv run --frozen python -m eval.judge_calibration \
  --samples eval/fixtures/article_claim_grounding.jsonl \
  --out /private/state/grounding-calibration --max-output-tokens 1200
```

输出目录必须是新的私有目录；保留首次输出及失败材料，不靠重跑筛选通过。该集合只校准判据，不能当作独立验收集或生产正确率。

`eval/fixtures/source_policy_claims.jsonl` 覆盖对比总结中的排他性断言，以及拒绝回复中的权限错误，
包括先说明正确权限、随后又建议由无权角色代办的情况。
核对时同时复判正确对照和已知误判，权限依据取自该轮冻结的产品事实或工具契约。

语义材料中的 `runtime_preparation_context` 来自同次已准备调用的产品元数据，记录执行策略、触发时间语义和控件默认策略。它不替代 `validated_preparation_facts` 中的服务核实结果，也不证明业务已执行、页面已渲染或通知已经送达。未记录或超过证据上限时保持缺失或未评估，不用当前源码补造历史事实；确认卡正文仍是待审输出。

线上先 POC，后全量，命令和目标见[发布验收](release-acceptance.md)。不得在普通 CI 默认运行线上写入或付费生图；生产材料交给外部 judge 前需脱敏和授权。

## 追踪与指标

每条 trace 关联构建、模型、用户来源、任务、请求及执行阶段，保留工具参数的安全投影、结果状态、错误及退出原因。密钥、签名确认凭据、原始私有图片不写 trace。

录制器在接收输入及事件时过滤诊断副本中的明确凭据字段、Bearer、常见 API key、JWT 和私钥块，
不修改模型输入、工具实参或用户实际收到的回复。`observability.credential_redaction=1` 标记该处理；
工具参数 schema 的字段定义保留，字段实例中的凭据则隐藏。普通姓名、内容和来源坐标仍可能存在，
这不是通用个人信息匿名化；trace 继续使用私有目录、0600 文件和现有保留策略，外传前仍需材料投影与授权。
压缩使用独立的 0600 临时文件并原子发布，保留原始时间戳；压缩失败不会删除源文件或覆盖已有归档。

审核待审列表为空可以由全范围、待审数为零的真实汇总证明；有待审记录时仍需返回列表证据。
明确查询留言发布者时必须查明对应账号，禁言意图的澄清不能替代发布者查询。
此类判据修订只用于新批次，旧报告保持原状。

业务 JSON 通道以 `tools.http_attempt` 记录每次请求尝试，沿用请求 trace 并关联工具 `call_id`/`round`；
与模型工具调用数分别统计。它是通道尝试计数，不证明 TCP 实发包，也不覆盖模型请求或图库原图下载。
事件包含方法、主机、路径和查询的独立 SHA-256 指纹、状态、耗时、安全错误类型，以及原有限额读取器
已经消费的 decoded `response_bytes` 和 `response_complete`；未读完时字节数仅表示部分读取。
失败、超限和读取中取消保留事件，发送前停止不计尝试；不会为观测读完流或保存正文、请求体、查询原文及凭据。
同一路径/查询指纹可定位重复读取，但分页、写后核实等仍须结合工具上下文判断，不能自动视为浪费。

当前 trace 落盘包含 `observability.json_http=1`，声明共享 JSON 通道的观测覆盖；
已有的 trace `schema_version` 同时覆盖无 HTTP 观测的旧构建，不能据它推断覆盖。
`request_metrics.summary/collect` 分别报告 `http_attempts`、`http_retry_attempts`（单次通道调用的
`attempt>1`）、`http_response_bytes`（decoded）、`http_incomplete_attempts` 和
`http_observed_requests`（含已知零次的覆盖请求数）。无标记或不支持的版本保留未知，不能用零填补；
即使旧材料包含个别事件也不推断整轮覆盖。字段缺失或非法时对应总值为 null；
混合分组只有每个请求的相应指标都已知才给总值，`*_sum` 仅保留已观测的有效小计。
前置拒绝或纯聊天的零仅表示该通道零次，不能证明整轮不存在其他 HTTP。

区分首个可见事件、首个正文、端到端时间和人工等待。任务级聚合包含暂停、浏览器和确认接续；当前请求只计增量，摘要及收尾调用也纳入费用。

文章工具在预算呈现后记录 `article_observation`：关联工具调用、结果状态及实际交付的来源范围，
不再次记录正文或查询。`request_metrics.summary.article_usage` 与发布报告的 `article_usage`
列出检索交付量、额外正文量、重复范围字符数、检索后模型调用及补读次数。
按文章、版本、解析器和小节区分坐标；缺失、非法或无法关联的观测保留未知，不从截断文本估算零。
重复读取仅作诊断，不自动判失败；相关性、回答支持度与补读必要性仍由证据标注或语义复核判断。

全文总结的 `article_summary.source_page` 记录实际遍历的同版本文档范围，
`source_delivered` 表示完整原文直接交给主模型，由普通正文观测记录实际交付量；
`completed` 记录派生摘要的完整源覆盖、策略与段数，`incomplete` 保留失败原因。
读量统计区分直接交付与内部合成，避免把同一份原文重复计入两次。
内部 `llm_start/done/error` 沿用用量和延迟聚合，包含每个 refine 步骤；
`article_observation.operation=summary` 的原文交付量为零，表示聊天模型收到派生摘要，
不能据此认为汇总工作流没有读取原文。完整源覆盖和摘要分别于运行时证据、工具结果中核对；
还需通过语义评审检查前中后章节、限制与跨章节关系，不能以 coverage 代替忠实度评估。

完整 usage 同时报告缓存输入、未缓存输入、输出、推理及缺失字段。以服务商口径归一化；不能把十几个字的用户输入等同于实际完整模型输入。缓存命中率按 token 加权，不平均每条请求百分比；实际费用累计服务商回执。

基线 `task_metrics.tasks` 用 `case_ids` 关联场景，保留跨请求的模型调用数、输入、缓存和覆盖率。
`provider_cost_usd` 是服务商回执中的余额扣费，`provider_list_cost_usd` 是标价，
`provider_allowance_usd` 是套餐额度扣减；三者分别报告，套餐余额扣费为0不等于没有消耗。
某字段未覆盖全部调用、有未知请求或任务预算历史不完整时，该合计为null；
原始 `*_sum` 和 `*_seen` 只表示已观测部分，不能用其或预算预留补齐任务总费用。
少量POC或脚本模型只验证接线、分页与判据，不能当作模型意图通过率、正式P95或生产SLA。
短指代展示用例不强迫重复读取：自动判据检查图片格式和禁止行为，跨轮链接来源仍需语义评审。

定点文章问答保留 `max_model_calls` 和 `max_article_body_chars` 的场景目标。
效率观察用例可用 `diagnostic_limits` 显式将这两项设为诊断；实际值、目标及超限记录写入
结果和发布报告，不因此判任务失败。其他用例仍按原断言执行，工具调用约束不能设为诊断。
正文量取来源证据的最大累计范围快照，不重复累计同一快照；缺失或无效证据仍标为未评估，
不能以诊断模式掩盖证据缺口。该指标不代替真实 usage、费用、时延和回答质量。

```sh
python -m eval.daily_metrics --days 7 --json
python -m eval.daily_metrics --days 7 --tasks
python -m eval.daily_metrics --days 7 --json --evaluation-report /private/run/report.json
python -m eval.token_cost_report --days 7
python -m eval.task_metrics --dir /path/to/traces --out /tmp/tasks.json
```

日报默认统计全部服务流量，包含线上评测；`source=production` 表示服务通道，不等于真人流量。
`daily_metrics` 和 `task_metrics` 可重复传入 `--evaluation-report`，按 canonical 报告中的精确请求 ID、构建及捕获摘要生成已知评测与排除视图。顶层总量和总成本保留，未标注流量不推断为真人；原始 trace 和报告不改写。运行服务的健康统计只展示含评测的全部请求范围，不读取私有评测报告。

`TRACE_DIR` 是默认根，CLI 显式目录优先；宿主日志对账通过 `--log-dir`、`--monitor-dir` 显式指定目录。无宿主日志或用量缺失时标记不可用，不补零。

## 比较与发布

固定输入、身份、模型、价格配置和构建做配对比较，报告新增退化、样本数、Wilson 95% 区间及成本/时延变化。小样本不能证明生产 SLA，未显著不同也不等于等效。费用按提供商当时实际价格核算。

HTTP 发布复评逐轮核对冻结 trace 的 SHA-256、服务构建和请求编号。请求证据、HTTP 计时与
trace 三方的编号须一致，且每次请求只计一次。编号缺失的轮次标记为未核验，错配或重复
会使完整性检查失败。只有通过核对的轮次才进入用量、时延及首次动作统计。

目标来自 `eval/release_profile.json`；失败明细和原始报告保留。禁止以修改 matcher、删除失败用例或补录成功标签代替修复。候选流程见[离线改进](offline-improvement.md)。

模型请求的 `request_layout` 记录 SDK 输入指纹，`wire_request` 记录实际 HTTP JSON
和会话路由头的指纹；两者均不保存消息、推理文本或凭据。超过 1 MiB 或不支持的
请求体显式记录 `wire_request_unavailable`，不影响发送，也不用于证明前缀稳定。
缓存诊断优先使用实际 HTTP 的 `wire_request`（包括真实会话头）；仅旧 trace 缺少 wire 事件时回退 SDK 布局并标明来源。显式观测失败计入未观测调用及其消耗，不用 SDK 外观替代实际前缀证据。

## 语义评审判例

普通用户偶尔被称为「主人」仅作为称呼偏差单独记录，不计任务失败；默认称呼规则仍保留并突出提示。
该容忍不覆盖错误角色陈述、权限放开、虚构业务事实或违反用户明确指定的称呼。

简短确认附带不改变含义的轻微语气词（如要求“只需说收到”时回答“收到喵～”）作为
“确认语气观察”保留原话，不计任务失败。此容忍不扩展到逐字复制、代码、JSON、验证码
或其他精确数据交付，也不覆盖额外事实、承诺、追问、无关内容和未经授权的操作。
产品仍优先遵循用户要求；旧冻结判定保留，人工裁定单独记录。

已完成 RAG 或关键词检索但未找到相关证据时，允许说“站内没找到”；同一检索语境下
口语化的“站里没有相关文章”作为范围措辞偏差记录，不仅因此判任务失败。产品提示仍
强调使用“本次站内没找到”，RAG 不代表全站存在性证明。该容忍不覆盖未检索、失败或
不完整检索、仅看目录某页、忽略实际已有相关证据、声称穷尽全站，或推导其他业务事实。
无关近邻候选不等于相关证据。judge 必须在 reason 中以“检索范围措辞观察：”保留原话
及容忍依据；原始回复、工具证据和旧冻结判定均保留，不把容忍当作措辞已修复。
新规则只用于明确采用它的新评审，观察记录与任务通过率分别报告。

## 分组与统计口径

各身份、领域和多轮场景同时报告分组成绩，不能只看总体平均值。
统计单位是完整场景，不把同一会话的多轮当作独立成功样本。
新报告附双侧 Wilson 95% 区间，由 SciPy 的 `binomtest().proportion_ci(method="wilson")`
计算。固定回归集不是生产流量的随机抽样，因此该区间仅描述本批检查，不能据此证明生产
成功率超过某个阈值。零失败也不意味着真实风险为零；证据不足仍是未验证。

Wilson 区间不替代实测通过率，两者一起报告。`quality_gate_statistics` 单列总体与核心
场景的完整场景数、通过率、双侧 Wilson 95% 区间和下界是否达到参考线；这些均用于质量观察。待审和未评估留在完整分母，不能只统计 judge 已通过的样本。
若要声称“长期任务成功率至少95%”，应事先固定独立抽样、判据、样本量和停止条件，
使用代表真实任务分布的样本及预先选择的置信下界门槛；不能测试到下界过线才停止。
双侧95%区间的下界与单侧95%下界不同，不应在看到结果后切换。
同场景重复试验用于观察稳定性，须按任务家族报告，不能把关联轮次和重复用例直接堆成独立样本。

## 成本与响应目标

以下均按**每个用户请求包含的全部模型调用**统计 P95，包括摘要与收尾调用。
输入包含缓存命中部分，输出包含服务商计入的推理用量。用这些指标观察成本和响应变化。运行时预算见[会话与记忆](conversation-memory.md#预算)。
版本 3 起把模型调用次数、token、延迟、缓存/用量覆盖和首轮动作列为观测。超过建议值在
`efficiency_findings` 中报告，缺样本或字段在 `observation_gaps` 中报告。开始流式进度快
不能证明任务快，模型先走另一条合法路径也可以正确完成任务，供应商缺报缓存字段不能证明
功能退化。结合真实分布、任务结果与成本变化决定是否调整实现。
版本 1、2 的冻结报告继续按各自判据复查，历史结果保留。

这些是低并发博客助手的效率目标，不是所有阅读任务的统一容量限制。闲聊以一次模型调用、
单领域查询以三次调用为成本目标；查询输入目标给按需加载后的 schema 和事实保留
20,000 token。时延预算容纳多次模型往返，不通过截断答案降低耗时。
每次冻结候选前固定目标；历史报告不重新标成通过。

时延归因复用 `eval.request_metrics`：分列执行与确认回复的模型调用、首 token 等待、
首 token 后耗时和业务工具耗时。模型调用耗时包括网络和服务端处理，仅凭 TTFT
不能区分排队与预填充。服务商等待不等于 Agent 本地开销；仍报告用户实际总等待，
不通过扣掉服务商时间美化体验。优化优先减少可避免的往返和冗余输入，不为偶发
零缓存命中添加提供商专用路由、填充或重复请求。

| 请求类 | 调用目标 | 输入目标 token | 输出目标 token | HTTP 耗时参考 |
| --- | ---: | ---: | ---: | ---: |
| 闲聊、简短知识、身份说明 | 1 | 5,000 | 400 | 30s |
| 页面操作 | 2 | 11,000 | 500 | 30s |
| 单领域查询 | 3 | 20,000 | 1,200 | 45s |
| 正文解读、查找后阅读、比较 | 5 | 32,000 | 1,600 | 60s |
| 写入准备 | 4 | 24,000 | 1,000 | 50s |
| 取消、修改待确认操作 | 3 | 20,000 | 800 | 35s |
| 多轮记忆与指代 | 4 | 24,000 | 1,600 | 45s |
| 多意图任务 | 8 | 32,768 | 4,000 | 90s |

首次可见事件 P95 ≤1s；页面指令交付 P95 ≤15s；确认卡交付 P95 ≤45s。
页面指令交付仍不代表浏览器执行完成。常用导航接近 2s 是后续体验优化目标，
不能拿一次暖缓存样本宣布达标。复杂任务可以有更长时延，但须显示真实执行进度。

首反馈、首段正文、模型首 token、首次业务工具发起及首次业务结果分别记录。
进度提示不能当作正文或模型首 token；元数据空块不计首 token。
工具参数或推理先于正文到达时，模型首 token 仍不代表用户已看见答复。
模型首 token 带测量覆盖率，非流式调用或旧 trace 缺失时不补零。

首轮正确行动暂以 ≥95% 作为诊断参考。每轮由测试材料明确标注可接受的工具或允许直接答复，
按需加载正确领域也算合理行动；闲聊、无权限拒绝和必要澄清可以不用工具。
调对一个工具同时夹带无关调用不算正确。这个指标只检查最初选择，不代替任务成功率；
缺少标注或当前 trace 不完整时明确未验证。
逐轮选择准确率单独报告；Wilson 区间按完整场景内各轮首选均正确来计算，避免把关联轮次
当作独立样本夸大统计把握。

每类、每项至少 20 个有效样本才报告 P95；小样本只报中位数和最大值，状态为
`unverified`。小批量试水用于发现退化，不能替代全量基线。长文输出等超出本轮
验收范围的需求单列评估，不能混入简短闲聊分母后再调整阈值。
20 条只是报告分位数的最低样本数，不证明尾延迟稳定；正式 SLO 还需持续运行观察。

## 缓存与费用口径

- 优先减少冗余调用、重复读取、工具定义和不必要摘要；不填充 token 换取命中率。
- 分开统计首次调用、同一次请求内前缀完全保留的后续调用、布局变化和无法关联的调用。
  前缀保留包括模型、会话、工具定义、请求选项与完整消息前缀一致。
- 对 `stable_prefix` 另算已知旧输入前缀的复用覆盖率，目标 ≥90%，作为诊断目标。
  分母取上一调用报告的输入量，且不超过本次输入；分子取其被缓存前缀覆盖的部分。
  新工具结果、当前问题和其他新增 token 不进入这个分母；上轮生成内容也不算旧输入。
  **该指标不是整次请求的缓存命中率或费用折扣**，报告仍同时保留总输入的命中率。
  供应商缓存是尽力而为；缓存指标均不单独阻断发布，不能替代成功任务成本。
- 本项目 trace 中的 `input` 已归一化为总输入。若账单把 Input 与 Cache read 分列，
  总输入是两者之和，命中率是 `cache / (uncached + cache)`，不能再除以未缓存 Input。
- 每次对照固定模型、版本、测试集与身份，记录执行顺序和冷暖状态。
  比较总量及每个成功任务的消耗，失败和取消任务的成本也保留。
- 跨峰谷价格时段不直接比较费用；例如 09:00 后的峰值计价不能直接与夜间回归费用相比。
  此时比较总输入、未缓存输入、缓存输入、输出和模型调用次数；需要费用对照时采用同一
  已核实价格表重算，并明确标注为归一化估算，不混同实际扣费。计价时段以当次服务商规则为准。
- OpenCode Go 的套餐额度与按量 API 价格不是同一口径；没有完整单价或实际扣额证据时
  只报告 token，不虚构人民币费用。价格齐备时复用 `eval.token_cost_report`。

Agent 直接把用户原话交给模型，按任务内容交付完整答复和所需来源。
文章 131 回归中的「300 字以内」来自该条测试请求。离线评测识别这类数字要求，
将实际字数及超出情况作为观察。模型输出的 token 预算由运行时资源配置单独管理。

评测按 Markdown 解析后的文本计数。汉字、字母、数字、标点、代码与链接文字均计入。
空白、Markdown 标记和链接目标地址省略。例如 `[原文](https://example.org/article/131)`
计 2 个字符，直接显示的 URL 按其文本计数。

## 冻结回归与采集证据

HTTP 轮次报错且关联 trace 记录客户端断连时，按链路评测错误停止批次；不能据此推断
模型答题错误或供应商根因，也不自动重跑。保留部分回复、消耗和未完成用例。
为收集完整覆盖，full 可显式使用 `--continue-transport-errors`：仅在 trace 已记录
可重试模型传输错误、且没有 HTTP 状态码时继续下一个独立场景；当前场景不重试，
失败轮次的依赖后续轮不发送。连续三次此类错误仍停止；鉴权、额度、限流、供应商
HTTP 错误及评测链路错误继续立即停止。采集策略写入冻结报告，原错误和未知用量保留。
`full_run=true` 仅表示全部场景均被采集，评测错误仍阻止发布，不降低任何质量门槛。

小批量可重复传入 `--case-id` 选择具体用例并保留顺序；该选项不用于 full。
每次运行在私有报告目录保存实际选择的 `suite.jsonl` 及其哈希，不覆盖旧结果。
定向首答验证已知问题。全量用于覆盖广泛的模型链路变更，范围由[发布验收](release-acceptance.md#按改动选择验收范围)决定。数据库、浏览器与部署恢复各有独立证据。

准备阶段只追踪已验证的原状态、收件人和影响范围，并关联框架工具调用 ID。
拟写正文和预期变更仍是待审输出，不作为自身事实依据。缺少准备事实、被截断或关联不上
同次调用的材料不能评成通过。确认凭据不进入这些事实。

模型可见工具结果按 `AGENT_TOOL_RESULT_TOKENS` 的估算 token 预算裁剪（默认 24,000），
文章结果还须保留有效来源与续读游标；整次请求仍受输入预算约束。trace 留存是另一层限制：
运行时普通工具默认保留 8,000 字符，文章读取与能力清单有独立上限，RAG 定位结果完整保留。
具体分档及 `TRACE_TOOL_RESULT_LIMIT` 的覆盖规则见 `utils/trace.py`；评测扩大 trace 留存
不扩大模型可见上下文。审查只能依据实际留存且可关联的材料，证据截断后仍按不足处理。

“已处于目标状态”可作为无需改动的正确结果，但必须有同次准备工具核实的目标和原状态，
不能只凭助手说“已经完成”。贴纸强制用例需由用户明确要求贴纸；公开内容允许等价的
公开读取工具，但文档类型、编号和权限断言保持严格。旧冻结报告不因修订测试集而改分。
试探性操作建议允许先完成明确读取并澄清意图，不能用无条件必调工具断言代替结果验收。
但角色、保护原因和操作资格结论必须有证据；明确资格查询与操作请求由独立用例覆盖。

回归集用于日常修复，独立验收集在候选冻结前不用于调优。入口支持 `--suite` 与
`--dataset-role holdout`，但一个标签不能证明测试集未见过。生产失败先留存原 trace，
人工归因后进入回归集；验收集暴露给调优后应轮换，不能反复重采样挑绿。

```bash
python -m eval.dataset_audit --out /tmp/dataset-audit.json
python -m eval.judge_calibration --dry-run --out /tmp/judge-materials
# 只发送仓内合成材料，不读取或执行业务：
python -m eval.judge_calibration --out /tmp/judge-calibration
# 两批必须使用同一套输入与判据，并保留 trace 摘要：
python -m eval.compare_runs /tmp/before/report.json /tmp/after/report.json \
  --out /tmp/paired-comparison.json
```

judge 校准报告分别列出误报、漏报、调用失败、precision/recall及其区间。
仓内合成样本是校准开发集，不能把修订后在相同样本上通过当作独立准确率验证。
高风险疑点仍由人工结合证据裁决。同任务 A/B 使用完整场景配对，报告新增退化、
精确 McNemar 检验与成本差值的配对重采样区间；没有显著差异不能解释为等效或无退化。
统计实现参考 [SciPy 比例区间](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats._result_classes.BinomTestResult.proportion_ci.html)
和 [SciPy bootstrap](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)。

从固定的 Agent 源码运行，先安装锁定开发依赖。使用独立验收环境中的三类已登录
测试账号，按[身份与写入](identity-and-permissions.md)配置 `SAUDADE_OPERATOR_SESSIONS_FILE`。
`TRACE_DIR` 指向操作员获准读取的该环境 trace 目录，`EVAL_STATE_DIR` 指向已有的私有状态目录。
`AGENT_URL` 指向可访问的内部 Agent，`BLOG_URL` 指向配套宿主，`AGENT_REV` 写完整候选提交。先核对
Agent `/version`、宿主 `/build-info.json` 和两端就绪，再按以下顺序运行。
采集会请求模型。可选的语义评审只接收已授权、经过投影的冻结材料，并使用独立配置。

```bash
umask 077
RUN_DIR="$(mktemp -d "${EVAL_STATE_DIR:?设置私有验收状态目录}/release.XXXXXX")"
PROBE=(
  --host --agent-url "$AGENT_URL" --blog-url "$BLOG_URL" --expected-build "$AGENT_REV"
  --admin-uid "$GOLDEN_ADMIN_UID" --user-uid "$GOLDEN_USER_UID" --zako-uid "$GOLDEN_ZAKO_UID"
)

uv run --frozen python -m eval.online_baseline "${PROBE[@]}" --phase poc \
  --report-dir "$RUN_DIR/poc"

# 确认 POC 无退化后，采集同一候选的完整套件。
uv run --frozen python -m eval.online_baseline "${PROBE[@]}" --phase full \
  --report-dir "$RUN_DIR/full"

uv run --frozen python -m eval.release_readiness "$RUN_DIR/full/report.json" \
  --profile "$RUN_DIR/full/evaluator/release_profile.json" --out "$RUN_DIR/readiness.json"

# 可选语义观察，按需复查内容缺陷
uv run --frozen python -m eval.online_judge --report "$RUN_DIR/full/report.json" \
  --out "$RUN_DIR/semantic"
```

发布判定离线执行，保留采集和评审的退出状态及原报告。已有语义报告时，可通过
`--semantic` 加入同一份发布报告。只调整评估工具且运行时代码相同的候选，可用
`--recheck-frozen` 对冻结 HTTP 报告复算版本 4 功能契约，报告保存捕获时和复算时的
判据哈希。完整运行时版本仍须从包和报告核对。`http_checks_passed` 只覆盖该批
HTTP 任务的读取、准备和证据要求。浏览器执行、批准后结果与生产可靠性需要独立证据。
可用性先以发布后 7 天 ≥99.5% 为试运行目标，真实观察满 30 天后再讨论 99.9%；
当前不能从单机测试推算 SLA。先验证 4 个活跃会话与断连、取消后的资源释放，
再按实际流量提高并发目标，无需为个人博客建设多租户调度平台。
