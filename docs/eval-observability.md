# 评测与可观测性

当前生产使用原生工具运行时。观测需要覆盖整个请求；旧规划器事件只用于历史记录诊断。
维护目标是判断任务是否正确完成、消耗多少，以及失败发生在哪一层。

## 1. 观测口径

生产追踪在请求入口记录 `source=production`、进程启动时固定的代码版本、配置的
模型/服务商和实际运行时类型。评测追踪记录 `source=evaluation` 并写入独立目录。
旧追踪缺少的字段保留 `unknown`，不推测来源或版本。模型字段表示请求配置，
不能证明网关内部最终使用的模型版本。

请求指标按 **来源 × 代码版本 × 模型 × 执行路径** 分组：

- 当前路径为 `native`；历史报告中的 `hybrid`、`graph`、`hybrid_to_graph` 单独分组，不混入当前成绩。
- 请求数、有回复数、结束原因、模型开始/完成事件数、交接原因分别计数。
- `with_reply` 只表示存在正文，不代表任务成功。旧图并非所有模型节点都发开始事件，
  因此不能把开始数减完成数直接解释成失败数。
- 延迟报告有效样本数和 P50；少于 20 个样本不报 P95。评测总耗时含夹具和执行开销。
- token 总量只累加实际测得的字段，同时报告输入、输出、缓存、思考的覆盖调用数。
  缺字段不是零；`reasoning_seen=0` 不能解释成关闭思考。
- 缓存命中率 = 命中 token / **有有效缓存测量的调用的输入 token**。
  无效负数、布尔值、缓存大于输入等数据不进入测量。
- 费用只有在输入、输出、缓存用量完整且提供三个有效单价时才估算。
  当前网关没有可靠价格回执，不内置模型价格。

原生路径记录 `llm_start/llm_done`、按需加载、工具结果种类、预算终止和持久化事件。
确认准备与取消工具只记录工具名、轮次、结果种类；确认令牌及终止工具结果不进入
模型上下文或 trace。事实回执、幂等命中与工具调用是不同事件，不拿调用数冒充完成数。

```bash
# 请求级 JSON；生产目录由应用配置决定
.venv/bin/python -m eval.daily_metrics --days 7 --json

# 简短日报；graph 前缀项仅针对旧图，不能作为混合路径成功率
.venv/bin/python -m eval.daily_metrics --days 7

# 用量与覆盖率；也可用 --dir 指向某次评测的 trace 目录
.venv/bin/python -m eval.token_cost_report --days 7
```

默认日期窗口按最近 N 个有追踪的日期选择，并非严格滚动 N×24 小时。
跨版本效果比较应使用 JSON 分组与相同任务集；简短日报和 token 分项表用于排查，
不直接用于跨版本质量结论。`trace_metrics`、`trace_alert` 和旧日志扫描保留为旧图
诊断，尚不能作为混合运行时的完整异常检测。

## 2. 评测分层

| 层次 | 检查内容 | 执行方式 |
| --- | --- | --- |
| 确定性契约 | 权限、参数、确认绑定、取消、幂等、真实回执、上下文预算 | pytest；CI 必跑，不调用真实模型 |
| 请求结果 | 真实模型能否完成用户任务，是否误操作，是否诚实报告失败 | 小型请求集与 `native_contracts`；按需运行 |
| 持久化与协议集成 | PostgreSQL 跨进程恢复、并发及 SSE/宿主协议 | 定向集成探针；显式运行 |
| 辅助质量复审 | 答案出处、复杂语义、疑似无依据结论 | LLM judge 与人工复审；保留证据，不作为唯一判据 |

不以工具调用序列、旧规划器步骤数或回复关键词作为新架构的主要质量标准。
工具契约测试可以锁住协议；任务级验收应优先核对目标状态、写入次数、签名范围和回执。

连续任务也属于验收范围，不能只登记一条输入和最终正文。
`native_contracts --case mailbox_short_followup` 使用合成信箱与真实模型，依次验证：
先列标题并询问是否读第一封、用户仅答“嗯”后读取该封、再追问事实时复用已有来源。
判据同时检查实际读取编号、未获请求时不读正文、查询不写入，以及复用事实时不重复查询。
`tests/runtime/test_context_contracts.py` 用模型桩证明错目标、无读取却声称完成、重复读取都会失败。

工具激活与历史裁剪、同任务恢复、权限变化、完整预算的边界由确定性行为测试保护。
这条连续场景不代表长对话压缩、所有指代或暂停交互已通过真实模型验收；
新增场景按失败机制归类，先定向小批量，再纳入全量报告，保留首次失败。
普通用户的无称呼偏好闲聊也检查默认称呼，不能把其他角色的称呼混入后仍仅凭
“有正文、无工具”判为通过；明确指定昵称的用例不能替代默认身份行为验收。

### 默认测试环境与维护

默认 pytest 不需要部署配置、模型密钥或数据库。测试启动时隔离应用配置环境变量，
使用明确的测试值，并忽略当前目录的 `.env`。配置读取的对照使用临时文件，不读取开发机
的真实 `.env`。需要不同参数的测试通过夹具显式设置。
测试trace和文件型幂等账使用进程独立的临时目录，退出时清理，不写入生产日志目录。

跨语言源码契约只读取显式的 `SAUDADE_PARENT_REPO`，不自动发现相邻部署仓库。
CI 检出固定公开提交且要求该契约；本地缺少它时，相关测试显示 skipped。
PostgreSQL 集成测试在未提供专用 `SAUDADE_CKPT_TEST_DSN` 时于收集阶段跳过，
不调用 libpq 的默认本机连接。skipped 不是通过，完整 CI 与无外部依赖的本地结果分别报告。

运行时、领域工具、模型协议和外部集成测试分别归入 `tests/runtime/`、`tests/domains/`、
`tests/providers/`、`tests/integration/`。共享夹具和待逐项整理的旧测试保留在根目录。
pytest 原生递归收集，不限制测试只能平铺、只能用顶层函数或不能放数据夹具。

pytest 迁移已完成，一次性转换和对拍脚本及其专用测试已经退役；仍在使用的共享断言
收集器保留行为与接线验证。全局隔离用例在独立 pytest 子进程内验证真实前后生命周期，
不依赖外层测试的执行顺序。测试数量不是删减目标；优先保留安全、状态与协议行为覆盖。

## 3. 当前可运行的任务验收

### 全量前的小规模预检

先检查评测接线，再以同一配置运行少量真实模型任务，不用复跑覆盖首跑失败：

```bash
.venv/bin/python -m eval.native_contracts --fail-fast \
  --case chat --case unread_counts --case favorite_cancel --case favorite_confirm \
  --case navigation_followup --case article_discovery --case oled_display --case admin_denial
```

这八项覆盖聊天、未读聚合、取消、确认与回放、执行后叙述、多轮跳转、主题文章发现、OLED 回执及普通用户越权拒绝。
模型使用当前配置，业务 HTTP、会话存储和设备指令均用隔离夹具，不修改生产业务数据。
确认路径启用生产叙述实现；回退文本仍可正常服务，但不能当作叙述已评估通过。
`planned_samples`、实际采样、未评估与提前停止分别报告；未尝试任务不算通过。
输入、输出、缓存和延迟通过既有 trace 汇总。首个可见事件尚未接入这个进程内驱动，字段保持缺失，不能当零。

通过预检后，还需审查全量用例的身份来源、已退役路径断言、重复前提和缺失领域。
旧 `basic.jsonl` 的总通过率不能直接作为迁移后基线；同一句话在不同身份或历史下是必要对照，不按文本相同就删除。

### 已有验收入口

```bash
# 真实模型 + 假业务 HTTP + 内存 checkpoint + 临时 SQLite 幂等账
.venv/bin/python -m eval.native_contracts

# 独立采样，每次均从空会话开始；失败不被后续成功覆盖
.venv/bin/python -m eval.native_contracts --case navigation_combined --repeat 3

# 聊天与公开读取；真实模型及站点只读数据
CHECKPOINT_DSN= .venv/bin/python eval/run_golden.py \
  --golden eval/golden/hybrid_requests.jsonl --min-pass-rate 1
```

`native_contracts` 复用现有生产事件驱动、身份验签、领域工具和确认执行器，
复用确定性测试的业务 API 夹具。它覆盖：

1. 普通聊天不调业务工具、不写业务数据。
2. 收藏准备固定目标且零写入；取消后旧卡不能执行，待办被清除。
3. 通知准备固定未读编号；确认只写一次，重放不重复写入，新到通知保持未读。
4. 最近收件摘要不含正文；点名读取单封不改已读状态，确认与重放只处理签名编号，新信和发件箱保持不变。
5. 未读聚合只请求一次计数接口，最多两次模型调用，不额外读取信件或通知内容。
6. 仅推荐不跳转；追问、推荐并打开和直接打开产生一条指向正确文章的页面命令，
   可逆页面操作不生成确认卡。推荐链接必须来自夹具文章，并有成功读取的来源。

每项使用独立会话状态，所有业务请求被假接口接管；意外交接旧图直接判失败。
报告保留首跑结果，不通过复跑把失败改成通过。确认令牌只留在评测进程内存中。
`--case` 可多次指定；`--repeat` 对每个选中任务独立采样。报告逐次保留回复、命令、
确认数量、错误、模型和工具次数、预算计量及 trace。汇总列出采样、已评估与通过数量，
夹具缺失读取明确标为未评估；未评估和失败都返回非零退出码。每轮进入生产 RequestControl，
使用共享预算和截止时间。导航夹具使用真实本地词法检索和合成正文，不调用外部 embedding；
业务搜索虽使用 POST，仍属读取，不计业务写入。
已接入既有夜间脚本作为独立必过项；没有新增计划任务。旧 golden 与原生任务验收分别记录，
历史架构断言需迁移后才能解释为当前任务质量。
报告位于 `eval/report/_smoke_native_contracts_<run>/report.json`，追踪通过既有
`golden_traces/<run>/` 机制隔离；手工报告按现有保留登记保留，避免被当作冻结基线。

这组验收不证明生产 HTTP 入口、数据库持久化、真实业务 API 或所有措辞均可靠。
导航通过只证明页面命令与目标正确，不证明浏览器已到达，也不自动判定整段叙述事实准确。
当前 `elapsed_s` 是进程内请求耗时，尚无首个可见事件时间；不足 20 个时延样本不报告 P95。
PostgreSQL 验证使用 `eval/native_checkpoint_probe.py`，生产版本与就绪状态看
`/version`、`/health`。

## 4. 旧 golden 与辅助判官

旧 `basic.jsonl` 继续覆盖未迁移领域。部分断言依赖旧规划器的内部路径，不能直接用
其总通过率评判混合运行时。迁移一个领域时，增加该领域的结果验收，再退役不适用的路径断言。

旧 runner 会对首跑失败的回归用例复跑；报告中的 `failed_first_run`、`flaked_ids` 必须
单列阅读。复跑后的门禁通过不能称为首跑成功率或稳定性。未评估、跳过、身份或语料前提
不成立要从已评估分母中分开报告，不能算通过。

`llm_judge` 的出处复审依赖可用证据和模型判断；截断工具结果、语料漂移、判官失败都
可能影响结论。它用于挑出需要复核的案例，不能替代业务状态断言，也不作为自动放宽门禁的依据。

## 5. 下一步

- 扩大本人读取、否定/歧义、修改目标、失败恢复及剩余写领域的任务覆盖。
- 将混合路径异常检测接入现有巡检；需要覆盖无回执、未知结果和异常交接。
- 用同一任务集多次采样，分别报告首跑成功率、错误类型、模型调用量和延迟分布。
- 迁移完成后删除旧规划器专用诊断及相应断言，避免长期维护两套成绩口径。

当前规模继续使用已有 trace、报告和 CI；没有为这次修正另建观测服务或评测框架。
