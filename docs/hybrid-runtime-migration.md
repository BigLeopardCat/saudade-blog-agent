## 目标边界

- 模型负责答复、选择相关工具、读取结果后决定下一步；只有复杂任务才进入有界循环。
- 代码负责身份与权限、确认、参数校验、幂等和真实执行回执。
- 工具按领域注册和加载。普通对话无需工具，站内任务只见到当前相关的工具 schema。
- 会话、任务和回执使用结构化状态；提示词只携带本轮必要的事实。
- 业务操作 ID 独立于编排引擎。复用现有鉴权、确认签名、PostgreSQL 幂等账和回执协议。
- 旧图只承担尚未迁移的领域；每个领域迁完即删除对应规划模板和纠偏分支。

## 身份与能力事实

`agent/runtime/context.py` 从已验签且 uid 有效的身份、现有角色权限表和贴纸渲染清单
生成本轮能力数据；角色不明或身份未经验证时不声明私有权限。用户消息不能修改这份数据。
工具菜单按需加载，尚未迁移的授权操作仍可委托旧路径，当前本人读取菜单不代表账号总权限。
能力数据随每轮请求重建，不依赖被裁剪的聊天历史；权限执行仍由工具与后端核验。
生产请求 trace 同时记录身份角色和来源，以便区分身份传递与模型理解问题。

## 管理员只读领域

`admin_reports` 按需提供服务器状态、服务健康、用户统计、文章流量与分期报表五件工具。
只向已验签、uid 有效且具有 `admin.console` 权限的身份显示。调用前再次核对 scope，
并拒绝请求账号与验签身份不一致的情况；本机运维读取同样受这个边界保护。
本人读取与管理员读取共用按 scope 校验，读取循环拒绝实际写入工具。

工具复用现有 I/O、2400 字符报表上限与后端鉴权，原生菜单使用简短说明。
用户统计缺少有效聚合值时返回不可用；渲染器缺字段保持未知，不再补成零值。
旧图默认入口和未迁移任务的交接尚在使用，因此暂时保留旧报表模板，随旧图退役一并删除。

未知工具名或重复加载领域时，运行时返回标准错误工具消息与当前可用名称，
在既有轮次预算内允许模型修正，不立即交接旧规划器。非法协议结构仍拒绝处理。
trace 分别记录工具请求、协议错误与实际调用；错误反馈不冒充已执行的工具结果。
每次实际读取前再次检查次数与结果预算，同批加载的新工具也受限；
循环预算耗尽返回停止答复，观测报告以 `budget_stops` 与 `budget_stop_reasons` 单独记账。

`admin_work_queue` 只向已验签管理员提供额度申请与个人待办两件工具，调用前复核身份绑定和权限。

## 已实现：普通对话单次调用

`agent/runtime/hybrid.py` 负责会话准入、上下文和持久化，`agent/runtime/session.py` 负责
单次请求的模型与工具循环，`agent/runtime/read_tools.py` 登记只读域与权限边界。
小上下文路径包含人格与短边界说明、至多两轮近期对话、
三个公开文章只读工具、站点资料及收藏/通知/信箱领域的按需加载入口，以及一个过渡期
交接工具。普通聊天一次调用；文章问题允许模型在有界循环中自主检索、读正文和答复；
站点资料加载后提供作者信息、社交链接和功能结构图三个公开工具。本人领域入口只向
**已验签、具备 `read.own` 权限且 uid 有效**的身份显示，各领域只加载对应读取工具；
读取不依赖写入持久化。具备写权限和稳定持久化时，同一领域再提供确认准备工具。
未读计数直接通过初始聚合工具查询。实际调用前再次检查授权，工具白名单启动时核对 scope 声明。
选择交接时保留原始输入与授权状态；恢复标记在取得会话锁后重新读取。
直接路径最多使用 4 次读取、4 轮追加调用；单条工具结果最多 8000 字符，
累计工具结果最多 16000 字符。入场内容超过 24000 字符时交接旧图；
进入读取循环后，读取次数、结果量或上下文预算耗尽则直接结束本轮，不重新进入旧规划器。
收藏、本人通知与收件箱已读的确认、修改及取消进入共享事务生命周期；其余领域确认和未完成任务仍进入旧图。配置图持久化时，直接路径从
checkpoint 中读取最近的用户与助手对话；答复先同步写回同一张图的 checkpoint，
然后才发送给客户端。待处理的 checkpoint 状态交给旧图，写入失败则不发送未持久化
答复。外壳提供同步状态接口，异步状态操作在线程中调用同步 PostgreSQL saver，供
恢复判定和丢弃末轮复用。收到停止信号后，在模型调用返回时终止，不再继续读取或保存
本轮答复；不会中断已发出的上游模型请求。同步和 SSE 生产者共用同一 arm 接口。

直接答复目前缓冲完整模型回复后发送，尚未实现 token 级流式输出。

## 会话生命周期与写事务

`agent/runtime/turns.py` 提供公共取消信号和会话串行化。PostgreSQL 的会话咨询锁覆盖
读取状态、模型/工具调用、checkpoint 写入整个轮次；使用独立自动提交连接，避免
占满 checkpoint 池或在模型调用期间持有数据库事务。等待有时限且可取消。丢弃末轮
和删除 checkpoint 使用同一把锁；锁在异常、断连或进程退出时释放。

`agent/domains/favorites/transactions.py` 接管已签名的 `favorite_add` / `favorite_remove`
单件确认操作，复核当前身份、权限、会话、过期时间和具体参数，再调用既有收藏工具。
它直接复用 PostgreSQL 幂等账，以签名中的操作 ID 认领并持久化执行结果；重复确认
返回已存结果，遗留 intent 如实报告结果未知。成功必须有工具给出的目标与变更事实，
纯成功文本不能生成完成回执。执行不调用 LLM，也不构造旧规划器计划。

收藏准备由 `agent/domains/favorites/preparation.py` 承担。模型通过小型原生工具选择
`add` / `remove` 和文章 id；代码复核身份、会话、权限、真实文章与本人收藏状态，
再复用现有签名和确认文案生成卡片。状态已达成时零写入、无确认卡，不产生执行回执。
卡片的标题来自 API 数据；本轮浏览器页面信息以结构化元数据传入，仅用于定位候选。
确认令牌不进入模型上下文或工具 trace。准备结果先写入 checkpoint，随后发送既有
`__CONFIRM__` / `__PENDING__` 与单份正文；用户点击确认后进入已有事务执行器。

收藏工具仅在已验签、可写本人数据、稳定会话且已挂 checkpointer 时按需提供。
缺少这些条件时保留旧路径。收藏、通知与收件箱已读待办的自然语言修改、取消及跨领域替换已由共享生命周期处理，其他领域仍走旧待办流程。

## 待确认收藏的修改与取消

`agent/runtime/pending.py` 只恢复已验签、绑定当前用户与会话的收藏提议。
模型选择取消或给出新的动作、文章 id；不会通过中文关键词表判断意图。修改先核对新目标，
成功后撤销旧卡并准备新卡；新目标读取失败时保留原待办。普通聊天和读取也保留原卡，不重复发卡。

撤销复用 PostgreSQL 幂等账，以原操作 ID 留下无写入的撤销结果。旧卡即使仍在有效期内、
换进程或重放，也不能执行。已经执行或结果未知的操作不能被声明为取消。签名中的 `executor`
固定收藏执行入口，切换默认运行时不会绕过账本；旧版令牌保持原协议，不恢复到新待办工具。
确认控制帧在 checkpoint 落库之后发送，令牌不进入模型上下文或工具 trace。

SSE 通过既有 `__PENDING__` 通道增加 `event=cancelled`，并在新卡之前发送旧卡取消事件。
宿主后端的 `src/routes/chat/pending.rs` 按用户、会话、task_id、jti 关闭对应行，同一流内顺序处理
取消与新卡登记。需同时升级宿主协议；收藏写入的撤销依据仍是 agent 持久化账本。

本轮真实模型配合 HTTP/身份夹具，取消、自然语言放弃、更换文章、否定取消、闲聊 **5/5** 通过，
11 次模型调用、24,253 输入 token，无旧图交接、无收藏写入。这组小样本不代表全领域成本分位数。
生产 PostgreSQL 使用 8 个独立进程验证取消、替换、旧卡拒绝、新卡执行与重放；仅 1 次模拟工具
执行、0 次真实站点写入，探针会话和幂等记录已清理。报告位于
`eval/report/_smoke_pending_favorite_20261022/{model,postgres}.json`。

## 恢复状态与会话删除

checkpoint保留可恢复状态，聊天记录与trace分别承担用户历史和诊断职责。
原生消息状态按约5400 tokens选取完整轮次；当前轮次过大时完整保留该轮，后续轮次继续裁剪。
模型输入仍使用较小的1800 tokens历史预算。工具调用与结果成对选取，签名确认与幂等账不从消息裁剪中推断。

依赖固定为`langgraph-checkpoint-postgres 3.2.0`及其兼容的checkpoint包，使用框架原生
[`prune(..., strategy="keep_latest")`](https://reference.langchain.com/python/langgraph.checkpoint.postgres/PostgresSaver/prune)
移除旧恢复点，保留最新checkpoint引用的blob和待提交写入。生产hybrid会话在共享会话锁内裁剪；
旧图交接也裁剪历史恢复点，但旧图消息状态尚未统一到原生预算。产品不提供旧checkpoint时间回溯功能。
裁剪失败记录异常并保留已有恢复状态，不把维护失败改报成业务操作失败。

博客会话删除与`agent_checkpoint_cleanup`任务在同一事务提交，账号删除复用相同入口。
短租约与数据库行锁分配任务，HTTP交付在事务外执行；仅收到`deleted=true`才删除任务。
失败按退避继续重试，进程重启不丢任务，旧尝试不能确认更新尝试的任务。

Agent在会话锁内登记持久删除屏障，再清理checkpoint；迟到或排队请求不能重建已删除线程。
屏障只保存线程编号及删除时间，至少保留30天，由既有夜间保留任务清理。
业务库五张聊天派生表由会话外键级联删除，数据库拒绝迟到回复、摘要或回执成为孤儿记录。
迁移`0012`新增清理队列，`0013`增加并验证外键；存量异常会阻止迁移，不自动删除历史数据。

单轮丢弃仍使用现有同步钩子；本批裁剪其旧快照，不宣称已统一丢弃、确认卡撤销和摘要重建。
幂等账与诊断trace沿用独立保留规则，不因删除会话伪造已执行操作的审计历史。

### 确认卡撤销与回放入口

原生领域的单次确认卡只提供“确认执行”和“取消操作”；需求修改通过聊天提交。
卡面沿用已读取并签名的目标、具体变更和不可逆说明。所有原生领域共用此展示，
移除领域各自拼接按钮说明的重复代码；本批静态登记仅增加这两个按钮显示文案及新模块零计数。

`POST /api/chat/confirmation/cancel` 校验登录态和会话归属，再携服务间身份断言请求
Agent 的 `/confirmation/cancel`。Agent 验签后，在与执行相同的会话锁内登记撤销账，
只清理匹配操作编号的待办；重复撤销可重放，旧卡撤销不清理新卡，已开始或完成的操作不报告已取消。
此入口不创建用户发言、不扣聊天轮、不调用模型，也不调用业务写工具。

博客对签名中声明原生 executor 的确认请求交由 Agent 验签和持久回放，不再抢先核销。
executor 只作转发提示，未验签不能授权；Agent 对未知的已声明执行入口拒绝执行。
卡片按服务端提供的回放能力保存重取入口，确认中刷新或失败后可再次提交同一操作，
由原账返回结果或明确的不确定状态，不重新调用业务写工具。

前端只在取得服务端撤销成功回执后显示“已撤销”；网络或持久化失败保留重试入口。
另发消息收起旧卡只显示“卡片已收起”，不谎称服务端已撤销。新 API 与传输处理分别落在独立模块，
server.py 和博客 chat.rs 都缩小；没有增加规划协议、关键词判断或提示词纠偏。

边界：旧 planner 卡片保留原核销机制，按钮撤销会明确拒绝；本批不宣称其具备原生回放能力。
回放仍受确认令牌有效期约束，长期结果查询、跨设备卡片重建以及旧审批退役继续推进。
