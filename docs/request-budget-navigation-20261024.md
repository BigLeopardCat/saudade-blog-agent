# 请求预算与跳转追问修复

## 生产问题与复现

生产会话的“推荐一篇文章带我过去”查询了置顶和文章清单，但没有发送跳转指令。
`navigate_page` 原说明把推荐一律描述为返回链接；页面操作还藏在资料加载入口中。
后续“带我过去呀”对应模型输入历史为零：上一轮两份工具观察约 2,575 字符，
加上用户与助手消息超出 1,800 历史 token 预算，旧裁剪把整个最近轮次丢弃。
这是工具发现与历史选择问题，不能归因为用户目标不明或笼统的模型能力不足。

当时闲聊调用的缓存读取为 3,328 tokens，总输入约 3,404–3,530；缓存命中正常。
领域加载后菜单变化时出现过零缓存，单条 trace 不能证明全部缓存失效原因。

## 完整请求预算

复用 LangChain `count_tokens_approximately` 和标准 `BaseCallbackHandler`，
一个 RequestControl 下的原生模型、旧图和摘要共享 RequestBudget。
原生循环明确预占，模型回调识别同一次原生调用以避免重复计量；旧图及摘要由回调预占。
配置中的工具回调约束旧图工具，原生循环在整批调用前核对预算并避免回调重复扣量。

默认策略：

| 预算 | 上限 |
| --- | ---: |
| 单次上下文（估计输入 + 输出预留） | 16,384 tokens |
| 整个请求的累计输入与输出 | 32,768 tokens |
| 模型调用 | 8 次 |
| 工具尝试（含领域加载、未知工具及失败） | 8 次 |
| 原生单次输出预留 | 实际模型输出上限，缺省 768 tokens |

消息估算包括结构化 tool_calls 参数，工具 schema 使用框架工具估算口径；
旧图结构化输出 schema 也计入。图片按每张 2,048 tokens 保守估算，不把 base64 当作文本 token。
输出、schema、历史和新工具结果均参与下一次预检，不再将 content 字符数冒充完整请求预算。
既有字符和结果字数限制仍保留为额外保护；移除 HybridArm 的旧字符交接入口须与存储分支统一集成。

服务商返回真实 usage 后结算；缺失字段保留估计/预留，不能填零。
缓存 token 仍属于输入用量，不从上下文与任务 token 总数中扣除。
失败调用保留预占，因为无法证明服务商没有处理。预算用尽后不能通过切换模型引擎重置。
估算并非精确 tokenizer 或金额上限，单次实际计量超出估算时阻止下一次调用，不能撤销已发生消耗。

原生已有工具尝试后不再整轮回退旧图。读取观察通过正常会话保存路径保留，
避免交接丢失结果又重新查询；已有浏览器回执继续保留。尚未进行任何 I/O 的交接仍受共享请求预算约束。

## 历史与轻量页面工具

先在原有预算内保留用户/助手对话，再用余量携带完整的工具调用/结果对，
避免一轮大结果挤掉推荐链接与用户目标。身份/权限过滤在两类选择之前完成。
没有扩大历史 token 上限，也没有增加新的记忆模型或语义关键词路由。

从已经过授权的 site 目录前置 `navigate_page` 与 `set_page_appearance` 两件小工具；
资料读取仍按需加载。直接工具顺序固定，不因不同 worker 的哈希顺序改变菜单。
历史页面动作不触发整个资料领域自动恢复，避免不必要的菜单膨胀与缓存前缀变化。
工具执行时继续核验身份及权限；只推荐不会自动跳转，明确要求打开才发送页面命令。
浏览器命令是已下发事实，不代表浏览器已经回报完成。

## 状态注入边界

保留可信身份、权限与渲染能力，以及作为数据的页面、待确认操作、摘要和历史来源。
本批不扩大系统提示词，不复制工具 schema 到文本能力清单，也不修改全局人设。
动态数据已经位于系统指令之后；将页面数据移至稳定历史之后的布局优化随会话存储分支集成。
尚未解决所有管理员均被称为作者的身份语义，也未开始全域提示词与模型质量验收。

## 真实模型验证边界

只读回放使用真实模型及当前公开目录；页面命令在本地收集，未发送到浏览器，未写业务数据。
第一次回放证实历史修复让追问正确解析为 `/article/19`，但组合请求仍未跳转。
前置页面工具后再次验证组合请求：5 次模型调用、21,899 输入输出 tokens、12.73 秒，
已生成一条文章跳转指令。仅推荐样本未生成跳转。
这些是有限样本，不能当作稳定成功率、P95、推荐事实准确率或浏览器实际完成验收。
证据目录：`eval/report/_smoke_navigation_20261024/`；上线后的真实入口验证另行记录。

上线后的宿主 SSE 入口验收中，仅推荐和后续“带我过去呀”通过；
“猫咪推荐一篇文章带我过去”未生成跳转，回复再次询问是否打开，**仍未通过**。
三次请求分别为 3 / 2 / 3 次模型调用、13,000 / 9,801 / 13,219 输入输出 tokens，
耗时 6.10 / 2.99 / 5.15 秒；推理 token 为零。自建会话和回执均已清理，没有执行浏览器命令。
这与之前单次只读回放的成功并存，说明组合任务尚不稳定，不能据此称为已修复。
已将四类导航任务接入 `eval.native_contracts`，支持独立重复采样并保留全部失败。

## 固定任务基线与未采纳的说明改写

固定身份为验签普通账号，真实模型为配置的 `deepseek-v4.1-flash`；
业务目录、搜索、正文与 checkpoint 均使用独立夹具，本地检索使用真实词法实现。
这与生产管理员的大工具菜单不同，结果单独记录，不能混算生产成功率。

| 任务 | 当前主线，每项 2 次 | 候选导航说明改写，每项 2 次 |
| --- | ---: | ---: |
| 仅推荐不打开 | 2/2 | 2/2 |
| 推荐后追问跳转 | 2/2 | 2/2 |
| 推荐并打开 | 1/2 | 0/2 |
| 直接打开链接 | 2/2 | 2/2 |

主线基线共 10 个请求、30 次模型调用，输入 106,942 / 输出 1,595 tokens；
输入缓存命中率 88.3%，请求耗时 P50 为 5.4 秒。样本不足，不报告 P95 或稳定成功率。
组合任务失败时已读取文章正文，却又询问是否打开；通过样本需 5 次调用、19,211 tokens、12.09 秒。
候选改写将说明换为明确“已请求则直接调用、无需再问”的中文契约，未得到改善，已撤回。
没有新增关键词路由、结果强制跳转或第二个纠偏模型。

首次夹具预跑只支持目录，检索路径出现 404；那轮不作为意图能力基线。
补齐替代读取路径并验证后重跑，两轮正式报告分别为
`_smoke_native_contracts_20261024_065916`、`_smoke_native_contracts_20261024_070114`。
它们证明动作契约的残留问题，并未自动验收全部叙述；已有命令的样本仍出现过“已经打开”
与“浏览器未回报完成”混说。下一步需审查统一的原生执行指令及事实叙述边界，不能靠重试掩盖失败。

## 原生指令收敛

会话存储 PR 合并后，原生输入组装从 HybridArm 移入 `agent/runtime/prompt.py`。
以通用的执行、澄清、确认和回执规则替代各领域的操作叙述，工具能力继续由 schema 描述。
移除“其他已授权操作交给旧引擎”的过时指示；可信角色保留，管理员权限不直接证明作者身份。
动态上下文布局、权限、签名、预算和执行账机制保持既有契约。

真实模型在合成业务接口上完成聊天、收藏取消、通知确认重放、未读聚合、信件读取与重放
五类任务，共 13 次请求，任务动作断言全部通过。导航再次独立采样仍为 7/8，
组合请求为 1/2；另一次选择先询问偏好而未执行，不能声称指令改写已稳定解决问题。
出现过先发跳转指令、回复却说“已经打开”的情况，命令下发与完成回报的叙述仍需验收。
评测夹具已补公开分类，避免合法分类读取被误记为模型失败。
报告：`_smoke_native_contracts_20261024_072135` 与 `_smoke_native_contracts_20261024_072431`。
