# 会话、上下文与缓存

## 状态来源

Conversation 保存记忆，Task 保存执行与预算，Request 管理连接和取消。模型循环使用 LangChain；持久会话、暂停和恢复使用 LangGraph PostgreSQL saver、interrupt 和 Command。Session 只提供当前节点工作视图，核心任务字段来自框架 state。

宿主保存用户可见的原始聊天记录，Agent 保存来源匹配的运行记忆。宿主历史仅用于初始化或显式补读；不能每轮覆盖已有 checkpoint。账号、角色、会话坐标必须匹配，未知来源不能按当前身份补盖。删除会话会清理关联状态并设置删除屏障。

会话所有者由已验签的 UID 确定，保存在框架原生 checkpoint 的 `metadata.user_id` 中；`conv_{id}` 线程标识不随角色变化。存储入口统一检查所有者和会话坐标，覆盖读取、历史状态、恢复、确认、撤销、更新及删除；请求体和调用方 metadata 不能覆盖所有权。首次写入与后续修改共用现有会话锁，跨用户请求在读取结果或执行操作前拒绝。缺少所有者元数据的状态明确拒绝，不能从消息正文推断或由首个访问者认领。

角色变化不改变会话所有权。模型历史继续按来源与当前权限过滤；旧角色的暂停任务和确认卡不能直接恢复执行，新请求按当前角色检查工具权限。宿主的归属查询和限定目标的签名清理授权仍须保留；数据库维护命令使用独立的运维权限，不通过用户接口绕过校验。

`history_scope`、`summary_scope`、`memory_actor` 是来源元数据；摘要、工具文本和浏览器页面均不能修改权限。当前不自动提取跨会话长期偏好。文章知识由业务原文和 RAG 提供，不由聊天摘要替代。

## 模型请求布局

系统指令与基础能力保持稳定，页面观察、会话摘要和当前任务作为带来源的数据传递。摘要不进入系统权限指令，也不伪装成用户刚刚说过的话。已激活工具域按首次加载顺序保存在会话 checkpoint，任务暂停和恢复使用同一份结构化状态。压缩对话本身不清工具域，无容量压力时加载只追加，不轮换菜单尾部。

激活记录绑定账号、角色和会话，重新构建时只解析当前授权目录；身份变化失效，删除会话一并清理，丢弃轮次只移除该轮首次激活的域。schema 与当前任务本身超出容量时，在框架调用边界释放闲置工具域，保留当前批次需要的域与全部发现入口；被释放的域仍可重新加载。暂停与确认接续不重整菜单，真实额度耗尽不会因此重置。只有旧历史过长时交给既有压缩流程，不以历史增长为由卸载工具。单个域或受保护批次仍无法容纳时返回明确的未加载结果，并回滚本次工具集调整；已读取事实保留。

`tool_menu_rebalanced` 记录容量原因、释放域及保留域；正常追加和恢复保持原顺序。工具域状态是模型可见能力的选择，不是授权凭据，实际执行仍按当前身份校验。

普通聊天只常驻文章检索/阅读与浏览器操作工具；账号目录、未读概览和任务挂起通过各自领域按需加载。首次使用需要一次工具发现，已加载定义仍按会话规则继承，不按每条消息重置。

模型可见重 schema 使用有界工作集，独立于本地完整工具目录。`AGENT_TOOL_SCHEMA_TOKENS` 默认4096，是追加领域 schema 按框架估算的软目标，不包含固定工具与发现目录；完整输入预算仍包含全部工具、消息与输出预留。固定前缀不会挤占动态工作集，常用领域不因固定目录较大而逐轮卸载、再加载。任务中保留已请求领域及当前批次；需要多域时可以超过软目标，仍受完整输入预算约束。新任务优先继承预算内最近加载的领域，保留原有顺序；单个追加领域超过目标也会释放。任务恢复保留 checkpoint 中的菜单。释放不删除历史事实或执行权限，当前任务仍可重新发现领域；可信目录中的读取继续由独立授权检查决定。

完整请求预算包含消息、工具定义、调用参数和输出预留。历史优先追加，在容量需要时以摘要覆盖一段最旧的完整轮次；不会每轮用小滑动窗口重排开头。压缩后前缀发生变化是预期成本，应分别统计压缩调用、首次新前缀和后续重用。

会话提交保存框架消息顺序、并行调用分组、完整可见工具结果及服务商重放字段；不把轮次重建成工具节选。页面和时间数据随所属请求保存为历史数据，新请求的数据只附在新消息。签名确认凭据留在操作状态，图片字节转为引用；权限变化仍按来源身份过滤整个轮次。摘要失败后的应急裁剪只改变本次模型视图，不删除 checkpoint 中的原文；持久压缩和存储保留上限分别由现有流程管理。

压缩触发和目标分别由 `AGENT_COMPACTION_TRIGGER`、`AGENT_COMPACTION_TARGET` 控制。保留当前任务、补充要求和来源信息。摘要失败时保留原文并标明应急视图缺口；不能把不完整节选说成全文，也不能因模型预算删除宿主原始记录。

## 预算

配置默认值以 `config/settings.py` 为准，部署样例见[环境模板](../.env.example)。

| 配置 | 含义 |
| --- | --- |
| `AGENT_CONTEXT_TOKENS` | 端点实际模型窗口，包含输出预留 |
| `AGENT_INPUT_TOKENS` | 单次调用的完整工作输入预算 |
| `AGENT_TASK_TOKENS` | 全任务累计用量，含缓存输入、摘要和接续 |
| `AGENT_MODEL_CALLS`、`AGENT_TOOL_CALLS` | 同一任务的调用上限 |
| `AGENT_TOOL_SCHEMA_TOKENS` | 追加领域 schema 的工作集软目标，不含固定工具与发现目录；当前任务必要领域可超过 |
| `AGENT_TASK_SECONDS` | 累计活动执行时间，不含人工等待 |
| `AGENT_OUTPUT_TOKENS`、`AGENT_SUMMARY_OUTPUT_TOKENS` | 对话和摘要输出预留 |
| `AGENT_EXTENDED_OUTPUT_TOKENS`、`AGENT_OUTPUT_MATERIAL_THRESHOLD` | 当前任务材料较大时的可选输出扩展；不改变输入和任务硬上限 |

端点窗口很大不意味着每次请求都应填满。任务预算是防止失控的上限，费用目标由[发布指标](release-acceptance.md)单独定义。

输出扩展只根据当前用户要求、补充和工具材料估算，不把旧历史、系统提示或工具 schema
算作本任务材料；确认说明沿用基础额度。完整规则见[生成预算](agent-architecture.md#生成预算)。

模型请求经过框架的有限重试：最多一次、固定等待两秒，仅接受可重试的 429/5xx，
或明确尚未产生模型输出的超时；配额耗尽不重试。服务商要求等待超过两秒或剩余期限不足时
直接返回失败。重试、摘要和接续都计入同一任务预算，不增加业务写入重放权限。

用量在调用前持久预留，返回实际 usage 后结算；未知结果保留预留。暂停、确认和浏览器接续沿用任务用量，新 HTTP 请求只统计本次增量。不能把历史累计量再次加入本次账单。

## 缓存口径

服务商缓存依赖实际序列化请求前缀，不是应用可保证命中的 KV 服务。保持提示、工具顺序和历史前缀稳定，避免插入当前时钟、随机 ID 或无关状态。恢复 checkpoint 会再次向模型发请求；不代表复用提供商内部推理进程。

若服务商把 `input` 记为未缓存输入，则完整输入为 `input + cache_read`，命中率为 `cache_read / 完整输入`；若它返回的 input 已含缓存，则不能再相加。追踪应保留原始字段和归一化结果，缺失 usage 不按零处理。

## 长文与图片

历史列表提供有界预览，完整消息按 ID 和游标补读。当前图片使用标准多模态内容块；提交轮次只保存图片引用及哈希，不把 base64 回灌历史。模型需要时通过 `get_conversation_image` 在会话归属、固定来源、哈希和下载上限内重读。

确认卡发布前的空答复或畸形协议答复最多重答一次，沿用已读取事实、原确认卡和任务预算；
重答阶段不执行新工具。再次失败保留待确认提示，供应商截断或过滤不重试。

准备操作、撤销和执行回执都是有范围的事实：`awaiting_confirmation` 不表示已写入，撤销一项操作也不证明目标实体不存在。需要当前业务状态时，调用实际查询工具。

框架行为参见 [LangChain short-term memory](https://docs.langchain.com/oss/python/langchain/short-term-memory)。本项目边界由 `tests/runtime/` 及记忆、缓存、恢复回归验证。
