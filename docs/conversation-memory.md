# 会话记忆与图片上下文

会话记忆继续使用标准 LangChain 消息与 LangGraph saver。没有新增数据库表、向量记忆、
额外摘要模型或后台任务平台。待确认卡和写入执行账独立保存，不以摘要恢复授权。

博客宿主已持久保存历史来源，按完整增量批次比较保存摘要实际覆盖水位。
宿主未提供有效来源和摘要覆盖批次时，继续主任务并保留旧摘要。

## 本轮修正

| 场景 | 之前 | 当前行为 |
|---|---|---|
| 合法图片请求 | base64 被当作普通字符，可能阻断本轮及下一轮 | 文本字符与视觉 token 分别计量；历史不回灌图片编码 |
| 长中文输入后追问 | 最近一轮超过常规窗口时可能整轮消失 | 优先保留最近完整问答；超出可用预算时保留显式节选 |
| 图片历史计量 | 裁剪与请求预算使用不同的每图估算 | 共用框架估算，并先为当前输入、输出和工具 schema 预留 |
| 空 checkpoint | 只因挂了 saver 就忽略宿主历史 | 锁内接纳有来源的历史；已有 checkpoint、丢弃和删除不触发重新导入 |
| 权限变化与摘要 | 过滤 checkpoint 后仍注入无来源摘要 | 自动注入须核验原始用户、会话和角色；缺少来源时拒绝 |

常规历史窗口与 checkpoint 上限仍取自 `agent/runtime/memory.py`。
最近完整问答可使用较大的 checkpoint 窗口，代价是少带更早轮次。
最近问答本身超过该窗口时，节选回落到常规历史预算，同时尽量保留用户原文；不把扩大的
窗口全部花在无法完整呈现的旧答复上，避免多轮工具调用反复携带大段节选。
第一轮模型调用还要为实际工具目录、当前附件和输出预留，并同时服从本轮请求的
剩余总额度；历史不能仅因为模型上下文尚有空间就挤占已消耗的任务额度。工具调用进行中不再裁剪消息，
以免破坏调用和返回配对；预算耗尽时沿用现有停止行为。

节选不是摘要，不保证覆盖中间细节。`get_chat_history` 先按消息 ID 向前定位，列表最多
每条 300 字；指定 `message_id` 后每片最多 2,000 个 Unicode 字符，使用 `content_offset`
继续或定位到所需段落。返回 `contentOffset`、`contentLength`、`nextContentOffset`，正文保留
换行、缩进和代码。末片仍可能标记 `contentTruncated=true`，因为该片缺少前文；
`nextContentOffset=null` 才表示读至末尾。偏移不是 UTF-8 字节数，不能拼接不同消息。
记录已删除或无法读取时如实告知；不能把没读到的中间片段说成已读。普通读取中断后重读。
通用历史层用 `memory_excerpt` 标记节选，博客在当前请求附件中说明可用的补读入口；
不把工具使用说明写成历史助手说过的话，也不改变稳定 system 前缀。

## 宿主来源契约

聊天请求增加可选的 `history_scope` 和 `summary_scope`，分别描述历史列表和摘要的
**生成来源**，不授予任何权限：

```json
{
  "conversation_id": 42,
  "history_scope": {"user_id": 7, "role": "user", "conversation_id": 42},
  "summary_scope": {"user_id": 7, "role": "user", "conversation_id": 42}
}
```

三个值必须与本轮验签身份和会话匹配。角色升级、降级都重新划定自动注入边界。
宿主应在产生记录时保存来源；混合角色的列表只能发送来源一致的可访问部分。
旧摘要应从仍可访问的数据重建，**不能在读取旧记录时补上当前角色冒充来源**。

宿主新写入的历史和摘要携带已保存来源；旧来源未知的记录保留可查看，但不自动导入模型。
缺少来源的旧请求仍可使用当前输入和已有原生 checkpoint，不按账号当前角色补造旧来源。
摘要任务接收经同一来源边界验证的独立增量批次和旧摘要，不能复用最近对话窗口代替
尚未覆盖的完整原文；协议及宿主要求见下节。

这是自动上下文的来源边界，不改变用户通过宿主查看自己聊天记录的权限；
显式调用已有聊天历史工具仍遵循后端现有读取政策。
老 checkpoint 没有 actor 标记的消息继续按原有兼容契约接续，无法追溯补造来源。

宿主历史先作为请求附件携带，运行时在会话锁和删除屏障检查之后判断是否首次初始化。
只在完成轮次时一起提交；失败或取消不落半轮数据。空消息列表不代表从未初始化，
因此丢弃最后一轮后不会从宿主重新导入。

## 摘要批次与覆盖水位

摘要是主任务完成后的可选缓存维护，共享同一请求的截止时间和剩余额度。
主任务失败或取消时不生成；剩余模型次数、token 或上下文不足时跳过，不改旧摘要及水位。
模型生成失败、空输出、非正常结束、拒绝或带未处理工具调用时也不产生新水位。

Agent 的 `runtime/summary_policy.py` 统一决定触发时机：未覆盖完整原文达到 20 条消息或
6,000 字符才尝试总结，确认请求不调度。宿主不决定频率，也不能通过旧 `needs_summary`
提示强制或禁止总结。字符数用于调度，完整模型请求仍受 token 和时间预算约束。

支持新协议的宿主每轮提供有界、未覆盖的完整前缀：

```json
{
  "history_scope": {"user_id": 7, "role": "user", "conversation_id": 42},
  "summary": "先前摘要",
  "summary_scope": {"user_id": 7, "role": "user", "conversation_id": 42},
  "summary_batch": {
    "base_id": 120,
    "messages": [
      {"id": 123, "role": "user", "content": "完整原文"},
      {"id": 126, "role": "assistant", "content": "完整回复"}
    ]
  }
}
```

`base_id` 是旧摘要实际覆盖的消息 ID。首次摘要使用 0 且旧摘要必须为空；已有基准必须有
来源匹配的旧摘要。`messages` 是同一会话中基准之后**最早、连续且完整的消息前缀**，
由宿主按 ID 升序查询，最多 60 条。全局 ID 可以有间隔；Agent 校验严格递增及超出基准，
但仅凭 ID 无法核实宿主是否漏查了同会话记录，完整前缀由宿主查询保障。

摘要输入保留每条完整原文，不再只截取最近 20 条或每条前 600 字。
若整个批次超过剩余额度，保留原水位；宿主下次可提供更小的完整前缀，不能截断单条正文
后将其登记为已经覆盖。大于单次模型能力的消息需要独立处理并明确覆盖语义。

HTTP 成功返回 `new_summary` 文本及 `summary_coverage: {base_id, through_id}`。
SSE 的 `summary` 事件对新协议返回 `{text, base_id, through_id}` 对象，仅在请求提供合法批次
时产生；宿主须在启用 `summary_batch` 前支持该格式。`through_id` 为真正送入摘要模型的
批次最后一条 ID，可能早于当前用户请求，不能用当前消息 ID 代替。

宿主保存必须比较当前旧水位是否仍等于 `base_id`，匹配时才一起保存文本与 `through_id`；
基准过时则丢弃更新并重新读取，不能让并发分支覆盖遗漏内容。
历史保留策略也必须考虑尚未摘要的范围；硬上限删除造成的缺口应明确记录。

宿主已在 [Saudade-Blog #93](https://github.com/BigLeopardCat/Saudade-Blog/pull/93) 接入本契约：
迁移 0018 保存来源，读取最早未覆盖完整前缀，按来源、旧水位、旧摘要和数据库版本做条件更新。
丢弃轮次在短事务内清理宿主历史、更新摘要版本；迟到摘要不能重新保存已删除范围。
宿主以 60 条和正文合计 12,000 字符限制批次规模，首条自身超长仍保持完整，最终由 Agent
校验完整模型请求预算；不能保证超过单次模型能力的独立长消息可自动推进。
清理只涉及同来源已覆盖记录，来源未知的旧历史仍可查看，不改写为当前角色。
完整代码契约固定在 `.github/host-contract.json`，生产状态以两仓实际发布版本为准。
旧协议请求继续完成主任务并保留原摘要。

## 图片生命周期

1. 当前轮使用标准图片内容块，base64 仅作为模型传输格式。问题文字放在图片块之前，
   多张图片保持用户上传顺序。当前网关在图片先于问题、配合完整系统上下文时出现色彩误识别，
   因而统一此排列，不修改原图或按内容猜测答案。沿用现有输入张数及字节限制。
2. 完成轮次保存用户文字、内容哈希引用和本轮真实答复，不额外调用模型生成描述。
   已有图片分析作为历史回答保留；未实际看到的细节不会被编造成图片描述。
3. 后续默认只回放这些引用和文字。仅对含已授权图片引用的会话开放图片回看领域，
   由模型选择是否调用 `get_conversation_image`，没有关键词路由。
4. 回看复用宿主既有 `/api/chat/history`，以当前验签用户的短期令牌访问固定宿主地址。
   后端再次检查账号状态与会话归属；Agent 核对会话、引用哈希和单调游标，限制下载大小、
   查询页数和单张图片长度。无法读取时要求重发，不把丢图说成已经看过。
5. Chat Completions 的工具消息仅支持文本；传输给模型的是文本工具回执加临时多模态
   用户消息。临时附件不进入完成轮次；trace 及历史工具观察只保留文字和引用。

图片编号不是公开链接或访问凭据。回看工具拒绝任意 URL、未知引用、更换账号或会话。
当前实现最多检查既有历史窗口的三页，不保证所有年代的原图均可恢复；宿主删除或窗口
预算排除的图片也可能不可用。哈希针对原始传输字符串；不能把重编码后的图片当成同一引用。

旧 checkpoint 的 inline 图片在读取时压缩为引用，下次完成保存写入新表示。
这不等于清除了数据库所有旧快照；既有 PostgreSQL checkpoint 裁剪策略继续生效。
原图仍由宿主既有图片存储管理，本 PR 不复制媒体库，也不需要对象存储迁移。

## 验证边界

`tests/runtime/test_memory_boundaries.py` 使用真实原生循环和 `InMemorySaver` 验证接续、角色隔离、
长文本、图片计量、丢弃及删除；`tests/test_conversation_images.py` 使用可控 HTTP 和模型
验证回看、越权拒绝、游标与下载上限、取消、正文和 trace 不含图片编码。
完整离线套件强制使用 `.github/host-contract.json` 固定的公开宿主 checkout。
离线回归使用可控模型验证数据能否到达、读取是否完整及预算边界，不代表真实模型会主动
选择正确工具或始终依据事实作答。生产发布探活和这些结果不能代替真实任务质量验收。
`tests/runtime/test_history_recovery.py` 使用真实框架运行时和目录，验证跨运行时重建后的长文尾部补读，
以及历史、本人留言、时间三来源读取中部分失败仍能保留其余结果。


部署此职责调整时先更新 Agent，再更新宿主。新 Agent 可读取旧宿主按阈值发送的批次；
新宿主不再发送触发标志，回退 Agent 时也须恢复兼容的宿主协议。此调整不更换存储、
来源隔离、摘要覆盖水位或 CAS 保存规则。
