# 会话记忆

Agent 的 LangGraph checkpoint 是执行上下文的唯一持久化来源。博客保存原始聊天记录，用于界面展示、显式历史检索和首次导入；不维护第二套实时摘要。工具授权、确认凭据和业务执行账不由摘要决定。

持久任务的历史、摘要替换及任务状态由父图提交节点一起更新，普通完成、审批接续和浏览器恢复
不再依赖 HTTP 结束后的维护保存。提交节点失败时使用框架断点重试，复用已完成模型结果；
确认后模型调用失败仍保留业务回执和可恢复任务，旧确认重放不能清除该任务。

## 上下文生命周期

1. 新请求先验证身份，在会话锁和删除屏障内读取 checkpoint。
2. 仅首次初始化时导入来源匹配的宿主历史。空消息列表与从未初始化是不同状态；丢弃最后一轮不会触发重新导入。
3. 正常任务先按来源过滤完整已提交消息，再追加本轮输入；不因最近一轮较长而在摘要前裁剪。完整预算同时计算系统指令、消息、工具定义、工具参数和输出预留。本轮动态事实合入当前用户消息尾部，不插进历史问答，也不写入完成轮次。
4. 已完成历史达到 `COMPACTION_TOKENS`（当前 5,400 估算 token），或当前完整请求空间不足时，在新任务第一次模型调用前使用 LangChain `SummarizationMiddleware` 压缩较早的完整轮次，保留近期完整问答及工具调用/结果配对。
5. 摘要与被覆盖消息的替换结果随本轮结果原子提交。暂停后从子图恢复已完成的压缩，不重复生成摘要；确认和浏览器回执接续不重新压缩本任务。

摘要调用共享任务模型次数、token 总额和当前 HTTP 的绝对截止时间，不启用独立重试。空白、拒绝、截断、未完成工具调用、超长输出或预算不足都保留原文。失败不登记虚假覆盖范围；必要时按完整请求预算缩小本次视图，记录 `memory.emergency_trim`。视图替换通过框架 `before_model` 消息更新保存到任务 checkpoint，后续工具轮和暂停恢复沿用同一视图，不重新带回被省略的长正文；会话已提交原文不受本次视图裁剪影响。

5,400 仅是压缩触发值，不是模型视图或数据库上限。`FALLBACK_HISTORY_TOKENS`（当前 1,800）用于首次导入和超出完整请求预算时的长文本节选。checkpoint 保留完整轮次，存储保留策略独立按 1 MiB 序列化正文或 256 轮管理；只有达到存储上限才淘汰最旧完整轮次，并保存明确的未摘要提示。最新一轮始终完整保留，宿主原始记录不删除。摘要短暂失败不能因为 checkpoint 超过模型窗口而阻止本轮提交。

## 来源隔离

宿主提供的 `history_scope`、`summary_scope` 必须与本轮验签用户、角色、会话全部匹配。来源在记录产生时保存，读取时不能补造。来源未知的旧宿主记录可在本人历史界面查看，但不自动导入。

```json
{"history_scope":{"user_id":7,"role":"user","conversation_id":42}}
```

运行时产生的轮次和摘要携带 `memory_actor`。缺少轮次来源的 checkpoint 不自动进入模型，也不按本轮身份补盖来源。角色或账号变化后，其他来源的派生上下文不再自动注入；工具消息还要重新核验当前读取权限。摘要仅保留目标、澄清、偏好和未完成事项，区分助手陈述与工具事实，不保留身份权限或授权凭据。

## 请求与任务预算

Conversation 保存会话记忆；Task 保存可恢复执行坐标并累计用量；HTTP Request 管理当前连接、取消信号与截止时间。人工确认或浏览器等待不占用已结束 HTTP 的时间预算，接续请求有新的截止时间，但沿用原任务的 token、模型及工具调用上限。

确认执行后若进入浏览器等待，保留标准框架 interrupt 和当前任务坐标；仅在收到浏览器回报并完成后续处理后保存完整轮次。轮次仅由父图提交节点保存；浏览器等待不进入提交节点，受控维护也不能结束活动任务。已执行写入的事实与独立执行账保留，浏览器回报不授予后续写入权限；下一项写入仍须单独确认。

核心任务字段由框架 `ExecutionState` 持有，Session 只保留当前节点的工作视图。每次模型节点前后从框架 state 刷新，终结结果直接从 state 生成，不维护第二套独立属性和序列化器。标准工具 `Command` 的状态更新不会被旧 Session 值覆盖；新任务显式清空旧效果，接续控制只消费一次。详见 [ADR-0029](adr/adr-0029-framework-task-state.md)。

`agent_task_usage` 在独立 checkpoint 数据库保存任务来源和累计用量。模型网络调用前持久化预留，收到 usage 后再结算；未知用量保守保留预留。该记录独立于可能被取消、回滚或重放的模型节点，避免进程退出后重置消耗。会话锁串行化同一任务的更新，删除会话同步清理用量。普通暂停、浏览器回执和确认接续走同一条预算绑定路径。

新请求统计只计本次增量，任务统计包含所有接续；不能把恢复的历史用量再次加进本次费用。缺少用量记录的旧未完成任务不会按零消耗恢复，需要重新发起；已完成会话原文保留。

旧宿主的 `chat_summary` 只作为带来源的归档资料，在首次初始化时导入一次。它不再接受新摘要写回，也不驱动聊天原文删除。此表可能包含已删除原文的唯一摘要，因此不会为清理旧代码而删除用户资料。

## 长文与图片

历史工具 `get_chat_history` 先按消息 ID 定位；列表每条最多 300 字，指定 `message_id` 后每片最多 2,000 个 Unicode 字符，可用 `content_offset` 继续读取。`nextContentOffset=null` 表示到末尾；节选不能冒充已读全文。显式历史检索遵循宿主读取授权。

当前图片采用标准多模态内容块，文字问题在图片之前。完成轮次只保留文字、图片哈希引用和真实答复，不回灌 base64，也不额外生成图片描述。需要重读时由模型选择 `get_conversation_image`；固定宿主、会话归属、引用哈希、游标和下载上限共同约束访问。图片工具回执和临时多模态附件不会进入长期正文或 trace。

## 数据与部署

宿主原文保留不再依赖模型摘要成功；用户删除仍清理相应记录。checkpoint 的存储保留策略独立于提示词压缩，不允许通过压缩恢复已删除会话。

本次接口调整先发布 Agent，再发布博客。两仓共同删除 `summary_batch`、`new_summary`、`summary_coverage` 和私有 summary SSE；不维护旧摘要写回协议。公开宿主契约固定在 `.github/host-contract.json`。

## 验证

- `test_framework_compaction.py`：真实标准 Agent 与 saver 的压缩、原子提交、失败保留、来源隔离及取消恢复。
- `test_context_lifecycle.py`：长轮次摘要前保全、摘要失败仍提交、未知来源拒绝、存储保留和跨请求预算耗尽。
- `test_task_state_authority.py`：同批多个 Command、跨节点状态保全、跨任务清空、恢复时旧投影不覆盖 state，以及提交数据冻结。
- `test_task_inputs_pg.py`：显式测试 DSN 下的 PostgreSQL 跨连接用量恢复及删除；默认离线测试不连接部署数据库。
- `test_cache_window.py`：90 轮短对话，检查只在实际压缩时改变早期消息前缀。
- `test_history_recovery.py`、`test_memory_boundaries.py`：长文补读、图片预算、删除屏障及跨来源读取。
- 博客 `chat_context_tests.rs`：只读导入、来源隔离、删除与归档失效的真实 PostgreSQL 事务。

离线桩验证数据链路和边界，不代替真实模型任务验收。线上评测必须覆盖跨压缩事实回忆，并同时记录摘要 token、首个可见事件、首个正文和端到端延迟。

框架接口参见 [LangChain short-term memory](https://docs.langchain.com/oss/python/langchain/short-term-memory) 与 [SummarizationMiddleware](https://docs.langchain.com/oss/python/langchain/middleware/built-in#summarization)。

准备确认和撤销也作为历史工具事实保留：准备结果明确为 `awaiting_confirmation`，不表示执行成功；确认凭据和待执行计划只留在受控状态中，不进入历史模型文本。历史读取复用领域登记检查当前身份权限，按钮撤销与状态清理在同一提交内记下事实，重复点击不追加重复记录。

撤销回执的范围为该次操作：`status=cancelled`、`scope=operation`、`executed=false`，业务当前状态为 `not_observed`。聊天撤销和按钮撤销使用同一事实投影；它不证明目标标签、文章或收藏在站内不存在。模型需要回答当前状态时，应读取对应业务工具，并保留分页、筛选与时点范围。摘要同样不得把“没有执行”改写为“实体不存在”。

审批等待期间的新文本属于原任务反馈。框架审批节点先撤销旧签名，持久保存反馈及操作未执行的事实，再恢复同一 Agent。当前工具响应标记为未执行；已提交的历史保留原预览及后续撤销事实，不改写过去。没有临时隔离 Agent、状态复制或历史提升路径。详见 [ADR-0032](adr/adr-0032-approval-feedback.md)。
