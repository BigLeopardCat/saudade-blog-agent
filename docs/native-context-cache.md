# 原生请求的上下文与缓存前缀

原生运行时使用上游模型提供的缓存统计，不在应用中缓存模型答案或工具结果。
`agent/runtime/session.py` 和 `agent/products/blog/prompt.py` 负责保持可复用输入的顺序。

## 工具目录

每轮请求的工具目录依次包含初始工具、全部已授权领域的加载器、已加载的领域工具。
运行时没有委托旧引擎的工具或配置回退。
新加载的工具追加到末尾，不删除加载器，也不把新工具插到既有定义之前。

普通工具循环接近请求 token、上下文、模型调用、工具调用或结果容量上限时，
如果剩余预算仍容纳已取得的事实和答复，就执行一次禁止调用工具的收尾调用。
完整定义与至少128token输出仍可放入时保留目录，使用标准`tool_choice="none"`；
只有完整目录确实放不下时才撤下定义。
该调用继续使用同一份请求预算，输出上限按剩余额度向下调整，不扩大限额、不丢弃事实，也不重做查询。
模型需要说明未完成部分；如果连收尾调用也放不下，仍停止处理。阶段切换记录为
`native.finalizing`，包含`tools_retained`，前端显示整理结果进度。

首次输入仍采用框架的完整保守估算。后续请求只有在同一模型实例、工具定义、已有消息
前缀均一致时，才以服务商已报告的输入用量为基数，再估算追加消息（含工具参数和推理回放）。
改变模型、目录或历史任一部分，以及缺少有效usage时，回到完整估算；锚点只在当前请求中使用。
这复用服务商实际计量，不另写tokenizer，也不按缓存折扣缩小请求预算。

保留的加载器支持幂等调用：重复加载返回已加载状态，不重复加载或执行业务工具。
重复调用仍计入请求工具预算，避免通过加载器绕过调用上限。

目录只包含当前请求有权使用的领域。权限、身份或待确认状态变化可以改变目录，
不能为了保持前缀相同而向模型暴露其他角色的工具。

工具激活状态独立保存，不从保留下来的历史观察推导。已完成任务将领域激活顺序连同
验签账号、角色和会话绑定保存在会话 checkpoint 的 `tool_state` 中。新任务只在绑定相同
时继承，并从当前授权目录重建定义；历史裁剪、摘要更新不增删已激活领域。
旧 checkpoint 缺少该字段时从基础目录开始，由模型正常按需加载，不扫描旧消息补状态。

继承是可选优化：如果完整继承目录会挤占已选对话、当前输入或输出预留空间，新任务
开始时整体退回基础目录，记录 `native.tool_menu_reset(reason=budget)`。
不增加领域数量、TTL 或关键词路由配置；本轮新加载仍受统一请求预算约束。
同一任务继续只恢复子图的 `loaded` 状态，保持原顺序，不执行跨轮继承或预算卸载。
决策和兼容边界见 [ADR-0026](adr/adr-0026-tool-activation-lifecycle.md)。

## 消息顺序

模型消息依次为：

1. 固定系统指令、渲染与按需加载能力，随后才是当前验签身份与权限。
2. 从验签身份派生的当前账号编号，作为独立消息保持固定位置。
3. 经过身份、权限和历史预算过滤的较早会话消息，含成对的来源工具观察；随后才是当前页面、
   待确认状态和经来源校验的有界历史摘要。
4. 最近一轮完整问答与当前用户请求，保持连续，避免动态数据隔开提议与简短回答。

每轮变化的数据放在较早历史之后、最近一轮之前。改变页面、摘要或待确认目标时，
同一权限下的系统和较早历史仍可保持相同；最近一轮优先保持对话连续，当前用户请求位于末尾。
页面附件和当前时间、额度、宿主记录不写入长期会话消息，确认凭据也不进入模型输入。
当前账号编号仅用于识别本人，不进入共享系统前缀或长期记忆；它从服务端验签身份生成。
页面、宿主记录和摘要仍是低信任数据，不能用来覆盖身份或授权。
宿主记录由 `agent/api/host_context.py` 有界投影，作为数据附件置于最近一轮问答之前；
它们不参与权限判断、确认授权或执行结算。

历史裁剪、权限变更、按需加载和新任务的预算回退仍可能改变前缀；
历史裁剪不再联动改变工具集合，该布局不保证跨轮完整请求一致。
保留加载器会增加已加载阶段的少量 schema 输入，换取目录前段稳定，
没有增加初始请求的工具数量，也没有预先平铺全部业务工具。

停止后继续恢复框架保存的消息和领域顺序；任务标识、继续控制和确认凭据不进入模型文本。
恢复重新核验当前权限，不为命中缓存保留已经失效的能力。已提交的工具观察复用原调用 ID，
未提交读取可能重试，真实缓存收益仍按服务商 usage 计量。

## 验证口径

`tests/runtime/test_native_cache_layout.py` 捕获实际原生循环绑定的工具定义和发出的模型消息，
验证连续加载时定义只追加、重复加载不报错且仍计数、页面变化后的历史顺序，以及降权隔离。
它还通过真实会话存储接续两轮请求，确认页面附件不会残留在历史中。

`tests/runtime/test_tool_state_lifecycle.py` 验证历史工具观察消失后目录和激活顺序仍保留，
观察不会反向激活工具，以及同任务恢复的请求一致性、读取不重做、身份隔离、目录撤权和
预算回退。测试使用标准 Agent 与内存 checkpoint，不依赖模型密钥或服务器配置。

这些离线测试证明请求布局，不证明上游缓存命中、任务质量或实际费用下降。
服务商的缓存保留、路由及最小缓存单位由服务商决定。
后续线上评测应使用 `llm_done` 的实际 `input`、`output`、`cache_read`，
区分首轮与热请求；缺少 `cache_read` 表示未测得，不能补成零。
请求级聚合沿用 `eval/request_metrics.py`，不新增另一套成本统计。
固定行为说明合并重复条款，保持服务端授权、准备确认、事实出处与短应答连续性；
不为提高命中率保留冗余历史，也不扩大窗口。评估同时看输入量、未缓存输入、调用次数
与任务结果；修改固定提示词后的首次请求不能与旧提示词热缓存直接比较。

DeepSeek适配器在补齐推理回放后，对最终SDK消息、工具目录与会话亲和记录`model.request_layout`
指纹，不记录对应原文或凭据。结合`budget.reserved.estimate_basis`，可以区分请求布局变化、
预算估算和服务商实际缓存统计，不能把相同指纹直接当作命中。
这组指纹覆盖 SDK 请求参数，不等于已捕获 HTTP 请求体或上游内部缓存键；
取消时缺少最终 usage，也不能用重试请求的命中率替代被取消调用自身的统计。

## 网关会话路由

OpenCode 的 `x-opencode-session` 按已验签账号、当前角色与会话编号生成稳定摘要，
同一会话的主循环、摘要任务与执行结果叙述共用；跨账号、角色或会话分别生成。
没有可信坐标的独立调用使用临时标识。该标识只提供路由亲和性，不承担权限或结果缓存。
客户端使用自己的 User-Agent，避免通用 SDK 名称。

这与 [OpenCode Go 的客户端契约](https://opencode.ai/docs/go/#where-can-i-use-it) 一致。
稳定前缀和路由不保证缓存命中；网关可能调整上游，应根据真实 usage 验证收益。
离线回归验证真实 SDK HTTP 请求头、跨轮重建及并发任务的上下文隔离。

## 工具状态解耦的小批量验证（2026-10-28）

使用当前 OpenCode DeepSeek、合成信箱与隔离 checkpoint，未执行生产业务写入。
信箱连续任务通过：先列标题，用户只答“嗯”后读取第一封，再追问取件码时复用来源；
三轮分别使用 3、2、1 次模型调用，加载后至后续轮次的实际工具目录指纹一致。

另一次普通用户闲聊虽然有正文且没有调用工具，却误用管理员称呼。
人工复核将其记为失败，并加强已有闲聊判据；未重跑覆盖首次失败，人设未在本批修改。
因此本批是 1 项任务通过、1 项失败，不能称为完整质量验收通过。

全部四次请求、七次模型调用均取得 usage，总输入 25,164、缓存读取 20,096、
未缓存输入 5,068，聚合命中约 79.86%。这包含首次冷请求，无相同任务的改造前对照，
不据此宣称费用下降或缓存优化完成。

## 公共能力与身份数据的顺序

固定贴纸渲染能力和工具加载方式排在 caller 与 permissions 之前，账号读取的规则属于固定
系统指令。跨角色因此可以共享更长的系统前段，当前角色和授权事实仍逐次核验。
账号编号继续放在本轮数据附件中，不进入公共系统前缀。

本轮离线对照中，超级管理员、用户和杂鱼三种身份的系统公共前缀从1081字符增至1326字符
（框架保守估算约728→891token）。这只证明消息布局变化；工具定义、网关路由和缓存持久化
仍会影响实际命中，不能将字符增长直接换算为命中率或费用收益。DeepSeek缓存为尽力而为的
前缀复用，见[服务商说明](https://api-docs.deepseek.com/guides/kv_cache/)。OpenCode Go的实际收益
继续以响应usage衡量。上一轮79.37%的全量成绩仍归属于当时版本。

一次具体取消请求的链路审计与单变量验证见
[DeepSeek 打断与缓存审计](deepseek-cancel-cache-audit-20261028.md)。
