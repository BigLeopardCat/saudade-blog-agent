# 原生请求的上下文与缓存前缀

原生运行时使用上游模型提供的缓存统计，不在应用中缓存模型答案或工具结果。
`agent/runtime/session.py` 和 `agent/products/blog/prompt.py` 负责保持可复用输入的顺序。

## 工具目录

每轮请求的工具目录依次包含初始工具、全部已授权领域的加载器、已加载的领域工具。
运行时没有委托旧引擎的工具或配置回退。
新加载的工具追加到末尾，不删除加载器，也不把新工具插到既有定义之前。

普通工具循环接近请求 token、上下文、模型调用、工具调用或结果容量上限时，
如果剩余预算仍容纳已取得的事实和答复，就撤下工具定义，执行一次不带工具的收尾调用。
该调用继续使用同一份请求预算，输出上限按剩余额度向下调整，不扩大限额、不丢弃事实，也不重做查询。
模型需要说明未完成部分；如果连收尾调用也放不下，仍停止处理。阶段切换记录为
`native.finalizing`，前端显示整理结果进度。撤下 schema 会改变最后一次请求的缓存前缀，
这部分以实际输入用量和完成结果判断，不以维持缓存占比为目标。

保留的加载器支持幂等调用：重复加载返回已加载状态，不重复加载或执行业务工具。
重复调用仍计入请求工具预算，避免通过加载器绕过调用上限。

目录只包含当前请求有权使用的领域。权限、身份或待确认状态变化可以改变目录，
不能为了保持前缀相同而向模型暴露其他角色的工具。历史观察恢复领域时同样受当前目录约束。

## 消息顺序

模型消息依次为：

1. 固定系统指令、渲染与按需加载能力，随后才是当前验签身份与权限。
2. 经过身份、权限和历史预算过滤的会话消息，含成对的来源工具观察。
3. 从验签身份派生的当前账号编号，以及当前页面、待确认状态和经来源校验的有界历史摘要。
4. 当前用户请求。

每轮变化的数据不会再插到既有历史之前。改变页面、摘要或待确认目标时，
同一权限下的系统和保留历史仍可保持相同；当前用户请求继续位于末尾。
页面附件和当前时间、额度、宿主记录不写入长期会话消息，确认凭据也不进入模型输入。
当前账号编号仅用于识别本人，不进入共享系统前缀或长期记忆；它从服务端验签身份生成。
页面、宿主记录和摘要仍是低信任数据，不能用来覆盖身份或授权。
宿主记录由 `agent/api/host_context.py` 有界投影，作为数据附件置于历史之后；
它们不参与权限判断、确认授权或执行结算。

历史裁剪、权限变更、动态工具恢复仍可能改变前缀；该布局不保证跨轮完整请求一致。
保留加载器会增加已加载阶段的少量 schema 输入，换取目录前段稳定，
没有增加初始请求的工具数量，也没有预先平铺全部业务工具。

停止后继续恢复框架保存的消息和领域顺序；任务标识、继续控制和确认凭据不进入模型文本。
恢复重新核验当前权限，不为命中缓存保留已经失效的能力。已提交的工具观察复用原调用 ID，
未提交读取可能重试，真实缓存收益仍按服务商 usage 计量。

## 验证口径

`tests/runtime/test_native_cache_layout.py` 捕获实际原生循环绑定的工具定义和发出的模型消息，
验证连续加载时定义只追加、重复加载不报错且仍计数、页面变化后的历史顺序，以及降权隔离。
它还通过真实会话存储接续两轮请求，确认页面附件不会残留在历史中。

这些离线测试证明请求布局，不证明上游缓存命中、任务质量或实际费用下降。
服务商的缓存保留、路由及最小缓存单位由服务商决定。
后续线上评测应使用 `llm_done` 的实际 `input`、`output`、`cache_read`，
区分首轮与热请求；缺少 `cache_read` 表示未测得，不能补成零。
请求级聚合沿用 `eval/request_metrics.py`，不新增另一套成本统计。

## 网关会话路由

OpenCode 的 `x-opencode-session` 按已验签账号、当前角色与会话编号生成稳定摘要，
同一会话的主循环、摘要任务与执行结果叙述共用；跨账号、角色或会话分别生成。
没有可信坐标的独立调用使用临时标识。该标识只提供路由亲和性，不承担权限或结果缓存。
客户端使用自己的 User-Agent，避免通用 SDK 名称。

这与 [OpenCode Go 的客户端契约](https://opencode.ai/docs/go/#where-can-i-use-it) 一致。
稳定前缀和路由不保证缓存命中；网关可能调整上游，应根据真实 usage 验证收益。
离线回归验证真实 SDK HTTP 请求头、跨轮重建及并发任务的上下文隔离。

## 公共能力与身份数据的顺序

固定贴纸渲染能力和工具加载方式排在 caller 与 permissions 之前，账号读取的规则属于固定
系统指令。跨角色因此可以共享更长的系统前段，当前角色和授权事实仍逐次核验。
账号编号继续放在本轮数据附件中，不进入公共系统前缀。

本轮离线对照中，超级管理员、用户和杂鱼三种身份的系统公共前缀从1081字符增至1326字符
（框架保守估算约728→891token）。这只证明消息布局变化；工具定义、网关路由和缓存持久化
仍会影响实际命中，不能将字符增长直接换算为命中率或费用收益。DeepSeek缓存为尽力而为的
前缀复用，见[服务商说明](https://api-docs.deepseek.com/guides/kv_cache/)。OpenCode Go的实际收益
继续以响应usage衡量。上一轮79.37%的全量成绩仍归属于当时版本。
