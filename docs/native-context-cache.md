# 原生请求的上下文与缓存前缀

原生运行时使用上游模型提供的缓存统计，不在应用中缓存模型答案或工具结果。
`agent/runtime/session.py` 和 `agent/runtime/prompt.py` 负责保持可复用输入的顺序。

## 工具目录

每轮请求的工具目录依次包含初始工具、全部已授权领域的加载器、已加载的领域工具。
运行时没有委托旧引擎的工具或配置回退。
新加载的工具追加到末尾，不删除加载器，也不把新工具插到既有定义之前。

保留的加载器支持幂等调用：重复加载返回已加载状态，不重复加载或执行业务工具。
重复调用仍计入请求工具预算，避免通过加载器绕过调用上限。

目录只包含当前请求有权使用的领域。权限、身份或待确认状态变化可以改变目录，
不能为了保持前缀相同而向模型暴露其他角色的工具。历史观察恢复领域时同样受当前目录约束。

## 消息顺序

模型消息依次为：

1. 系统指令和从当前验签身份派生的可信能力。
2. 经过身份、权限和历史预算过滤的会话消息，含成对的来源工具观察。
3. 当前页面、待确认状态和有界历史摘要，均作为低信任数据。
4. 当前用户请求。

每轮变化的数据不会再插到既有历史之前。改变页面、摘要或待确认目标时，
同一权限下的系统和保留历史仍可保持相同；当前用户请求继续位于末尾。
页面附件和当前时间、额度、宿主记录不写入长期会话消息，确认凭据也不进入模型输入。
宿主记录由 `agent/api/host_context.py` 有界投影，作为数据附件置于历史之后；
它们不参与权限判断、确认授权或执行结算。

历史裁剪、权限变更、动态工具恢复仍可能改变前缀；该布局不保证跨轮完整请求一致。
保留加载器会增加已加载阶段的少量 schema 输入，换取目录前段稳定，
没有增加初始请求的工具数量，也没有预先平铺全部业务工具。

## 验证口径

`tests/test_native_cache_layout.py` 捕获实际原生循环绑定的工具定义和发出的模型消息，
验证连续加载时定义只追加、重复加载不报错且仍计数、页面变化后的历史顺序，以及降权隔离。
它还通过真实会话存储接续两轮请求，确认页面附件不会残留在历史中。

这些离线测试证明请求布局，不证明上游缓存命中、任务质量或实际费用下降。
服务商的缓存保留、路由及最小缓存单位由服务商决定。
后续线上评测应使用 `llm_done` 的实际 `input`、`output`、`cache_read`，
区分首轮与热请求；缺少 `cache_read` 表示未测得，不能补成零。
请求级聚合沿用 `eval/request_metrics.py`，不新增另一套成本统计。
