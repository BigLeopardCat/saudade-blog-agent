# 零调用/声称的残余：一次「没有效果」的实测，和残余真实的落点

> 分支 `opt/zero-call-residuals`。承接上一批 `6f5a1dc`（planner 单通道化 + 零调用不再等于闲聊）。
> 本文的主结论是一条**否证**：残余的形状换了（`一个函数都不点` → `显式点 chat`），
> 而"把闸门那两条窄判据前移到决策层"这个改法**够不着它**——探针 72 次数据型决策里
> 新判据开火 **0** 次。工程上这次前移仍然留着（理由见 §5），但它**不是**残余的主攻方向，
> 别把它的落地读成"残余治好了"。
>
> 最后更新：2026-10-04。

---

## 0. 一句话

上一批把零工具决策分成两格之后，残余**没有变小，只是换了个形状**：全量语料里"零帧零调用"
42 次（占总决策 9.6%）是**旧代码**的账；在**今天这版代码**上跑定点探针，数据型句子的零工具率
是 **8/60 = 13.3%**，其中 **7 格是"显式点了 `chat`"**——而"零调用纠偏"（`undecided`）
**结构上看不见那一格**（它只为"一个函数都不点"置位）。这就是残余。

本批做的"判据前移"（把 `authz` 那两条窄判据从闸门挪到 planner）在探针上开火 0 次：
那两条判据覆盖的是**已经带"我的/站内"指称**的问句，而真会掉进零工具的那几句恰恰是
**指代型**（「这篇」「这段」）、**写命令**（「给他驳回请求」）和**含糊短应答**（「嗯，看看吧」）
——它们的排除守卫（④⑤ 步）是拿全量语料量出来的，不能为了这一批拆掉。

## 1. 靶子的当前形状（两个来源，分开数）

### 1.1 全量语料（1058 份 trace，**全部是改动前的代码**）

| 项 | 计数 |
|---|---|
| `planner.native_decision` | **436** |
| └ `finish=tool_calls`（正常决策） | 345 |
| └ `finish=stop`（一个函数都没点） | **90** |
| &nbsp;&nbsp;&nbsp;└ 已有工具帧之后（合法收尾轮，**不碰**） | 48 |
| &nbsp;&nbsp;&nbsp;└ **零帧**（靶子） | **42** |

⚠️ 语料里这三项**恒为 0** 不是"机制没生效"，而是**语料比代码旧**：1058 份 trace 全部产自
`6f5a1dc` 之前。所以"改动之后残余还有多少"这个问题，**语料答不了**，只能靠 §2 的探针。

### 1.2 闸门各族的真实射程（同一份语料）

`gate.replan` 全量只有 **3** 次，分属三个不同族：

| 族 | 次数 | 现场 |
|---|---|---|
| `site_absence_claim_without_tool` | 1 | 20260929T020640 |
| `sys_write_claim_without_tool` | 1 | 20261001T024334 |
| `own_read_question_without_tool` | 1 | 20261004T015927（「小猫咪我都有哪些收藏」） |
| `site_corpus_question_without_tool` | **0** | ——（`authz` 头注里已写过：它今天在生产一次都没开火过） |

换句话说：**本批前移的那两条判据，在全量语料里的合计射程是 1 轮**。这不是"改错了"，
而是"改的东西本来就很窄"——上一批把它们落到闸门时就已经量过射程，本批只是把它挪早一层。
唯一那条现场（20261004T015927）今天**已经不可复现**：同一句「小猫咪我都有哪些收藏」在
§3.2 的探针里两臂各 3 轮**全部落到真工具上**。

## 2. 仪器：`eval/zero_call_residual_probe.py`

**只看决策层**：24 句（20 句数据型 + 4 句闲聊对照组）× N 轮，进程内直调 `planner_node`，
不跑 narrator、不跑 gate、零真实写、trace 落临时目录。一轮 = 一两次 planner LLM 调用。

它按句子**该不该有工具**分组，把零工具决策再分两格数：`零调用`（一个函数都没点）与
`显式 chat`（点了 `chat`、零工具）——**这两个必须分开数**，因为纠偏只罩得住前者。

「两臂交替」在本脚本里是内建的（`--arms a,b` 时逐轮把臂序反过来）：同一个时段模型自己
也会漂，不交替就会把"那个时段抖了"读成"改动生效了"。实测过：**同一个臂**先后两次跑
（3 轮 × 20 句）拿到过 11.7% 与 13.3% 两个数。

三个臂，各自只还原**一笔改动**的行为面（不换文件——`git show` 换 `graph.py` 会把同期那批
路径改名一起退回去）：

| 臂 | 含义 | 怎么实现的 |
|---|---|---|
| `after`（默认） | 本批（判据前移）生效 | 什么都不做 |
| `before` | 本批改动**之前** | 把 `authz` 那两条判据短路成恒 `False`——这就是本批唯一的**行为面** |
| `legacy` | 再往前一笔：`6f5a1dc` 之前 | ① 契约规则 7 还原成"可以不调用任何函数"；② `undecided` 恒 `False` |

## 3. 读数（一律读**计数**，不读通过率）

### 3.1 上一批到底改变了什么（`current` × `legacy`，同刻交替）

| 臂 | 数据型零工具 | 零调用 | 显式 chat | 纠偏触发 | 纠偏后仍零调用 | 不可解析 |
|---|---|---|---|---|---|---|
| `current`（=本批的 `before`） | **8/60 = 13.3%** | 2 | 6 | 7 | 1 | 2 |
| `legacy`（契约许可零调用） | **12/60 = 20.0%** | 8 | 4 | 0 | 0 | 5 |

闲聊对照组（4 句 × 3 轮，零工具**是**正确答案）：`current` 8/12、`legacy` 10/12，
两臂差的正是那两格零调用——**契约改动让闲聊终于"说出了 chat 这个词"**。

**这张表是本批最重要的发现**：`undecided` 纠偏把原始零调用从 8 压到 2（探针口径），
但**显式 chat 从 4 涨到 6**。总量 12 → 8（20.0% → 13.3%），**没有它看起来的那么多**，
而且**洞从"不点"挪到了"点 chat"**——纠偏对这一格是盲的。

### 3.2 本批改动有没有效果（`after` × `before`，同刻交替）

| 臂 | 数据型零工具 | 零调用 | 显式 chat | **`data_question_no_tool`** | 纠偏后仍零调用 | 判对 |
|---|---|---|---|---|---|---|
| `after`（判据前移生效） | 8/60 = 13.3% | 1 | 7 | **0** | 1 | 33/60 |
| `before`（判据短路） | 8/60 = 13.3% | 3 | 5 | 0 | 2 | 31/60 |

**新判据开火 0 次，零工具率一格没动。** 而且这不是"恰好没轮到"——**本探针里根本没有
它够得着的靶子**：`after` 臂 7 个"显式 chat"轮次落在 5 句上（「猫咪这段我看不太懂」×2、
「给小猫咪我读一下这篇文章」×2、「嗯，看看吧」、「给他驳回请求」、「猫咪我的未读信息
全部就标记为已读」），**一句都不在两条判据的射程里**：

| 句子 | after/before 的零工具轮次 | 为什么两条窄判据够不着 |
|---|---|---|
| 「给他驳回请求」 | 2/2 | 写命令，句里没有"我的/站内"指称（`_own_command` 那族归写侧） |
| 「猫咪我的未读信息全部就标记为已读」 | 1/0 | 有"我的"，但是**写**命令，② 步排除 |
| 「给小猫咪我读一下这篇文章」 | 2/0 | 指代型（「这篇」），⑤ 步刻意排除（rule 6b：照抄跨轮摘要才对） |
| 「猫咪这段我看不太懂」 | 2/3 | 同上（「这段」） |
| 「嗯，看看吧」 | 1/0 | 短应答，不成问句（⑥a 步排除） |
| 「把它号封吧」 | 0/2 | 写命令 |

实测：`authz.is_own_read_question` 与 `is_site_corpus_question` 对这六句**全部返回 `False`**。
这不是判据写漏了，是那两道排除守卫（④ 自指数据 / ⑤ 指代型）**拿全量 300 轮零帧放行轮
量出来的**，拆掉它们会把现在已经绿的跨轮取值用例打成新红（`golden
followup_entity_slot_category` / `_ambiguous`）。

⚠️ **两臂的零工具集合几乎不重叠**：20 句里 7 句至少有一臂掉过零工具，但**两臂都掉的只有
2 句**（「给他驳回请求」「猫咪这段我看不太懂」）。所以 8/60 这个数里**相当大的部分是采样
噪声**，不是"这几句稳定地错"。报这类读数时要么把句子列出来，要么把轮数加上去——
**只报一个百分数会把噪声读成病灶**。

### 3.3 顺带量到的一条：`_scan_action_intents` 也够不着

想到的第二个候选判据是"零帧 + 显式 chat + 意图清单非空"（复用 `_pending_intents`，
它已经在 `route_after_execute` 与"收尾丢意图"两处用着）。实测**不成立**：
`_scan_action_intents` 扫的是**四条快道**的动作别名（特效 / 导航 / 夜间 / 屏幕），
上面五句**全部返回 `[]`**——它不是通用动作词扫描器。真去扩展它，等于新造一条判据，
代价与误伤都要重新量。

## 4. 被否掉的方案：让所有"显式 chat 且零帧"都纠偏一次

看着最省事：既然两格（零调用 / 显式 chat）都是"这一轮一个工具都不会跑"，就一起纠偏。

**否掉，代价量得出来**：闲聊对照组 12 轮里 **11 轮**是"显式 chat 且零帧"（§3.1）。
所以这条改法会让**几乎每一次闲聊都多一次 planner LLM 调用**（探针实测中位 2.4–3.9s
一次），换回来的是数据型那 8/60 里的一部分。**贵在这头，便宜在那头**。
正确决策的代价如果是"每句闲聊都慢一倍"，那它就不是正确决策。

（顺带记一条容易担心的成本，实测**不成立**：`is_site_corpus_question` 会走 BM25，
但它第 ⑥b 步先过 `_SITE_DEIXIS_RE`（站内/文章/文档/笔记…），**没有站内指称的句子在
调 `rag.search` 之前就返回了**。闲聊句不付这笔钱。）

## 5. 本批实际落地的东西（留着，但别高估它）

**判据前移**：把闸门那两条窄判据（`authz.is_own_read_question` /
`is_site_corpus_question`）在 `planner_node` 里复用一次——这一轮点了 `chat`、零工具、
本轮零帧、主人问的正是那两条判据认得的问句时，**先走既有的 correction 通道纠偏一次**，
第二次仍点 `chat` 才记 `data_question_still_no_tool` 放行。

它买到的是两件事，都不是"残余下降"：

1. **省掉一次会被丢弃的 narrator 调用**。闸门那两条判据开火时，narrator 已经把整段话写完了
   （实测 `20261004T015927`：那次叙述 4.4s），主人先看到一句错话、再被改口。
   决策层判得出来的事不该留给闸门——这也是主人原话里的取向「我希望正确决策」。
2. **闸门不必撤防**：那两条判据在闸门里**一个字没改**，它是兜底；前移只是让它在更早的
   一层先跑一次。前移 ≠ 撤防。

**射程要写清楚**：探针 72 次数据型决策开火 **0** 次；全量语料里这两族合计 1 轮
（且今天已不可复现）。所以这是一条**结构上对、量级上小**的改动。

顺带的两处**没有行为后果**的记录：`no_call_accepted` 多带一个 `via` 字段
（`no_call` / `data_question`，供复扫分辨"是被哪条纠偏催过"），以及两个新事件名
`planner.data_question_no_tool` / `planner.data_question_still_no_tool`。

### 5.1 改动带来的一个真实（但很冷）的取舍

前移之后，闸门那两条判据**只在 planner 纠偏失败时才轮到**。于是有一种形状从"闸门接得住"
变成"没人接"：planner 纠偏成功、工具真的执行了（**本轮有帧**），而 narrator 仍然写了一段
**与那件事无关的**话——闸门第 4 节整族挂在 `if not frames:` 下面，有帧就摸不到它。
`tests/test_gate_replan.py` ⑥/⑥d 的夹具**演的就是这个形状**（脚本化的 narrator 固定说那句
"我没有工具"的谎），改这一批时当场撞上：用例红得有理。

处置：⑥/⑥d 的脚本让 planner **第二次仍然点 `chat`**（`_PLAN_CHAT` 写两遍），于是这一节
仍然测的是**闸门兜底层**；决策层那条成功路径锁在 `tests/test_native_wiring.py`。
新出现的那个形状（有帧 + 驴唇不对马嘴的叙述）本批**不治**——它需要的是"答没答这个问题"
这类判据，而那个判据族在本仓是明写的空白（见 `docs/问题记录.md` 与 gate 判据族的取向：
全是"不许说假话"型）。**这是一条要记账的欠债，不是本批的成果。**

## 6. 残余接下来往哪打（本批只给数，不动手）

把 §3.2 那张表摆齐，残余的落点是清楚的——**不是"模型不肯调工具"，是"这几类句子本来就
没有确定性的正确出路"**：

| 形状 | 例子 | 缺的是什么 |
|---|---|---|
| 写命令没有引号点名 | 「给他驳回请求」「我的未读信息全部就标记为已读」 | 写通道要落到"哪一条"上（id/名字/身份），现有写侧纠偏（`_name_write_nudge`）要求**引号点名** |
| 指代型读请求 | 「这篇」「这段」 | 按 rule 6b 应该照抄跨轮执行摘要；模型选了 chat 说明摘要里**没有可抄的取值** |
| 含糊短应答 | 「嗯，看看吧」 | 承接上一轮提议——`_short_reply_kind` 是整串相等型，这类句子不在它的表里 |

三条落在三个不同的机制上，**没有一条是"再补一条否定式判据"能收的**。要给的话得先定
"哪种形状该由哪一层负责"，再各自量误伤——这是**下一批的选题**，需要先拍板。

## 7. 复现陷阱（跑这个探针/读这些数之前先看这里）

1. **`PYTHONPATH=$PWD` 必须给**：venv 里 editable 安装的 `.pth` 把**主仓**钉在 `sys.path`
   上，不指就在主仓那份代码上跑"本分支的臂"，而且**不会报错**——只是结论全错。
2. **`native_decision.calls` 只有技能名，工具名在 `PARAMS` 里**：判"这一轮有没有工具"
   必须从**计划文本的 `TOOLS` 行**取（探针里那段 ⚠️ 就是为此写的）。读 `calls` 会把
   「我有哪些未读通知」整族误记成"零调用"。
3. **两臂必须交替、且至少 3 轮**：同一个臂先后两次跑拿到过 11.7% 与 13.3%。
   单遍的差一律当噪声。
4. **闸门跑在 narrator 之后**：所以"闸门拦下了"从来不是"用户没看到"——这一点决定了
   §5 第 1 条那个收益（省一次 narrator）才是有意义的。
5. **契约改一个字面会移动病灶，不只是减少病灶**：这一批的教训。改契约之后只看
   "零调用降了吗"会得出"降了 4 倍"的结论，而把两格加起来看是 **20.0% → 13.3%**。
   **数指标时先问"这一格还装得下这个病吗"。**

## 8. 验收（本批跑过的）

- `eval/zero_call_residual_probe.py --rounds 3`：`before,legacy` 与 `after,before` 两组
  同刻交替，读数见 §3。
- 离线套件（出厂档 `AGENT_TASK_STATE=0 SAUDADE_IGNORE_ENV_FILE=1 IOT_ENABLED=1`）：全绿。
  本批改了两处**用例**（不是判据）：
  - `tests/test_gate_replan.py` ⑥/⑥d：脚本里 `_PLAN_CHAT` 写两遍（判据前移之后，第一次
    落 `chat` 会被决策层接走，闸门就看不到零帧轮，本节会退化成"没被测到"）；
  - `tests/test_skills.py` `calls_in_wrong_skill`：那句 `最近有哪些文章呀` 命中
    `is_site_corpus_question`（会走上一层纠偏，本节要验的 `_drop_correction` 就看不见了），
    换成中性句 `帮我看看天气吧`。
- 新增接线锁 `tests/test_native_wiring.py`：判据前移的**成功路径**（纠偏一次 → 落到真工具）、
  第二次仍点 `chat`（记账放行、**不放宽成 `wrapped`**），以及三条反锁
  （闲聊句 / 已有帧 / `uid<=0`）。
