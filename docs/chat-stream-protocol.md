# 聊天流式协议 v2

Python 入口为 `POST /chat/stream/v2`，使用标准 SSE `event:` 与 JSON `data:`。
正文内容不参与事件分类，也不会按命令前缀被过滤或改写。

| 事件 | JSON 数据 | 宿主行为 |
| --- | --- | --- |
| `text` | 字符串 | 累积并转发正文；成功结束后保存完整历史 |
| `progress` | 字符串或 `{text, work:{id,stage,status}}` | 转发进度，不写正文历史 |
| `confirmation` | 允许展示的确认卡字段 | 转发确认卡，不写正文历史 |
| `command` | 浏览器命令对象 | 转发；浏览器继续检查站内地址和动作 |
| `pending` | 已签名提议或取消状态 | 依序持久化，不向浏览器透传 |
| `receipts` | 执行回执数组 | 等待批次事务提交，不向浏览器透传 |
| `done` | 空对象 | 已收到的回执、待确认状态及完整正文保存成功后，正常终止 |
| `error` | 安全的用户文案 | 错误终止；不把残缺正文写成完整回复，不能再发成功结束 |

标准分帧复用 FastAPI、Rust eventsource-stream / Axum 与浏览器 eventsource-parser。
浏览器校验名称、数据类型和终止状态；错误、未知事件和终止后的命令不能触发动作。
页面命令只来自受信任工具的结构化回执。模型可以在正文中引用任何协议示例。

## 发布衔接

Python 与博客都使用 v2；旧 `/chat/stream` 入口及其编码适配已退役。
博客请求仍为 `POST /api/chat/stream`，widget 必须发送 `X-Agent-Stream-Version: 2`。
旧缓存客户端在消息创建、确认消费之前收到 409 与刷新提示；不尝试猜测协议。

流没有自动重连或副作用重放。断连、取消和未知执行结果继续遵守已有运行许可、
确认令牌、执行账和幂等约束。离线探针中的旧报告标签仅供判据读取，不是传输协议。

## 展示身份与断连恢复

单个 SSE 连接按到达顺序消费，终止后事件非法；不另维护一份客户端执行日志。
任务 `task_id`、签名操作派生的卡片 `id`、浏览器 `command_id` 分别负责语义去重。
每个在途请求还绑定发起账号、会话与本地轮次，迟到响应不能更新新轮次或执行页面命令。
相同正文属于不同消息时保持独立，不以文本相等消除消息。

`confirmation` 只含 `id`、`task_id`、`q`、`opts`、`token`、`exp`、`server_time`、
`replay_safe`，以及生图审批可选的 `image_review`。后者来自已核实的后端任务，包含完整
提示词、冻结参考图及结果预览；预览链接只用于展示，不进入模型上下文或作为执行凭据。
提示词按纯文本展示，提供专用复制按钮；确认授权仍只认签名的任务 ID 与版本。
`server_time` 配合浏览器单调计时器展示剩余时间，不依赖本机钟面准确；
授权与过期仍由服务端校验。卡片挂在产生它的回复上；旧操作收尾不能结算其替代卡。

重载或其他标签页改变卡片后，widget 调用博客 `POST /api/chat/task/confirmation`
（`conversation_id`，可选 `task_id`）。博客验证登录和会话归属，再以当前角色签名调用
Agent `POST /tasks/confirmation`。Agent 从 checkpoint 投影仍有效的当前卡片；
跨账号、角色、会话或任务不匹配时不返回凭据。查询不等待模型轮锁、不调用模型、
不签发新授权、不执行操作，响应 `Cache-Control: no-store`。
本地最多保存 64 条、24 小时的卡片展示记录，不保存确认令牌、操作参数或可执行按钮；
历史源消息不在当前窗口时，恢复出的有效卡片单独展示，绝不猜测附着到最后一条消息。

导航的页面到达与超时结果只恢复原任务；账号、会话、任务、命令与路径分别校验。
主题与特效使用 `appearance` 命令，`settings` 只允许 `dark_mode/sakura/rain/snow` 的
`on/off` 绝对值，同次请求合为一组。浏览器应用设置后回传实际观测的 `settings`，
服务端逐项匹配请求；缺失、矛盾、部分失败或超时不能宣称整组完成。回报只证明本浏览器
显示状态，不授予任何业务权限。尚未观测到的值不以默认关闭代替。
命令重放不再跳转；已回传到达结果后刷新只恢复 checkpoint，不重发到达结果。
模型和工具进度每轮最多 24 条；静态进度键随框架状态恢复。可更新工作使用不透明 `work.id`
定位同一展示行，`stage` 来自已核实状态，`status` 只允许 `running`、`waiting`、`completed`、
`failed`、`cancelled`、`unknown`。这些字段不派发操作；重连后重复状态更新该行，不增加重复条目。
生图和入库分别批准，批准后可用一次有界 SSE 读取等待状态变化，不追加模型轮询。
等待超时仍未完成，`saving` 也不等于入库；仅 `accepted` 与真实图片编号证明保留成功。

## 轮次丢弃

`turn_id` 标识一条主用户消息及其补充输入，历史返回 `turn_id` 和 `parent_turn_id`。
`task_id` 标识可恢复任务；审批反馈可形成新轮次并继续原任务，累计预算不重置。
这两个标识不得互相替代，也不以消息文本定位删除目标。

`POST /api/chat/discard` 必须提交 `conversation_id` 和 `turn_id`。宿主验证归属及最后轮次，
在同一事务中删除对应历史、失效摘要并登记 outbox。Agent 以轮次屏障和 LangGraph 公共
状态 API 完成清理，宿主仅在收到可验证确认后返回成功；投递中的 `202 cleanup_pending`
不允许客户端重发任务，须保留编辑草稿并稍后核对。双方屏障阻止迟到请求和历史回写。
无法识别的历史失败轮次拒绝猜测删除；丢弃不撤销已发生的业务操作，也不删除执行账。

## 博客保存完成边界

登录用户的 `done` 还表示博客的完整回复、已收到的执行回执与待确认状态已经保存。
数据库或短写任务失败返回安全的 `error`，不转发 `done`。访客不创建博客聊天记录。
上下文摘要由 Agent 的框架中间件和 checkpoint 管理，不通过 HTTP 或私有 SSE 写回宿主。
职责与来源边界见[会话记忆](conversation-memory.md)。

正常请求等待写任务，浏览器断开只取消等待方；已开始的短写入继续完成并记录错误。
没有收到完成事件不能推断远端操作未执行，应先核对结果。Python 的执行账继续负责
业务幂等与未知结果处理；博客的展示/检索副本不提供跨服务 exactly-once 或进程崩溃后
恢复尚未提交写入的保证。真实模型线上基线保持独立，不以这些离线检查替代任务质量验收。

## 慢客户端与执行终态

每条SSE流最多缓冲64个数据帧，正文与控制卡按产生顺序交付。生产线程在缓冲满时等待，
每次等待都检查停止信号；超过五秒仍不能交付会终止生产并记录`backpressure_timeout`。
进度属于尽力而为的展示事件，缓冲满时可以跳过，不替换正文或确认卡。

生产任务的取消与错误通过标准Future返回，独立于数据缓冲；消费者先处理已入队数据，再
读取终态。只有收到正常终止帧才发送成功`done`，提前退出、异常及取消均不伪装成功。
消费者退出会取消等待中的取帧操作，不取消或遗弃实际工作线程；名额仍在工作线程退出后归还。

满载准入采用Semaphore的无等待快路径，拒绝额外请求，不积累进程内等待队列。
容量是每进程设置，部署总上限还须结合进程数、数据库连接和模型服务配额验证。

单次ASGI发送最多等待十秒，超过期限按连接不可用结束。响应关闭显式终结请求所有权，
覆盖响应头尚未发出、生成器尚未启动时的断开；随后通过AnyIO取消作用域关闭数据源。
这层只给Starlette的发送和资源清理增加应用期限，不另建HTTP或SSE协议实现。

## 浏览器天气上下文

博客前端通过 GeoJS 推断 IP 城市，再向 Open-Meteo 请求当前天气模型数据。
`current_weather` 仅包含城市、国家代码、摄氏温度、WMO 天气代码、湿度、风速、
Unix 数据时间和来源，不传递原始 IP 或坐标。定位是估计，不等于用户实际所在地。
请求不携带站点凭据；十分钟缓存、失败退避和有界超时，无后台轮询，不阻塞聊天。

宿主和 Agent 分别验证类型、范围和数据时间；超过一小时或无效的附属数据直接丢弃。
快照只进入本轮上下文尾部，不写入固定系统前缀或长期记忆，不用于授权。
无快照或询问其他城市时保持未知；天气查询工具已移除。
