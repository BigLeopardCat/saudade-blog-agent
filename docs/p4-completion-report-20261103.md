# P4 收尾验证（2026-11-03）

本轮完成工程收敛与固定版本回归。框架迁移完成、确定性检查通过、语义无疑点和企业验收通过分别记录。
生产为 OpenCode Go / DeepSeek v4.1 Flash、low；不批准线上业务写入。

## 本轮完成范围

- AgentRuntime 与 CheckpointConversationStore 使用职责命名；应用入口显式装配博客能力。
- 领域权限依赖通用接口，签名提案不再反向依赖产品。继续复用 LangChain create_agent、LangGraph checkpoint/interrupt 与 DBOS。
- 暂停与审批恢复沿同一任务；内部反馈不作为新用户边界。失败草稿通过结构化 text_reset 撤回，进度、卡片和业务回执保留。
- 标准 TodoListMiddleware 支持多事项请求；无效协议和未完成清单仅有界纠正，不复制框架执行循环。
- RAG 通用算法使用 BM25S、LangChain、SciPy、Tokenizers、scikit-learn 和 markdown-it-py；删除 CLIFF、手工疑问词删除和旧探针。领域别名、权限、来源与发布适配保留。
- 原文读取绑定解析版本、小节和字符范围；候选链接不当正文证据。文章 trace 为 32K 字符、完整语义材料为 64K，截断或缺失保持未评估。
- 24 款表情与旧别名统一；六种指定表情在真实浏览器加载成功。24 份原始 PNG 已经博客 R2 图库逐份校验并归档。
- 默认 CI 使用锁定公开依赖及宿主源码，不读取维护者部署配置；PG 集成独立配置。源码扫描排除 Git 忽略的历史快照，原始首跑和失败证据不删除。

## 疑点复核与处理

逐条读取冻结材料后，15轮标疑中有8轮真实缺陷、5轮judge核心误判、2轮材料不足。
误判中包括把可信caller当无来源身份，以及把页面导航/外观权限当文章管理权限。
`write_denial`的拒绝有依据，但其具体后台恢复建议仍未完全核实，不能整轮洗成无疑点。
人工分歧记录不覆盖原始judge，不将131/145直接改成另一份“通过率”。

| 已确认缺陷 | 本轮处理与边界 |
| --- | --- |
| 后台文章分组表头数量矛盾 | 工具用标准库Counter给出返回页状态计数，明确不是全库聚合；保留原始失败与后续专项结果 |
| 未调用检查却声称查过页面/博客健康 | 记录为事实性缺陷，不加关键词短路或正则改写回复 |
| 拒绝后额外限定只能由博客作者处理 | 权限拒绝与恢复建议分开评估，不能从缺少工具补造流程 |
| HTTP无浏览器回执时混称已打开 | sent与完成必须区分；真实浏览器等待/恢复已另测，不能用它倒填HTTP首跑 |
| 服务异常无依据归因 | 系统状态与故障原因分别取证，现有服务计数不能证明原因 |
| 访问面板每日曲线能力无依据 | 已知页面路径不等于已经核实具体功能 |
| 代写通知增加未来解冻通知安排 | 保留为草稿事实性缺陷；本轮未批准通知或冻结，确认卡仍是执行前边界 |

两项材料不足是导航栏具体布局和站内信空结果的完整收件箱覆盖范围；
不能从空items或当前网页补造当轮证据。剩余语义问题进入可靠反馈标签与后续候选对照，
不以新增逐场景输出门禁、扩大schema或修改旧分数替代质量改进。
