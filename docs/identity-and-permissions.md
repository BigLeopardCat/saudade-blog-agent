# 身份、权限与操作确认

本文描述当前主线。身份来自宿主验签，权限由确定性代码检查；模型选择工具和组织回复，
不决定授权。现役运行时没有 shadow 放行、命令正则免确认或旧规划器分支。

## 3. 身份与授权

### 3.1 身份：Principal

`agent/principal.py` 定义用户编号、角色和来源。服务只接受已验证宿主断言作为可信身份，
请求正文、页面内容、模型输出及摘要不能提供身份或提权。私人数据访问还要求编号为正整数，
并与当前会话和工具配置中的用户一致。

默认启用 `AGENT_REQUIRE_ASSERTION`；私有与后台端点不能靠正文中的 `user_id` 绕过校验。
业务服务独立验证转交的短时效凭据，并执行自身的账号、角色和目标政策。

### 3.2 权限：scope manifest

`agent/authz.py` 只定义封闭权限范围、角色授予和纯授权判断。

| 角色 | Agent 授予 |
| --- | --- |
| `user` | 公开读取、本人读取、本人状态修改、本人页面动作及已启用的设备能力 |
| `admin` | 上述能力与后台读取、写入 |
| `superadmin` | Agent 范围与管理员一致；后台业务服务继续执行更细的账号层级政策 |
| `zako` | 不授予工具范围，仅对话 |
| 未知角色或未验证身份 | 不授予私人或后台能力 |

范围分为 `read.public`、`read.own`、`write.page`、`write.device`、`write.own`、
`admin.console` 和 `write.console`。权限声明覆盖可调用工具和服务端确认操作；
操作名不意味着模型可直接调用对应写入对象。

### 3.3 失败时拒绝

`check` 返回允许与否、原因码和所需范围；`holds` 查询已知角色是否拥有某一范围。
未知权限名、未知角色、未获授范围均拒绝。生产不再提供可关闭检查的权限灰度开关。

工具目录在加载时按可信身份过滤，实际分派前再次检查。私人及管理员领域通过
`agent/runtime/access.py` 核对验签来源和用户编号。模型手写不存在的工具名或旧裸写操作名，
不能进入领域确认或绕过执行入口。

### 3.4 人在回路：授权之后确认本次操作

授权回答“这个身份能做什么”；确认绑定“本次要对哪些目标做什么”。两者不可互换。

1. 领域准备工具按用户需求读取、解析目标和版本，不写业务数据。
2. 服务生成绑定用户、会话、有效期、操作标识及具体参数的签名提议，展示可读确认卡。
3. LangGraph 暂停持久任务；用户确认后，服务校验签名、绑定、撤销状态和当前授权。
4. 领域执行器核对目标版本并执行业务事务；真实回执才允许恢复相应任务。
5. 取消撤销服务端提议；关闭界面卡片不等同于取消。过期卡、旧会话卡和被替换的卡均不能执行。

自然语言“确认”不会直接成为业务授权凭据，也没有靠关键词识别命令后跳过签名确认的快道。
框架 `Command` 恢复信号本身也不授予写权限。

### 3.5 观测与未知结果

当前 trace 记录实际拒绝、执行、回放及终止原因，不用旧 shadow 统计替代授权。
历史报告解析保留在评测包，不能影响生产放行。

执行账先保存意图，再发送业务请求；已完成回放既有回执，在途或未知结果不盲目重做。
写入可能已成功而回执丢失时，先查询实际状态。这里不承诺跨服务 exactly-once。
确认凭据、业务凭据和原始敏感参数不进入模型提示词或公开进度。

### 3.6 零工具身份：zako

`zako` 是明确的对话身份，权限集合为空。人设与轻度调侃属于产品表达，不能据此更换权限，
也不能让角色扮演文本覆盖真实调用者。普通用户、管理员和站长的称呼同样由可信身份决定。
公开数据仍通过站点自身可见性政策提供，Agent 不冒充已经读取了未调用的接口。

## 4. 调用链

宿主鉴权 → 签名身份断言 → Agent 验签 → 领域目录过滤 → 工具分派校验 →
只读准备 / 持久审批 → 版本及执行账核对 → 业务服务独立鉴权和事务 → 回执 → 回复。

历史与摘要只提供对话事实，不能成为执行凭据。删除会话、身份变化、断连及任务恢复
继续受会话锁、来源范围、截止时间和删除屏障约束。

## 5. 管理能力与执行边界

### 5.1 管理读取

管理员读取使用有界目录、指定记录或聚合统计；公开接口不返回草稿、私密正文或匿名内容的
真实账号归属。需要后台事实时读取对应后台能力，不用公开留名推断身份。

### 5.2 管理写入与审计

文章状态、标签、分类、公告、账号、通知、审核、待办和额度操作由各领域准备与事务执行器承担。
模型只看到准备入口，不暴露已退役的裸后台写工具。权限名与回执名继续保留，因为业务能力仍然存在。

文章批量状态操作冻结明确编号和版本后一次确认、一次事务执行；任一目标失效整批拒绝。
跨服务或不同操作类型不冒充同一事务。新增领域应复用标准工具、middleware 和现有执行账，
不新增文本计划语言、自然语言授权匹配器或并行规划引擎。

### 5.3 确认卡、恢复和自然回复

确认卡与浏览器命令来自结构化服务事件，模型正文不能制造有效卡片或命令。
界面仅展示操作内容、范围与可选决定，版本和签名留在服务端协议。

执行参数不由模型在确认后重新生成。可选叙述根据受限的事实回执组织自然回复，计入请求预算；
叙述失败仍保留实际回执，不重试业务操作。确认、取消、重复回放、权限变化和未知结果
由各领域及运行时行为测试验证，详见[架构](agent-architecture.md)和[会话记忆](conversation-memory.md)。
