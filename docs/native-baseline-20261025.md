## 成本与延迟

以下仅统计全量 134 请求；小样本已预热缓存，不能当成冷缓存性能。

| 指标 | 结果 |
|---|---:|
| 带完整 usage 的 `llm_done` | 298 |
| 输入 / 输出 token | 1,205,648 / 22,745 |
| cache-read token / 输入 | 999,040 / 1,205,648 = 82.86% |
| HTTP 单请求 P50 / P95 | 6.28s / 11.53s |
| 服务端首个可见事件 P50 | 0.027s |
| 服务端正文首片段 P50 | 2.50s |
| 请求因累计 token 预算中止 | 2 |

首个可见事件包含进度，正文首片段也可能是读工具前的说明，均不等于最终答案完成。
缓存比例是输入 token 的读取占比，不是请求命中率或计费折扣。

闲聊样本为 1 次模型调用、3,151 输入 token；“带我去留言板”虽成功，却用了 4 次调用、
13,697 输入 token、约 12s。缓存已有可接受的初步收益，简单动作的往返次数仍需优化。
最高输入样本是检索后读向量图谱，4 次调用、27,534 输入 token；不能把均值当作单任务上限。

## 确认的问题与优先级

| 优先级 | 场景 | 证据与下一步 |
|---|---|---|
| P1 | 收藏准备 | 公开接口返回 `noteKey`，准备代码只检查 `noteId`，导致真实文章无法生成收藏卡；统一文章 DTO 适配并补真实接口形状回归 |
| P1 | 一句包含两项写入 | 模型同批提出两个准备调用，运行时以 `parallel_terminal_calls` 中止；完善原生确认与任务续行契约，不能把第一张卡当作整个任务完成 |
| P1 | 长文 / 三来源读取 | 两项因 `request_tokens` 中止；优化证据选择、分页和上下文使用，不直接提高全局预算掩盖问题 |
| P2 | 角色语义 | 管理员寒暄被当作普通客人；把站内 `zako` 角色调整误当成贬损请求而拒绝；修正能力与角色语义表达 |
| P2 | 待办新增 | 明确请求仍被追问并非必填的截止时间，未调用准备工具 |
| P2 | 读图 | 红图答成白色；红蓝两图答成黑蓝。浏览器解码确认原 PNG 是不透明红/蓝，模型/网关/图像链路仍须定位 |
| P2 | 天气 | 实际工具返回 unavailable，未获得天气结果；检查上游与适配契约 |
| P2 | 格式 | 用户只要数字时仍附加猫系口癖 |

上述覆盖 11 条真实失败。标签“测试”的识别、增删替换清空、取消与修改卡片、
短会话记忆、角色越权拒绝、页面上下文注入和留言指令注入等本批判据通过。
这不代替长上下文压缩、并发恢复及真实写入夹具专项，详见
[当前基线范围](evaluation-native-baseline.md)。
