## 真实流量结果

普通用户在同一新会话中先找文章再解读；管理员在另一新会话中准备修改再取消。
所有请求均经过博客鉴权、身份断言及实际 Agent HTTP 服务。

| 场景 | 实际工具及结果 | 模型调用 | 输入 / 输出 token | 耗时 |
| --- | --- | ---: | ---: | ---: |
| 找 IoT 与 asyncio 文章 | 两次 `search_notes`，返回真实文章 22、23 的标题及链接 | 2 | 6,494 / 201 | 4.77s |
| 接着解读 asyncio 文章 | 从上一轮定位 23，调用 `get_article_detail`，按正文解释协程、Task 与事件循环 | 2 | 10,491 / 498 | 7.42s |
| 文章 54 添加验收标签 | 读取当前文章并 `prepare_article_tags`，确认内容绑定精确标签名，无业务执行 | 3 | 13,739 / 143 | 7.93s |
| 取消上述操作 | 加载取消工具并 `cancel_pending_operation`，根状态待确认项及 approval 清空 | 2 | 10,681 / 49 | 7.12s |

解读的文章正文为 5,325 字符，工具一次取到完整内容；答复有关 Task、Future、事件循环
及用户态调度的表述均可对应原文。这个样本没有覆盖超过读取上限后的多次续读。
正文进入下一次模型输入时为 6,026 字符的工具结果；跨轮历史保留 1,421 字符节选，
属于既有有界记忆策略，不等于当前解读时正文被截断。

四步合计输入 41,405、输出 891、缓存读取 22,272 token；缓存读取占输入约 53.8%。
这些是单次计量，包含缓存输入，不是费用或稳定成功率。两条会话删除后，checkpoint
均为空，历史接口均返回 404。

## 节点与数据变化

| 边界 / 节点 | 数据变化及核对结果 |
| --- | --- |
| 博客鉴权 → Agent API | 服务端核实普通用户或管理员；当前问题、会话坐标及来源通过断言与请求上下文进入运行时，页面上下文不授予权限 |
| `build_messages` → 产品装配 | 用户问题转为标准 HumanMessage，可信身份与页面数据单独装配；本次观察到的七个模型输入 checkpoint 中，当前问题均只出现一次 |
| `ArticleMiddleware.before_agent/before_model` | 文章证据状态通过标准 middleware 接入；模型可见菜单由当前权限和已加载领域组成 |
| `SessionMiddleware.before_model` → `model` | 模型调用前的标准消息序列均完成上一批工具配对，没有待回答工具调用穿过下一次推理边界 |
| `model` → `tools` | 搜索、正文及后台文章读取的参数可在 AIMessage.tool_calls 中找到；工具结果哈希与 child checkpoint 中对应 ToolMessage 一致 |
| `tools` → 下一次 `model` | 两个搜索结果按调用 ID 回填；下一轮定位文章 23，正文结果进入模型后才形成解读答复 |
| 准备工具 → `approval` | 文章编号、原版本及精确增量意图进入确认规格；child 保存 proposal，根图保存待确认项并在 approval 中断，未生成业务回执 |
| 取消工具 → 根状态提交 | 撤销事件关闭待确认项；根状态的 pending_confirm、pending_action、approval 均为空。旧 child proposal 是未激活的历史状态，不构成批准；旧卡撤销与后续零执行由既有行为回归覆盖 |
| 终态 → SSE / trace / 博客历史 | 四步正文逐字一致；公开 SSE 不透传宿主内部 Pending 帧，宿主负责保存相应待确认或取消状态 |
| 会话删除 | 本次创建的两条会话及各命名空间 checkpoint 均已删除，其他会话不受影响 |

只读轮询共取得 47 份 checkpoint 观察，包含部分上一轮保留状态；短暂的最后写入可能被
`keep_latest` 裁剪，所以另读取每轮结束后的最终状态。取消轮使用隔离的临时子图，
其所有瞬时节点不由 PostgreSQL 轮询覆盖；不能把本次检查称为生产每条 SDK 请求的完整抓包。

## 隔离的真实模型确认执行

请求“把文章 19 加入我的收藏，完成后再查一次我的收藏确认结果”。业务 HTTP 全部通过
现有 `favorite_backend` 模拟；框架使用 InMemorySaver，执行账使用临时 SQLite。

1. 真实模型加载工具、准备确认；夹具收藏为空，未写入。
2. 重建 NativeRuntime，再用已验签确认恢复 LangGraph；夹具只收到一次收藏 POST。
3. 模型继续读取收藏，依据真实模拟回执自然回复；pending 与 approval 清空。
4. 重放同一确认，只返回既有回执，模型调用为零，夹具写入仍为一次。

准备、执行续行分别为两次模型调用，预算账记录 6,411 / 7,036 token。
捕获的四次模型 SDK 请求均完成工具调用配对，确认 bearer 未进入模型输入或报告。
这验证了相同框架的确认续行与任务表达，不代表生产外部业务服务具备跨服务 exactly-once。

## 本轮修复及未覆盖项

- 评测适配器此前将 Python 无图片默认值 `""` 直接发给要求数组的博客接口，导致请求
  在 prepare_chat 阶段被拒。初始材料保留为前置失败；适配器现将字符串规范为数组，
  没有放宽博客接口。
- 宿主 SSE 已返回具体错误时，评测曾只报“找不到 Agent trace”。现保留上游错误原因。
- 原准备工具 trace 没有参数关联信息，各工具事件也缺少稳定调用 ID。补充原生 call_id
  及规范 JSON 参数的 SHA-256 指纹后，可精确关联重复调用与框架 ToolMessage。
  准备参数正文及返回的确认凭据继续不进入 trace；具体写入内容在签名确认规格中核对。

本次未做浏览器点击、进程崩溃或线上并发压测。单红图识别仍是独立未解决项，见
[视觉记录](native-regression-20261025.md#部署后的真实-http-验收)。全量线上基线继续暂缓。
