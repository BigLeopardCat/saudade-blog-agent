# 原生运行时线上基线

当前入口：`python -m eval.online_baseline`，测试集为
`eval/golden/native_requests.jsonl`。它复用 `run_golden` 的请求构造、多轮驱动及判据，
通过标准 `httpx-sse` 客户端调用正在运行的 HTTP 服务。

## 范围与判定

- 127 条场景、137 轮请求：普通用户、管理员、杂鱼身份；导航与外观；文章检索与正文；
  公开资料、本人资料、管理员读取；确认准备、取消、修改、多意图；真实会话记忆、隔离、
  提示注入、图片与格式。
- 工具读取以 `native.call` 的实际观察验证；请求工具、自然语言声称和旧规划器节点都不算执行。
- 卡片检查已验签载荷中的目标与嵌套参数。例如新增标签必须是 `add:["测试"]`，
  不能把“加上测试当标签”当作名称，也不能误变成整体替换。
- 计数回答必须符合格式并来自本轮读取的实际数值。正文摘要等开放内容仍须复核事实质量；
  自动通过率不能代表全部语义质量。
- 不自动重试失败用例。每条结束即保存原始结果、失败原因、请求 ID、trace 和首段延迟。
  评测前提错误单列 `evaluation_error`；它不是任务成功，也不归因于模型退化。
- 本测试集不发送批准业务写入的请求。准备、取消、替换卡片必须零业务写入。
  HTTP 客户端在发送前拒绝任何确认凭据，防止多轮驱动误带上一张卡的批准信息。
  实际写入、签名、幂等和未知结果另由隔离领域契约验证，不能冒称本轮已线上验证实际写入。

## 运行

在可访问运行中 Agent、博客和 trace 的受信环境中运行；`.env` 仅由本机读取。
UID 必须是环境中真实账号，先用博客 profile 接口核对角色，不能凭账号名称判断。

```bash
python -m eval.online_baseline --phase poc \
  --admin-uid "$GOLDEN_ADMIN_UID" --user-uid "$GOLDEN_USER_UID" \
  --report-dir eval/report/online-poc-<唯一批次>

python -m eval.online_baseline --phase full \
  --admin-uid "$GOLDEN_ADMIN_UID" --user-uid "$GOLDEN_USER_UID" \
  --zako-uid "$GOLDEN_ZAKO_UID" \
  --report-dir eval/report/online-baseline-<唯一批次>
```

小样本全部获得可靠 HTTP/trace 证据后，再运行全量。小样本遇到评测接线错误即停；
全量保留每项任务失败，继续其余用例。服务版本变化则停止该批，避免混合不同构建。
报告目录必须不存在；不覆盖此前首跑。

运行前冻结测试集及判据源码。额度重置准备要求真实目标有已用额度；前提不满足时单列
评测错误并停止该条，不能把正确 no-op 误判成业务故障。

默认全量直接访问 Agent `/chat/stream/v2`，验证服务鉴权、原生运行时、模型、工具、
持久会话与传输。`--host --phase poc` 另走博客 `/api/chat/stream`，
核对宿主身份转发及集成。宿主会私有保存回执等事件，因此不拿宿主过滤后的事件冒充全量回执证据。
Agent HTTP 不验证博客额度扣减，也不模拟浏览器点击或视觉渲染。

每条用例创建该账号拥有的临时会话，所有轮次使用同一 ID；通过博客删除接口清理，
不会删除既有会话。确认凭据只留在内存，报告保留脱敏卡面及结构化参数。
生产 HTTP 请求不可改写其生产 trace 来源；报告通过确切请求 ID 单列评测流量，
成本只汇总本批 trace，不能把这些流量当作自然用户流量。

## 与旧测试集的关系

`basic.jsonl` 的 193 条用例保留给历史报告与离线判据回归；其旧 CLI 不能当作当前线上基线。
`native_migration.json` 记录每条的去向：159 条以当前场景族重建、10 条退役无效前提、
5 条由独立契约验证、19 条明确未纳入此次 HTTP 集。两个测试集的通过率不可横向比较。

退役前提包括：伪执行台账当事实、无身份管理员准备写卡、未登录对话强制调用本人写工具。
多轮用例改用真实请求建立历史，保留同一句话在不同身份下的对照；不会将这些对照误删为重复。

尚缺的专项包括长上下文自动压缩恢复、断连并发孤儿消息、真实通知锚点、带状态的专属写入夹具，
以及确认第一项后自动继续第二项的任务完成度。第一张卡准备成功不能代表两项任务已完成。
新增覆盖应使用当前请求与事实证据，不恢复旧 planner、ledger 或 task-frame 断言。

## 报告口径

每次记录测试集哈希、用例哈希和运行服务版本。`passed/failed/evaluation_error` 分开统计，
未跑用例不算通过。缓存命中以服务商返回的 cache-read / input 计算，缺失 usage 单列；
P95 至少需要 20 个时长样本。小样本、全量与宿主样本分别报告。

复核发现判据错误时，保留原始首跑及错误判定，在独立复核报告解释修正；不重采样冲绿。
确认真实功能缺陷后另开修复批次，再用受影响用例验证，不在冻结基线途中修改提示词。

## 语义评审

复用 `eval/llm_judge.py` 的模型适配与解析，针对已冻结的线上报告运行：

```bash
python -m eval.online_judge --report eval/report/<批次>/report.json \
  --out eval/report/<独立语义评审批次>
```

此步骤不重发用户请求，不批准任何写入。材料包含本轮及先前真实请求、实际工具观察、
执行回执、待确认参数和回复；拟写正文是待审输出，不能成为自身事实依据。
这些材料会发送到配置的模型端点；运行前应确认该端点获准处理相应数据，报告保存在本地。
评审检查新增事实与业务条件、无依据拒绝、任务遗漏和无效追问，允许正常暂停等待确认。
第一张卡不能证明后续任务已经执行。新 trace 保存实际绑定工具的契约与轮次状态；评审读取
当时可用工具的名称、说明，以及实际请求工具的参数 schema。旧 trace 缺失的能力和状态
保持未知，不用当前源码重建。隐藏摘要与视觉证据仍未包含，不能宣称长期记忆和视觉体验通过。

结果单列 `suspect/no_issue_found/not_evaluated`，不改原始确定性判定。`no_issue_found`
仅表示本次评审未发现问题；模型相关偏差仍可能漏报。模型错误、截断、超长或缺失材料均为
未评估，不能报绿。疑点应引用原文供人核对；已知错误和正确样本要一起校准误报与漏报。
可用 `--model` 指定同一已配置端点支持的其他评审模型；默认与生产同源，不能宣称独立评审。
每轮保存原报告、材料与评审器哈希、模型及 usage；不自动重试、改换评审提示或择优取结论。
业务权限、确认、幂等和精确参数继续使用确定性测试，LLM 不参与线上授权或执行裁决。

## 多步写入任务的隔离验收

`python -m eval.native_contracts --case notice_then_role --case notice_role_cancel --repeat 2`
使用真实模型、实际领域工具和合成 HTTP 服务，分别以验签的合成管理员身份运行。
业务请求仅进入 `httpx.MockTransport`，checkpoint 使用内存，执行账使用临时 SQLite。
检查通知的精确目标与原文、确认前零写入、第一次批准只发通知、第二次批准才改身份、
最终业务状态、旧卡重放和中途取消。模型负责工具选择与确认后的续行。
它不验证 PostgreSQL 持久性或真实业务服务器事务，也不代替自由代写的语义质量评审。
