# 安排后台计划

后台计划仅对已启用调度的管理员开放。没有独立 Worker 或有效委托时，不能只凭一句聊天承诺执行。

## 先从提醒练习

> 十分钟后提醒我检查文章草稿。

按以下顺序操作：

1. 明确提醒内容与时间；跨时区时写出地点或 IANA 时区，不只说“九点”。
2. 阅读确认卡的触发时间、时区、任务类型、正文和来源会话。
3. 批准后查询自己的计划，核对其已保存，而不只看模型承诺。
4. 到点在来源会话查看结果；未回报时查计划/执行状态，不新建多个同内容计划。
5. 不需要了先查询准确计划，再准备暂停或取消，审阅变更后批准。

核对确认卡中的时间、时区、提醒内容和来源会话，再批准。需要修改或取消时，先查询自己的计划，
然后核对目标和变更卡。提醒直接交付已批准正文，不需要到点再调用模型。

## 再使用只读报告

> 明天上午九点整理公开文章的近期情况，结果发回这个会话。

明确时区、范围和输出。后台分析使用独立任务上下文，不自动拥有原聊天完整历史、编辑器草稿或图片；
应在目标中给出执行需要的信息。到期结果回到来源会话，网页不必一直开着。

## 定时写入与条件

支持的定时公告会冻结标题、正文和时间；部分管理员变更还冻结对象与版本。
目标到时变化可能导致冲突或跳过，这是保护，不能让后台模型随意扩大权限。

当前支持有限的文章公开条件等待，需明确截止时间；通用条件写入授权与任意跨领域组合仍不是已实现能力。
创建前核对[调度支持范围](https://github.com/BigLeopardCat/saudade-blog-agent/blob/main/docs/scheduling.md)，
不要把未来 ADR 设计当作现有功能。后台未执行或未回报时按
[排障](https://github.com/BigLeopardCat/saudade-blog-agent/blob/main/docs/troubleshooting.md)检查。

## 在界面管理计划与结果

聊天中的任务/计划入口可以查看自己的持久记录和结果提示。核对标题、时间与状态，再选择当前界面允许的操作。
暂停阻止尚未开始的执行，恢复沿用原定义；取消阻止后续执行或通知，不能撤销已经投递的内容。
删除记录和取消任务不要混为一谈，按按钮的实际说明核对。

结果绑定创建计划的会话。关闭窗口不调用汇报模型，重新打开后按状态补报；切到其他会话不会把结果改投过去。
有执行中、暂停或待确认任务时，先处理当前状态再查看汇报，不能把暂未弹出当成已经丢失。
没有 Worker、委托过期、账号权限下降、目标版本变化和条件截止都可能阻止执行，分别查明后处理。
