# Agent 能做什么，怎样提出任务

先问“你现在能做什么”，助手可按当前身份和已启用目录介绍能力。
角色、确认服务、Worker 或模型能力缺席时，不把整张功能表当作你已经可用的权限清单。

## 按目标选择说法

| 目标 | 示例要求 | 看什么结果 |
| --- | --- | --- |
| 找文章 | 找三篇关于事务的公开文章，给链接并说明区别 | 真实标题、链接和相应来源 |
| 定点阅读 | 解释这篇文章第二节的限制条件 | 对应章节证据，不扩成未读全文 |
| 全文总结 | 总结全文，列出主要方案、局限和来源 | 完整源覆盖；失败时明确未完成 |
| 页面操作 | 打开文章列表，开启夜间模式 | 浏览器实际回报，不只是“已发送” |
| 个人数据 | 查我的收藏、通知和当前会话记录 | 只读本人范围；读内容与标已读分开 |
| 写作协作 | 在当前编辑器润色第二段，保留事实 | 可审阅差异，采纳后还要检查保存 |
| 管理文章 | 准备给文章设置封面、标签或状态 | 卡片对象、版本、实际选项与回执 |
| 管理字典 | 在主标签“开发”下准备子标签“Rust” | 正确层级和父标签，不凭重号猜目标 |
| 管理账号 | 查询账号的冻结资格，再准备操作 | 准确账号、当前权限与确认卡 |
| 公告/个人通知 | 准备公告，或给指定账号发通知 | 两者受众不同，完整正文和影响范围 |
| 图库与生图 | 找合适图片，或审阅参数后生成新图 | 参数批准、结果保留、封面设置分别决定 |
| 后台计划 | 十分钟后提醒我，结果发回这个会话 | 已批准的计划、真实触发和结果投递 |
| 统计和诊断 | 读取后台文章统计并说明时间范围 | 真实指标来源，未知项不补成零 |

管理员动作仍受宿主权限、目标版本、数量和业务规则限制；没有图片理解能力的端点不能因附件可显示就声称识图。
设备演示仅在明确启用且用户获授权时可用，不是博客或聊天的必备功能。

## 提问时给出四件事

写清**目标对象、要做什么、限制、交付形式**。例如：

> 对这篇公开文章做全文总结；保留前提与限制；不修改文章；用五条要点并附来源。

> 只准备给账号 reader-demo 发一条维护通知，先让我核对正文，不要发布全站公告。

已知 ID 或真实链接直接提供；只知道昵称时先让系统核对候选，不默认为唯一账号。
任务中可以补充要求，但已经发生的业务效果不会被一句“改成别的”撤销。
