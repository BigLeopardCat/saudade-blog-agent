# 聊天与文章阅读

## 找到要读的文章

打开聊天窗口，先说目标，再给已知标题、链接或关键词，例如：

> 找出介绍 PostgreSQL 事务的文章，给我链接，并说明哪篇更适合先读。

核对回答中的真实文章链接。没有命中时，换关键词或给准确标题，不把相似文章当作同一篇。
追问某段内容时指定文章和章节，例如“解释第二节的失败场景”。

## 总结全文

> 总结这篇文章全文，按问题、方案、限制和适用场景组织，并附来源。

全文总结与查找局部证据采用不同读取模式。长文可能需要额外读取和内部汇总，耗时也会增加。
看到读取失败、版本变化或预算不足时，应先处理未完成状态，不将已读片段当作全文结论。
总结是派生材料，重要细节回到原文核对。具体覆盖契约见
[RAG](https://github.com/BigLeopardCat/saudade-blog-agent/blob/main/docs/rag-design.md)。

## 操作窗口与任务

顶栏可把窗口收成一条可拖动的顶部栏；隐藏按钮将窗口贴到页面顶部，再点击展开。
长文或宽表格可以拖动、缩放后阅读；宽屏文章页可能自动进入阅读侧栏。
收起或关闭窗口是展示操作，不代表撤销确认或回滚已执行的动作。

执行中可补充文字，例如“保留技术细节，按章节列出”，界面会区分收到和实际采用。
需要停下来时使用暂停；持久暂停后用继续入口接续原任务。图片在任务暂停或结束后添加。
断连不保证任务继续完成，也不证明外部请求已经停止。

完整交互以[组件契约](https://github.com/BigLeopardCat/saudade-blog-agent/blob/main/frontend/CHAT-UI.md)为准。
