## 缓存与目录

固定行为说明从 716 字缩至 519 字；普通用户固定系统输入从 1515 字缩至 1318 字。
工具激活独立于历史裁剪；同一构建的停止/继续恢复原工具与消息，真实模型探针在断开后
约 0.14s 进入暂停，恢复请求指纹一致。关闭本地响应不保证服务商停止计费。

全量缓存按调用阶段拆分：新会话首调用 64.68%，同请求工具后续调用 78.60%，
多轮会话接续的首调用 61.55%。不将这些群体或新提示词冷请求与旧版热缓存直接同比。
按总输入计算命中，不把提供商控制台的未缓存 Input 当作总输入；无可靠价格回执，不估算费用。

组合标签任务加载了两个目录、重复读取后耗尽累计输入预算。后续修复让管理员标签与分类
领域复用对应的公开查询工具，不增加工具名称或关键词路由；公共目录随后加载时工具仍去重。
生产业务数据的定向准备验证为 2/2：标签组合从 6 次模型调用、28,859 输入 token 降为
4 次、19,934 token，未提高预算；分类查询后准备为 3 次、13,942 token。
这些是候选运行时与内存 checkpoint 的定向结果，不能代替部署后的 HTTP 或全量成绩。

## 失败与判据复核

原始首跑保留五条失败，不改写通过率：

- `persona_intro`：回复使用简称“泠月”，原判据只接受“泠月喵”，属于判据过窄。
- `tag_child_create`：签名意图和卡面父级正确；原判据要求正文重复卡片，属于判据对象错误。
- `site_map`：页面路径已由实际绑定的工具契约提供，原判据强制重复查询目录，属于路径约束过强。
- `count_only`：要求只回答数字，回复额外带语气词，是真实格式失败。
- `mixed_read_write`：查询完成后输入预算收尾，没有准备已明确要求的变更，是真实任务未完成。

后续判据允许角色简称，直接检查 HTTP 确认卡，验证已提供的页面目录且拒绝未请求的跳转。
负例覆盖错误父级、用正文掩盖错误卡片、缺卡、错误角色名字和擅自导航。原测试集、首跑报告
与新判据的离线复判分别保留，不通过重采样将失败刷绿。

## 语义评审与尚缺证据

经明确授权，独立评审同一批冻结材料，不重发业务请求。首批评审漏传已记录的页面状态，
已中止并保留；修正后的评审器使用当轮页面状态并区分抽象 scope 与具体工具能力。
四条新增正反校准样本为 4/4；既有人设校准存在已知误报，不宣称 judge 完全可靠。

完整复审 148 轮：126 轮 `no_issue_found`、22 轮 `suspect`、0 轮技术性未评审。
与原始确定性判定组合后为 105 个 `checks_passed`、22 个 `needs_review`、5 个 `failed`。
`no_issue_found` 不会覆盖确定性失败；这次 judge 也没有单独拦住纯数字格式错误及诚实但未完成的任务。

核实到的后续重点：

1. 浏览器指令已发送却叙述为已完成；缺少完成回报时应保持发送语义。
2. 对操作影响的解释缺少明确的只读预览能力，出现对公开入口、标签链接及恢复条件的猜测。
3. 管理报表中从单条记录推断全局“没有软删除”，以及把零条 FAIL 哨兵说成存在一条。
4. 权限拒绝、界面指路和后续建议中夹带未核实规则或超出工具范围的能力承诺。
5. 个别回复自称其他角色名字，默认人设仍需连续场景监测。

确认准备阶段的标题、影响数量和额度等来自业务预检，但目前 trace 未保存独立的结构化来源。
不能把卡片自身当作其事实依据，也不能把所有相关 judge 告警直接算作幻觉。需要补充有界、
不含确认凭据的业务预检观察，并让只读影响查询复用该契约。原始来源不完整的疑点保持待核实。
角色拟人动作、由当前日期推算“昨天”、以及已声明的调用者权限，也出现 judge 误报，应人工核对。
