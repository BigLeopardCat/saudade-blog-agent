# 首版核心执行链路验证

最终候选 `e0a0042b22de09e027ab29bd1623e4b1d89bd6bc` 的 19 个核心场景和 6 个独立重复样本已完成。
本轮使用既有 `native_contracts` / `golden` 框架，语义审查保持暂停，RAG 保持冻结。
机器数据见 [冻结结果](report/baseline_e2e_closeout_20261113.json)。

## 范围与修复

运行真实 OpenCode Go / deepseek-v4.1-flash，业务 API 和浏览器回执使用合成夹具，
执行账为临时 SQLite，checkpoint 为内存。真实 PostgreSQL 和既有 Playwright UI 测试由 CI 验证。
没有批准生产业务写入，也没有运行线上真实浏览器测试；合成回执覆盖故障处理的通过，
不代表浏览器实际已打开这些页面。

修复了错误回执后的任务状态不一致：foreign command_id 被拒绝后，原 checkpoint 仍挂起，
任务输入记录却已 completed，后续正确回执无法恢复。现在只根据同一未完成任务 checkpoint
保留 paused / awaiting-confirmation 状态；正确回执可恢复，旧回执不会重复执行。
直接运行时反例在修复前失败，新增 PostgreSQL 重建用例在独立 CI 中验证。

通知查询结果明确本次只读、不修改已读状态、不准备确认卡。首次真实失败确实没有调用准备工具，
却声称卡片存在；最终场景继续严格要求真实签名卡片、固定目标、未确认零写入、批准后仅写入一次。
局部工具契约改善不构成对模型未来自然语言误报的完全消除证明。

## 判据对齐与失败留存

| 首次材料 | 核查结论 | 最终处理 |
| --- | --- | --- |
| 通知总结后声称卡片已准备 | 真实执行遗漏 | 查询结果与工具契约明确只读效果，实际确认卡必须存在 |
| 部分写入后仅一次 Agent 查询 | 旧判据依赖内部两次列表 HTTP，误判 | 检查 Agent 本轮真实成功查询；没查、内部读取冒充、查询失败仍拒绝 |
| 101 / 102 两次不同详情读取 | 列表路径和一次调用上限误判 | 允许一次列表或两次不同详情；两个目标必须有直接正确证据，重复覆盖仍失败 |
| 准备确认多一次预查询 | 真实效率目标未达标 | 复用已有发布上限 4 次；3 次仍是优化目标，未达标单列观察；5 次仍失败 |

普通用户偶尔被称为「主人」沿用已接受观察口径，保留原话；身份、授权、校验码、精确 JSON、
实际业务状态与回执均继续严格检查。没有把已接受的风格观察再次扩写成禁词失败。

一次工具说明提示未能稳定消除额外预查询，已撤回；没有增加强制规划、意图分类、文字拦截或另一个
收尾模型。所有旧原始失败状态、批次哈希、首次成本和停止位置均保留；没有把旧批次改成通过。

场景覆盖确认执行、取消旧卡、批准令牌重放、部分写入故障后的独立核对、管理员复合写入、
准备失败后的恢复、显式暂停后恢复、导航回执及 checkpoint/runtime 重建。
completed、failed、timeout、错误路径分别验证；缺失、foreign 和重复回执均不得调用模型或重发动作。

19 个场景按完整场景计数，6 个重复样本单列，不合成 25 个独立用户任务。
Wilson 95% 只描述这批固定协议场景，不能证明生产任务成功率。
语义判定、真实浏览器线上执行和长期稳定性没有被这些样本替代。

最终 90 轮中 35 轮没有模型调用；模型跨度合计 500.42 秒，请求 trace 合计 510.2 秒，
合成业务工具单次最长约 24 ms。两次确认回复触发既有不完整工具调用修复，已计入成本；
没有把它们隐去或当作服务商超时。

所有诊断、失败、候选和重复验证消耗均计入总数；不只统计最后通过的一轮。
时延分开报告含零模型控制请求的全部请求、实际调用模型的请求和模型跨度；不把零模型重放
混成用户任务的提速成绩。模型跨度包括网络和服务商处理，不能据此拆出服务商排队时间。
本轮没有可控的同请求 A/B，不宣称缓存提升或模型调用整体下降，也不跨峰谷比较扣费。
