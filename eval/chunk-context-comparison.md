# 句段子片与预算化父段、邻近窗口对照

本实验固定编码模型、查询向量和融合策略，只改变文档细分边界与命中后的读取范围。
复用已有 LangChain 切分、CommonMark 结构、RRF、宿主读文协议和评测器，没有引入语义切分模型、
生成回答或 LLM Judge。实际结果和策略决定见下表；生产默认值保持兼容，离线候选不自动上线。

## 实验边界

沿用[全库基线](full-corpus-retrieval-comparison.md)的固定公开源：
DuRetrieval 全部 100,001 篇源文档、2,000 个原始 dev 问题，以及 CMRC2018 的 848 个源段落、
3,219 个原始 dev 问题。Du 实际可向量化 100,000 篇；原有一篇只有标题结构、没有正文的文档
仍保留在源库和数据哈希中，不暗中删除或重排 ID。CMRC 所有问题保留，不用博客调参。
语料 revision、原文件哈希、许可和答案坐标恢复规则继承基线，另随本报告封存。

Du 只有文档级 qrels，不能报告其答案位置覆盖。CMRC 使用原始来源 scope，衡量该段内的答案跨度
是否出现在最终可见范围，不能当成全库召回、官方 CMRC 阅读理解分数或 Agent 任务成功率。
两者都是公开 dev，可能存在预训练重叠，没有独立业务盲测的含义。

固定 BGE-small-zh-v1.5 Q8_0、512 维、CLS/L2、匹配 tokenizer 与 llama.cpp b11829 的 normalizer；
模型权重 SHA `5a88d266870fbd27c6f329df60de80e2d4cf3bbd5e6f080bd5c1b2e5abb12039`。
查询指令、文档前缀和完整 512-token 输入预算均不变。全部查询向量直接复用已冻结基线，
不把编码漂移当作 chunk 策略收益。该实验没有比较 BGE 官方浮点权重或其他 embedding 模型。

| 控制项 | 本轮设置 |
| --- | --- |
| 旧子片 | 既有结构块内 tokenizer offset window |
| 新子片 | 同一结构块内 LangChain RecursiveCharacterTextSplitter，优先段落、换行和句末 |
| 完整输入上限 | 标题、节标题、正文和 special tokens 合计不超过 512；逐片校验 |
| 重叠 | 两种策略都使用 `min(180, 剩余正文预算 // 4)`；边界导致实际重叠不同 |
| 兜底 | 重复文字坐标恢复不可靠、续词重编码超限或覆盖缺口时复用安全 token window |
| 文档融合 | 词法、向量等权 RRF，k=60，每路 24，读取前 8 篇；不调权、不扩大候选池 |
| window | 保留原检索窗口 |
| parent | 扩到同节包含锚点的 CommonMark 块，目标 1,024 BGE tokens |
| neighbors | 同块加前后相邻块，同样的目标与锚点保护 |
| 读文预算 | 每题最终工具响应合计最多 4,096 framework-estimated tokens |

这里的“父段”是同节源结构块，不是另一套向量索引；大块边缘可缩以满足预算，完整原锚点保留。
词法锚点本身大于 1,024 时，不截掉原证据，扩展有效预算以锚点为下限；它不是严格的 1,024-token
返回上限。相同章节的重叠读取合并，保留首个命中的优先级，并遵守单次 24,000 字符接口边界。
子片仍只负责检索，读取范围独立保存于 `read_window`，不覆盖原命中坐标。

新旧 Du 向量质量都用 scikit-learn 精确余弦计算并调用当前文档聚合；原基线已有 2,000 题完整
PostgreSQL 控制。本轮新索引另取固定等间距 32 题核对实际 SQL，其余 `production` 明确为 null。
这 32 题最大评分误差为 4.17232513e-07，低于 2×10⁻⁶；没有排名差异。
旧矩阵从保留的 SQL 向量在内存恢复，原始矩阵字节 SHA 与旧导出一致；不是重新编码。
词法原生 BM25S 的前 24 位置逐题与原冻结排名核对。CMRC 新策略走实际 RagIndex/SQL 的全部查询。
这能检查本轮编码、排名与定位，不代表新索引又做了 2,000 次 SQL 校验。

读文对照通过现有 `document_page → project → render_article_result` 和 `estimate_tokens`，
按固定排名顺序读取，只有裁剪后真正可见的源范围才计证据覆盖。响应封装、元数据和 JSON 长度
都消耗预算。它是确定性的协议回放，不发 HTTP，也没有 Agent 自主取舍、追读或回答生成。
framework 估计使用 chars/1.5，另报 BGE 正文 tokens、字符量和模拟读取次数；这些都不是提供商账单，
也不含系统提示词、历史、工具 schema 或推理输出。最终响应长度被保存，可不分发正文而复算估计成本。

每题硬预算均为 4,096，表中是实际接收范围的平均消耗；预算会让后面的命中文档没有可见正文。

增加到 3,949，是预算挤压后的总量，不能说扩展本身没有代价。检索 Recall 表也不能当作这些
裁剪后正文的证据覆盖率。

两套语料所有分组的 parent 与 neighbors 最终范围完全一致，不能证明相邻块扩展对长文没有价值。
源段落主要是单一结构块，缺少能区分两种策略的跨段证据；该能力只有合成边界测试，继续保持可选。

### 排序失败归因与 reranker 决定

| 固定每路 24 候选 | 并集 Recall | 理想 top-8 Recall 上限 | 池中有正例但 top-8 全漏 | 向量 top-8 命中而融合全漏 |
| --- | ---: | ---: | ---: | ---: |
| 原切窗 | 0.89116 | 0.87556 | 54 | 22 |
| 句段子片 | 0.89242 | 0.87687 | 55 | 23 |

理想上限使用标签作 oracle，只描述现有候选的空间，不能承诺 reranker 达到它，也不把未标注文档
直接判为无关。切分后仍有池内正例被融合排掉，下一优先级应是固定候选的成熟 cross-encoder
离线对照，记录排序收益、超长输入覆盖、额外延迟和吞吐，而非继续堆分块规则或扩大上下文。

**决定：本轮不在生产路径加入 reranker；保留原切窗与 window 默认。** 父段扩展已具备定位收益的
证据，作为可选策略保留；neighbors 没有独立收益证据。先让成熟重排器与纯向量、固定融合做同池对照，
再决定是否承担线上依赖与延迟。通用 dev 的轻微名次差异不足以替代未来真实文档的验收。


## 缓存、运行成本与失败记录

Du 旧片段 117,735、新片段 117,948；对应唯一编码输入 117,703 与 117,884。
新策略按完整输入精确复用 99,088 个向量，新增提交 18,796 个；CMRC 新片段 1,157，
复用 658、新增提交 499。合计新增持久化输入 19,295；新增查询编码为零。
评测复用先校验权重声明、tokenizer、special-token、前缀、归一化和模型参数，只允许不同的
评测 namespace；不提供未经验证的生产跨策略自动迁移。

首次 Du 缓存阶段遇到共享磁盘满，已提交 14,670 个新输入保留，失败的 10 输入批次没有提交；
只压缩校验本任务的可再生中间副本，在确认 SQL 向量保留后移除旧矩阵导出，恢复后补完剩余 4,126。
评测入口增加了编码前的临时空间门槛。这些额外计算和失败阶段耗时都保留，不能仅用恢复阶段计算总成本。
服务端日志 release 计数只作为观测，不能等同计费或精确输入去重账本。

第一次读文回放在完成 5/30 个分组后停止，以补记最终响应长度；随后只重复本地读文与计分，
未重复向量编码、检索或 SQL。初次临时数据库重启还处理了一次自身 socket 目录权限问题。
成功与中断阶段的 CPU、墙钟、峰值 RSS、代码哈希及模型进程观测随运行台账保留。
共享生产主机上的 nice 15 本地批处理耗时不作为在线延迟 SLA。

专用 embedding 进程、临时 PostgreSQL 均已停止，临时密钥已移除，昂贵的评测向量缓存保留。
生产服务未部署或切换，LLM Judge 继续暂停。

## 复现与独立复核

冻结结果不含语料正文、答案摘录或用户材料。使用标准库 XZ 无损压缩，
与原 gzip 的解压 JSON SHA 一致，归档从 37.7 MB 降至 8.7 MB；没有自定义编码格式：

- [排名、标签、位置与逐题成本](report/baseline_chunk_context_20261112.json.xz)
- [配置、源哈希、SQL 控制与运行台账](report/baseline_chunk_context_operations_20261112.json)

在仓库锁定环境直接复算文档指标、证据覆盖、固定分组和框架成本，不需要原始正文、模型或数据库：

```sh
SAUDADE_IGNORE_ENV_FILE=1 python -m eval.replay_chunk_context \
  eval/report/baseline_chunk_context_20261112.json.xz
```

BGE 正文 token 数需匹配 tokenizer 和公开原文才能重新分词；无源复算仅核对该记录的平均值，
不声称独立重算过所有编码输入。构建、检索和读文的独立复现先按全库报告准备原始数据与模型，
在可丢弃 `eval-` collection 使用新 profile：

```json
{"chunking_strategy": "sentence-paragraph-v1"}
```

该字段须加入完整原 profile，不能单独作为有效配置。新旧空间分开准备。
`full_corpus_cache --reuse-collection ... --reuse-inventory ... --reuse-profile ...` 支持检查后复用旧输入；
没有旧缓存时正常完整编码。随后使用 `full_corpus_dense --postgres-verify-queries 32 --locations-top-k 24`
和 `full_corpus_locations` 冻结新旧向量、词法定位，CMRC 沿用 `model_retrieval_run --query-cache`。
融合与读文入口如下；所有路径是该次独立实验产物，不读取默认生产配置或库：

```sh
SAUDADE_IGNORE_ENV_FILE=1 python -m eval.chunk_context_comparison \
  --du /tmp/du-full --cmrc /tmp/cmrc-spans \
  --baseline eval/report/baseline_du_full_20261112.json.gz \
  --old-vector /tmp/comparison/old-vector-locations.jsonl \
  --new-vector /tmp/new-du/dense.jsonl --lexical /tmp/comparison/lexical-locations.jsonl \
  --old-cmrc eval/report/baseline_cmrc_spans_20261112.json.gz \
  --new-cmrc /tmp/comparison/new-cmrc.json --output /tmp/comparison/context.json.gz
```

本实验不能回答长篇跨章论证、最终答案忠实度、无答案拒答、权限过滤正确率或生产负载下延迟。
这些需要将来真实文档迁入后另建来源与证据集验收，不用当前博客或公开 dev 代替。
