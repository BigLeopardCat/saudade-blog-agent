## 预算超标归因

单领域查询 55 个请求中，输入 p95 为 20,190.4，只有这项达到样本要求的预算未通过。
成本口径与上轮一致，没有发现分位数实现或标签临时变化造成的误判。

| 高输入场景 | 输入 / 模型调用 | 执行证据 |
| --- | ---: | --- |
| `admin_services` | 26,938 / 4 | 加载两个领域；分别读取健康、服务器和审核状态，之后补读审核 AI 视图；同名工具的参数不同 |
| `search_missing` | 25,711 / 3 | 精确检索后改用更宽的关键词和语义查询，参数不同；不当成完全相同的重复查询 |
| `account_mute_protected_target` | 21,701 / 3 | 加载资格和账号两组 schema，实际只调用资格查询；存在可减少的 schema 开销 |

另核查了 `tags_children`：先找一级标签，再按父标签 ID 查二级标签，属于真实依赖，
不能只按工具名称相同就去重。部分投影共享宿主端点也不等于返回给模型的视图相同。
这轮保留有限的冗余优化机会，没有为约 190 tokens 的分位数差额增加运行时拦截、
强行限制检索轮数、堆提示词或调整验收分类。
