# 自包含夹具：在自己的机器上跑一次端到端

`eval/golden/basic.jsonl` 那 158 条用例的每一条期望，都锚在**维护者那个站点**的文章上：
`require_doc_terms` 的术语表从那些正文里派生，检索用例期望命中的就是那几篇。你 clone
下来对着自己的博客跑，判据一定对不上——而**红的样子与「模型退化」一模一样**，读的人会去
改一个根本没坏的模型。

20261006 起这件事不再靠"你猜"：`run_golden.py` 启动时有一条**语料出处闸**
（`eval/corpus_provenance.py`）先判"这一轮评的是不是原来那块地"，对不上就把全部用例判成
**未评估**并退出 3，还会打印一句「这不是模型退化」。

而这一套是给你的另一半：**语料、桩服务、用例、出处声明都在本目录**，不依赖维护者的站点，
也不需要站点后端——一条命令跑完一整套真实的 agent 链路。

## 跑起来

```bash
# 0) 只需要你自己的 LLM key（本仓的 .env / 环境变量那一套，见仓根 README）
uv sync

# 1) 终端 A：起桩服务（标准库 http.server，没有额外依赖）
.venv/bin/python eval/fixtures/serve.py --port 8099

# 2) 终端 B：把工具的出口地址指到桩上，然后跑夹具用例
BLOG_API_BASE=http://127.0.0.1:8099/api/public \
    .venv/bin/python eval/run_golden.py --golden eval/fixtures/golden_smoke.jsonl

# 或者全量跑法（逐条独立子进程，口径一样）
BLOG_API_BASE=http://127.0.0.1:8099/api/public \
    .venv/bin/python eval/golden_full_run.py --golden eval/fixtures/golden_smoke.jsonl
```

`BLOG_API_BASE` 是 20261006 新增的工具出口地址（默认值是维护者那个站点）——不设它，
agent 读的还是别人的博客，读数是真的、只是不属于你。

四条用例约 1–2 分钟（闲聊那条几秒，检索那两条各十几秒，取决于你的模型）。

## 目录里有什么

| 文件 | 是什么 |
|---|---|
| `corpus/*.md` | 三篇**编出来的**文章（滴灌改装 / 收音机中波 / 夜跑配速）。第一篇的首行 `# 标题` 就是标题，其余是正文。id 按文件名顺序 = 1、2、3 |
| `serve.py` | 桩服务：把上面的语料按真实公开接口的形态供出来（字段名与真实接口逐个对齐） |
| `golden_smoke.jsonl` | 四条用例：检索答细节 / 站内搜索 / 已下线页面的导航 / 闲聊（零工具） |
| `provenance.json` | 出处声明：这套用例锚在本目录 `corpus/` 的那三篇上。**闸按文件名找它**——用例与声明必须放在同一个目录 |

## 桩的边界（先说清楚，免得把桩的缺口读成夹具坏了）

实现了这四个：

| 端点 | 用途 |
|---|---|
| `GET <base>/notes?page=&page_size=` | 文章列表（分页；**不带正文**，与真实接口一致） |
| `GET <base>/notes/<id>` | 文章详情（带 `noteContent`）；库里没有这个 id ⇒ HTTP 404 |
| `GET <base>/notes/<id>/stats` | 阅读/点赞/收藏三个读数（**桩编的固定值**，别拿它们当期望） |
| `POST <base>/notes/search` | 站内搜索（标题 + 正文子串命中） |

**其余接口一律回 `{"code": 501, ...}`**：工具侧读成 `unavailable`，agent 会说"服务暂时
不可用"。那是桩的诚实边界，不是夹具坏了——分类/标签/留言板/说说/公告的端点这里没有。
（也正因为如此，这四条用例刻意不碰那些工具。）

桩编的三个读数与语料无关，属于"这个假站点的假事实"；**没有一条用例断言它们**。

## 换成你自己的语料

想拿自己的文章当夹具，就照这个目录的形状改三处（顺序别反）：

1. 把 `corpus/*.md` 换成你的文章（每篇首行 `# 标题`）；
2. 改 `provenance.json` 的 `anchors`：填**你**的文章标题（`min_present` 是"至少命中几篇
   才算同一块地"，锚点少时按比例调）；
3. 改用例里的期望词：`text_contains` 的词必须能在你的语料里找到、且**不在提问里**
   （否则照抄问题就能过），`require_doc_terms` 的 `doc` 要写你的文章 id（`note:1` …）。

第 2、3 步错了不会静默：`tests/test_golden_fixture_corpus.py` 在离线秒级套件里就能告诉你
（它拿桩的语料把这两件事逐条对一遍），跑到线上时还有出处闸兜着。

## 谁守着这个夹具

`tests/test_golden_fixture_corpus.py`（离线、无网络、无 LLM，跟 `tests/run_all.py` 一起跑）
守四件事：

1. 桩真的供出了 `corpus/` 的那几篇（**起真桩、走真读路径**：`tools/base._get` →
   `rag/_fetch_corpus`，不是本地的 json 拼装）——字段名漂了这里就红；
2. 拿夹具语料跑出处闸：夹具自己的声明判 `ok`，而**维护者那份声明判 `foreign`**
   （证明这条闸真的分得开两块地，不是恒绿）；
3. 每条带 `corpus` 标签的用例：`text_contains` 的词在语料里出现、且不在提问里；
   `require_doc_terms` 申报的文档在语料里、且真能派生出 `min_terms` 个术语；
4. 用例文件的 shape（gold 键属于哪一类由 `tests/test_golden_keys.py` 一并扫）。

## 已知边界

- 跑起来时会先看到几行 `[corpus] WARN 期望命中文档 note:12 不在当前语料——期望过期…`：
  那是**另一条**检查（`eval/corpus_check.py`，拿 L1 检索集 `recall_eval.QUERIES` 的期望文档
  对当前语料做在位性检查），它期望的是**维护者那个站**的那几篇——夹具语料里当然没有。
  它说的是实话（语料确实换了），但**与你无关，不用修**。出处闸那三行才是给这一轮定性的。
- 它需要**你自己的 LLM key**：夹具解决的是"语料与判据的前提"，不是"不用模型"；
- 夹具语料是编的，与任何真实站点无关；桩的读数是编的；
- 这四条是**冒烟**，不是你那套评测的全部——它证明链路通、判据判得动，不证明你的 agent
  在你这块语料上答得好。要那个，得照上面「换成你自己的语料」自己写一批。
