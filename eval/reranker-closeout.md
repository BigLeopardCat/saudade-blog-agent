# 固定候选重排对照与 RAG 冻结决定

**决定：保留成熟重排器作为离线基线，不加入当前生产同步链路；本轮后冻结 RAG。**
固定 2,000 查询、81,903 候选对中，INT8 BGE-reranker-base 的 Recall@8 为 0.82772、
nDCG@8 为 0.84684，优于纯向量与固定 RRF；但共享 CPU 的额外预分词查询 p95 为
11.90 秒，超过运行前封存的 1 秒项目预算。三项质量条件通过、延迟条件未通过，且没有独立业务盲测。
保持原有 token-window-v2、等权融合和 window 默认，不为公开 dev 成绩增加线上依赖。

实验于 2026-11-12 开始、11-13 完成。以下分别说明排序质量、评分输入、读文成本和执行时间，
不把检索命中率表述成 Agent 任务成功率。

## 固定范围

本轮只评估一个成熟模型 BGE-reranker-base，复用现有数据、原生 RRF、指标和取文协议；
不增加生产重排服务、工具、配置开关或模型依赖，不运行回答生成与 LLM Judge。
[运行前封存的计划](report/baseline_reranker_plan_20261112.json)保留候选、输入、资源预算和决策条件。
后续只补充可观测性与复算，没有按成绩更换模型、切分、权重或候选池。

沿用[全库基线](full-corpus-retrieval-comparison.md)的固定 DuRetrieval dev：
100,001 篇源文档、2,000 个原始查询；实际可向量化 100,000 篇，源 ID 和原始标签均保留。
原来的单篇无正文来源差异不被隐藏。本轮没有重新编码文档或查询，也没有博客数据调参。

词法前 24＋原切窗向量前 24，等权 RRF k=60，逐题并集固定，共 81,903 个查询—候选对，
每题最多 48 篇。比较纯向量、固定 RRF、同并集 cross-encoder 重排，均取前 8。
纯向量在同并集内按原向量次序排列，前 8 与原基线逐题核对一致；它的后续截断指标只描述同一并集。
没有按相关性标签增加、删除或优选候选。

这些是公开 dev，模型训练材料可能重叠；它们不代表独立业务盲测、官方榜单成绩、
回答正确率或 Agent 任务成功率。未标注文档不直接判为不相关，原始 qrels 不因个案疑点而改变。

## 成熟实现与输入

模型来自 [BAAI/bge-reranker-base](https://huggingface.co/BAAI/bge-reranker-base/tree/2cfc18c9415c912f9d8155881c133215df768a70)，
MIT 许可，作者提供 cross-encoder 与 ONNX 用法。本轮主成绩使用
[社区固定 INT8 导出](https://huggingface.co/onnx-community/bge-reranker-base-ONNX/tree/f131ae72114cb18333648a2ee6b0942849e8ab95)，
通过 ONNX Runtime 1.23.2 的 CPUExecutionProvider 执行；不是自研打分器，也不称作官方浮点成绩。
模型二进制、tokenizer、原始数据、输入与代码 SHA 随台账封存。权重和可解码原文的 token IDs 不进入仓库。

每篇候选只取既有生产 RRF 的第一个命中定位，加原有的标题前缀；来源范围在加载时验证。
完整查询作为第一序列，不加 embedding 查询指令；标题与来源窗口作为第二序列。
复用 Hugging Face Tokenizers 的 `only_second` 截断，完整输入最多 512 tokens，保留实际可见源坐标。
使用单个原始 logit 排序，同分保留固定 RRF 次序，不设相关性概率阈值、不与 RRF 分数再混权。

重排只改变文档顺序。重排器输入的裁剪范围不会覆盖最终读文定位；正文继续使用原始命中位置，
再经过现有宿主页协议、结果裁剪和每题 4,096 framework-estimated-token 总预算。
该预算按框架 chars/1.5 估计，另记 BGE 正文 tokens 与字符数，不是聊天提供商账单。

| 控制 | 观测与范围 |
| --- | --- |
| 量化版与作者版 tokenizer | 2,000 个查询、128 个固定来源对及 16 个控制输入的 token IDs 一致；不是穷尽证明 |
| 同输入作者 FP32 / INT8 | 16 个固定来源/合成对，排序 Spearman=1.0，logit 平均绝对差 0.319、最大 0.866 |
| 中文合成正负例 | 两种表示的分数方向均正确；不作为真实质量成绩 |
| INT8 单个 / 批量输入 | 最后四对最大 logit 差约 0.506；动态量化对批次组成敏感，因此全量固定批次顺序和大小 |

同输入小控制能发现明显的词表、输出方向或表示错误，不能证明全部浮点模型质量，也不能消除
量化差异。全量使用两线程、顺序执行、关闭 spinning、batch=4、nice 15，单推理进程。
作者 FP32 控制单独执行、采用 basic 优化与关闭内存 arena，其计时不作主推理性能基线。
这些设置用于限制共享主机资源，不是声称找到了最优部署后端。

## 排名与固定分组结果

| 同池方法 | Recall@8 | nDCG@8 | Success@1 | Success@8 |
| --- | ---: | ---: | ---: | ---: |
| 纯向量 | 0.75133 | 0.75821 | 0.80650 | 0.94250 |
| 等权 RRF | 0.71687 | 0.71539 | 0.76900 | 0.94250 |
| BGE INT8 重排 | **0.82772** | **0.84684** | **0.90050** | **0.96600** |

Recall 为逐题相关文档覆盖的宏平均，Success 只表示至少一个标注正例进入指定前列。
三臂的候选并集相同：宏平均并集 Recall=0.89116，标签 oracle 的前八 Recall 上限=0.87556。
R@100 在本轮只穷尽最多 48 个同池候选，不是原全库向量 top-100 的指标。
61 题池内完全没有正例，任何同池重排都无法恢复；555 题至少有一篇标注正例不在候选中。

| --- | --- | --- | ---: |
| 纯向量 | +0.07639 [0.06793, 0.08460] | +0.08863 [0.08074, 0.09710] | 50 / 3 / 1,947 |
| RRF | +0.11085 [0.10185, 0.11982] | +0.13145 [0.12234, 0.14083] | 48 / 1 / 1,951 |

## 输入截断与可见证据

Du 81,903 对中，2,314 对发生文档侧 token 截断（约 2.83%）；查询完整保留。
Du 只有文档级相关性标签，不能由截断比例推导答案遗漏率，也不能把未截断当作上下文充分。

另用 CMRC2018 的 848 个原始段落、3,219 个问题做已知来源输入审计。
每题只有一个候选，重排不能改变排名，因此没有为它执行无意义的 cross-encoder 推理。
647 对触发输入截断，其中 60 题的标注答案跨度没有完整进入重排器输入，覆盖率为 98.14%。
原取文定位的跨度覆盖仍为 100%，定位没有被输入审计修改。
这说明评分输入和最终阅读证据必须分开，不能把该输入缺口判成 Agent 执行失败。
CMRC 本来就是已知来源范围，也不把它的文档命中率当作全库检索表现。

| 同一 window / 每题 4,096 框架 token 总预算 | 平均最终框架 token | 平均正文 BGE tokens | 平均正文字符 | 平均模拟分页读取 |
| --- | ---: | ---: | ---: | ---: |
| 纯向量 | 3,943.92 | 1,952.91 | 2,113.26 | 6.809 |
| RRF | 3,946.14 | 1,998.23 | 2,154.28 | 6.743 |
| 重排 | 3,948.20 | 1,938.05 | 2,093.75 | 6.857 |

重排没有增加向量数或重新编码；原 Du 索引仍为 117,735 子片、117,703 唯一编码输入。
上下文接近既定总预算，不能据正文 BGE tokens 略少就声称聊天账单降低。
Du 的原标签只有文档 ID：预算化读取后的文档排名指标与上表相同，但这不能验收可见答案或多段证据覆盖。
有跨度标签的 CMRC 才能报告上述输入覆盖缺口。模拟分页次数不等于线上 Agent 工具调用次数。

## 成本与耗时

主运行环境为共享 Intel Xeon Platinum 8255C 2.50GHz，4 逻辑 CPU、约 3.64 GiB RAM，
支持 AVX2 / AVX512-VNNI；Python 3.12.3、NumPy 2.5.4、Tokenizers 0.22.2。
采用前述两线程限制，机器没有独占隔离，因此结果是本机观测，不是模型部署性能上限。

| 每题预分词重排（2,000 题） | 平均 | p50 | p95 | p99 | 最大 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 墙钟秒 | 8.539 | 8.363 | 11.901 | 13.733 | 15.774 |
| 进程 CPU 秒 | 16.637 | 16.276 | 23.258 | 26.911 | 30.804 |

质量推理共 21,222 次 forward，未填充输入 17,142,237 tokens，填充后 25,486,801，
约增加 48.68% 计算位置；总逐题 CPU 33,274.08 秒，墙钟 17,077.08 秒。
另有 INT8 预热 8 对、表示控制 20 对和 FP32 控制 16 对；含控制共 81,947 对、21,257 次 forward。
离线向量编码、云模型调用、LLM Judge 均为零。

| INT8 16 对＋4 对批量控制 | 9.97 | 14.36 | 808,368 |
| CMRC 输入审计 | 14.56 | 14.48 | 809,348 |
| CMRC 导出元数据投影修复与复核 | 8.14 | 8.01 | 296,884 |
| 三臂指标与预算化读取分析 | 119.41 | 119.33 | 941,472 |
| 首次无模型复算 | 12.16 | 12.15 | 543,024 |
| 由公开来源重建全部输入并校验 | 134.81 | 134.63 | 1,281,864 |

主完整阶段模型初始化 0.809 秒、4 对预热 1.153 秒。主权重 279,252,659 字节，
FP32 控制权重 1,112,459,588 字节，两者不同优化设置，不能据此宣布相同质量下的加速比或内存缩减比。
准备时遇到公开 Hub TLS 错误与 wheel 超时，成功下载使用 HTTPS 镜像并核对固定摘要；
成功下载耗时、字节和摘要单列在台账，失败网络等待未完整计时，不能把其成本记为零。
CMRC 首次导出遗漏分组元数据，导致复算失败；只恢复原分组投影，保留原件 SHA，
验证来源、原数值指标、定位与输入不变，没有再次执行模型。

每题平均有 40.95 个候选对，cross-encoder 对每一对联合编码查询与来源窗口；新增的前向计算
和填充量单独计数，原查询及文档向量直接复用，业务工具调用没有增加。

模型加载、预热、离线输入准备、源码与标签读取、报告复算均单列；查询延迟统计测的是预分词输入
下的本地重排，不含检索、tokenization、HTTP、排队、生成回答或服务商延迟。
加载值指新进程的模型初始化；权重摘要校验会预热文件缓存。
两线程在该共享主机上的结果不能推导 GPU 生产 SLA，也不与聊天模型的输入 token 单价相乘。
没有调用云端模型并不等于本地计算没有成本；报告用 CPU、墙钟、输入量和峰值 RSS 表达。

8 题小批量的结果随后直接复用，完整阶段只补剩余 1,992 题；额外预热与表示控制单独入账。
持久化结果绑定完整输入 SHA、模型 SHA、线程与批次配置，逐题提交，重复恢复不重复算已完成的题。
生产版本保持原有部署，本轮所有实验入口显式忽略部署 `.env`，不使用生产数据库。

先在独立环境按 [固定语料说明](offline-rag.md)准备同 SHA 的 Du 全库与 CMRC，
按 [模型固定 revision](#成熟实现与输入)下载主权重和 tokenizer，逐项核对计划/台账 SHA。
项目锁文件保持不变；模型推理额外依赖只在独立评测环境安装 `onnxruntime==1.23.2`。
以下 `model/tokenizer.json` 是社区导出 tokenizer，不能替换成 BGE embedding tokenizer。

无需模型、原始正文、数据库或网络的指标与判定复算：

```sh
SAUDADE_IGNORE_ENV_FILE=1 python -m eval.replay_reranker \
  eval/report/baseline_reranker_20261112.json.xz
```
